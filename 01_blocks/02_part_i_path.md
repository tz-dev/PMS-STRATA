# Part I — PATH

**Temporal Composition and Trajectory Formation**

<a id="chapter-9-temporal-order-and-transition"></a>

## 9. Temporal Order and Transition

Chapter 9 begins the operational work of PATH. Foundations established the object, coordinate, operation, continuity, admissibility, record, and non-equivalence controls that every temporal claim must preserve. PATH now applies those controls to temporally extended praxis without treating temporal extension as self-interpreting history.

The governing question is:

> When does a temporal difference constitute a reconstructible transition rather than two disconnected descriptions?

The chapter will answer that question progressively. This first work package establishes the purpose of PATH, bounds the role of `Θ`, defines temporal-position declarations, and specifies order dependence. It does not yet define duration, delay, persistence, bounded irreversibility, temporal recontextualization, or the full transition test. Those duties remain in Sections 9.5–9.12.

The local result of Sections 9.1–9.4 is not a path. It is a controlled set of temporal declarations and order-sensitive claims that later sections may use when testing transition candidates.

<a id="9-1-purpose-of-path"></a>

### 9.1 Purpose of PATH

PATH specifies the reconstruction of temporally ordered praxis structures. Its scope includes:

- temporal position and relation;
- transitions between configurations;
- sequence and path formation;
- trajectory formation and sedimented historical load;
- path-dependence testing;
- branches, delays, unavailable alternatives, and non-events;
- the bounded operation `COMPOSE` where several source structures are formed into a declared temporal composite.

PATH therefore asks how praxis becomes historically ordered, carried, constrained, redirected, interrupted, or left unresolved. It does not assume that every dated difference is a transition, that every sequence is a path, that every path is a trajectory, or that every trajectory is path-dependent.

```text
chronology
≠ sequence automatically

sequence
≠ path automatically

path
≠ trajectory automatically

trajectory
≠ path dependence automatically
```

These distinctions are not obstacles to temporal reconstruction. They identify the additional burden that each stronger claim must carry.

#### PATH is a Part, not an operation

PATH is one of the four Parts of STRATA. It is not a fourth operation and is not identical to `COMPOSE`.

```text
PATH
≠ COMPOSE
```

PATH contains temporal concepts, tests, records, boundary conditions, and later one operation-specific procedure. `COMPOSE` remains one of exactly three STRATA operations and receives its complete PATH procedure in Chapter 15. A temporal relation may be reconstructed without yet identifying a transformation operation. Conversely, a `COMPOSE` occurrence may form a composite whose relevance is not primarily temporal.

```text
temporal reconstruction
≠ operation occurrence automatically
```

Chapter 9 therefore reconstructs temporal position, order, and transition candidates. It does not infer an operation merely because a record contains multiple temporal objects.

#### PATH is not RETYPE

PATH reconstructs temporal order and historical formation. It does not assign a higher-level contextual target function. A path or trajectory may later become the source object of `PROJECT_AS`, but the projection requires a separate target context, target function, origin-type preservation, continuity test, and admissibility result.

```text
temporally extended object
≠ higher-level target function
```

A recurrent temporal structure may be analytically important without functioning as a frame, macro-event, attractor, memory structure, or other RETYPE target. Those are new claims.

#### C9-SCOPE-01 — temporal reconstruction used as an undeclared target function

Suppose the review materials support a temporal reconstruction of:

```text
C0
→ adoption event E1
→ C1
→ unresolved reconsideration interval
```

The analyst then states that the resulting temporal object is an “institutional memory function” for every later context. The temporal reconstruction and the function claim are not the same claim.

The responsible segmentation is:

```text
temporal-order claim
→ remains testable within PATH

institutional-memory function
→ requires a separate PROJECT_AS record in RETYPE
```

If the function is merely suggestive and not source-dependent, it may remain an analogy. If it is asserted as an already established target function, the claim requires reduction or failure. PATH does not acquire additional authority by being historically richer.

```text
more temporal structure
≠ more functional authority
```

The local purpose result is:

```text
PATH permits temporal reconstruction
without pre-authorizing transition,
path, trajectory, path dependence,
causality, or target function.
```

<a id="9-2-theta-as-temporal-structuring"></a>

### 9.2 Θ as Temporal Structuring

`Θ — Temporality` is the PMS Base operator that provides temporal structuring. Within STRATA it supports the declaration and testing of:

- sequence and relative order;
- duration and temporal interval;
- anticipation and delay;
- repetition and recurrence;
- persistence;
- accumulation;
- bounded irreversibility;
- historical position and developmental extension.

This role is substantial but bounded.

```text
Θ-supported temporal declaration
≠ sufficient historical claim
```

`Θ` enables temporal articulation. It does not by itself establish the identity of an event, a non-event, a transition, a path, a trajectory, sedimentation, path dependence, causal necessity, or authority.

#### Operator type, occurrence, and temporal object

The abstract operator type `Θ` remains a PMS Base grammar element. A concrete configuration or event may contain a `Θ` occurrence. A sequence, transition, path, or trajectory is a temporal object reconstructed from source-supported relations. These are related but non-identical.

```text
Θ operator type
≠ Θ occurrence
≠ temporal coordinate
≠ transition object
≠ path
≠ STRATA operation
```

The distinction matters because otherwise the presence of temporal language could silently perform several invalid upgrades at once:

```text
"over time"
→ transition
→ path
→ trajectory
→ path dependence
```

No such automatic chain is permitted. Each arrow would require a new testable claim.

#### Θ does not supply event or non-event identity

`Θ` may locate a realized occurrence in time, but temporal location does not prove that the occurrence satisfies the event burden. It may define an expectation window, but elapsed time does not by itself establish a `Λ` non-event. The event or non-event claim must retain its own reference, frame, realization or non-realization conditions, and source basis.

```text
temporal window
≠ event identity
≠ non-event identity
```

This becomes especially important for delay. A delay may be a temporally relevant relation between configurations. It becomes a framed non-event only where a warranted expected occurrence and bounded realization condition are also present. Section 9.6 will test that distinction directly.

#### Θ does not establish causal or deterministic order

A supported order may matter for praxis without proving causality. `Θ` can make before/after, interval, repetition, and persistence visible. It cannot determine that the earlier structure caused the later one, that no other continuation was possible, or that the observed order is universally law-like.

```text
supported temporal order
≠ causal proof
≠ necessity proof
≠ predictive law
```

The same sequence may have different praxis consequences under different frames. Conversely, two differently timed sequences may produce similar endpoints while retaining different cost, expectation, binding, or alternative structures. Those differences must be reconstructed, not inferred from `Θ` alone.

#### C9-THETA-01 — rich temporality inflated into trajectory and dependence

Suppose a record declares:

- a thirty-day interval;
- repeated reminders;
- an unresolved commitment;
- increasing reopening cost;
- continued procedural asymmetry.

This is a rich temporal declaration. It may support later claims about duration, persistence, accumulation, or bounded irreversibility. It does not automatically establish a trajectory or path dependence.

```text
rich Θ declaration
→ temporal structure preserved

trajectory claim
→ requires sedimented historical-load test

path-dependence claim
→ requires separate determination test
```

The immediate stronger claim therefore requires:

```text
claim_reduction_required
```

A narrower result remains available:

```text
the source bundle supports a bounded temporal structure
with repeated reminders, unresolved commitment,
and increasing reopening cost.
```

This preservation is important. Rejecting the trajectory upgrade does not erase the temporal evidence.

<a id="9-3-temporal-position"></a>

### 9.3 Temporal Position

A **temporal position** is the claim-relative placement of a declared object, occurrence, configuration, interval, or relation within a bounded temporal frame.

It may be represented as:

- an analytical instant;
- an analytical period;
- a relative before/after relation;
- a partially ordered relation;
- an open, closed, or bounded interval;
- an uncertain or disputed date;
- a retrospective periodization whose construction is explicitly declared.

Temporal position is not exhausted by calendar notation.

```text
calendar timestamp
≠ temporal position automatically
```

A timestamp can support a temporal-position claim, but the claim must still identify:

- what object is being positioned;
- which temporal relation matters;
- which frame and scope apply;
- what precision the sources support;
- whether the date is contemporaneous, reconstructed, estimated, disputed, or retrospective;
- which later claim depends on the placement.

#### Analytical instant and analytical period

An event may be represented by a date even where its relevant structure extends across an interval. A configuration may be analytically located at a boundary even though its constitutive relations began earlier and persisted later. The analyst must state whether the position is punctual shorthand, interval-based, or relational.

```text
punctual representation
≠ punctual ontology
```

A meeting vote may occur at a recorded instant while the adoption event includes prior revision and subsequent procedural enactment. Conversely, an interval label such as “the reconsideration period” does not prove that every day within the interval shares one homogeneous configuration.

#### Relative order without exact dating

Exact dates are not always necessary. A bounded relative order may be sufficient where the tested claim depends on sequence rather than precise elapsed time.

For example:

```text
E1 adoption
precedes
R1 reminder

R1 reminder
precedes
end of realization window
```

The exact date of `R1` may remain disputed. If both sources place it after adoption and before the end of the window, that relative position may be supportable.

```text
uncertain exact date
≠ no temporal position
```

But uncertainty must be preserved. A relative-order claim may not be silently converted into a false exact date merely because a total timeline is easier to display.

#### Partial order

Temporal materials may support only a partial order. If two reminders both occur between adoption and the end of the window, but their internal order is unknown, the correct representation is:

```text
E1 < R1 < W_end
E1 < R2 < W_end
R1 ? R2
```

The unresolved internal relation affects only claims that depend on it. It does not invalidate every temporal finding.

```text
partial order
≠ failed chronology automatically
```

#### Retrospective periodization

Retrospective period labels can be useful. They may group events under an analytically declared interval such as “pre-adoption,” “reconsideration window,” or “post-window stabilization.” But the period is constructed for a claim. It is not automatically a natural historical unit or a higher ontological layer.

```text
retrospective periodization
≠ historical self-division
```

The periodization must disclose:

- its boundary rule;
- its selected reference object;
- its inclusion and exclusion decisions;
- the claim it supports;
- what remains uncertain or crosses the boundary.

#### C9-POS-01 — disputed date with supported relative order

Two sources disagree on whether a reminder occurred on Day 18 or Day 20. Both agree that:

- the rule had already been adopted;
- the reminder occurred before the thirty-day window ended;
- no reconsideration decision had yet been recorded.

The exact date remains disputed. The bounded temporal-position claim is:

```text
E1 < R1 < W_end
exact date of R1 uncertain
```

The local result may be:

```text
admissible_with_bounded_claim
```

The result does not authorize a fabricated timestamp. It preserves the relative position needed for later delay and transition tests while carrying the uncertainty forward.

#### Temporal-position declaration

A compact declaration should contain at least:

```yaml
temporal_position:
  object_ref:
  position_form:
  relation_or_interval:
  frame:
  temporal_scope:
  precision_status:
  source_basis:
  uncertainty:
  claim_dependency:
```

This is a conceptual declaration, not a new schema. Chapter 7 remains the owner of the Shared Transformation Record, and existing record fields remain the technical carriers.

<a id="9-4-order-dependence"></a>

### 9.4 Order Dependence

**Order dependence** is a bounded property of a declared temporal relation: materially changing the order of the load-bearing elements would change the warranted reconstruction of the tested praxis claim.

```text
A → B
≠
B → A
```

The inequality is not merely chronological. It states that order may alter one or more praxis-relevant relations, including:

- frame legibility;
- expectation;
- cost or exposure;
- binding;
- accessible or blocked alternatives;
- asymmetry;
- residue;
- the meaning or consequence of the same later event.

The order-dependence claim must identify which difference is load-bearing. It is not enough to observe that one item happened first.

```text
mere succession
≠ order dependence
```

#### Order dependence is claim-relative

A pair of events may be order-dependent for one claim and order-neutral for another. If an objection occurs before adoption, it may contribute to revision or informed consent. The same objection after adoption may instead create reopening cost or implementation conflict. For a claim about approval conditions, order matters. For a claim merely that both objection and adoption occurred, their co-presence may suffice.

```text
order dependence for claim Q1
≠ order dependence for every claim
```

The analysis must therefore declare:

- the ordered elements;
- the supported order;
- the tested claim;
- the changed praxis dimension;
- the counterfactual reorder;
- the expected result difference;
- the source and claim ceiling.

#### Counterfactual order sensitivity

The primary test is:

> Would a materially different order of the declared load-bearing elements change the warranted reconstruction of this claim?

This is a controlled counterfactual sensitivity test. It does not prove what would empirically have happened in an unrealized world. It tests whether order is constitutive of the declared analytical result.

```text
counterfactual order sensitivity
≠ causal simulation
≠ prediction
```

A positive order-dependence finding requires a reasoned dependency between the reorder and a changed praxis relation. That dependency may be supported by procedural rules, expectation windows, binding conditions, documented costs, or other source-traceable structure.

#### Directionality, asymmetry, and non-commutativity

Order dependence is often directional. The relation does not merely state that two elements differ when exchanged; it identifies which burden is introduced by the earlier position and which is inherited by the later one. This directionality may arise from a rule becoming operative, an expectation window opening, an asymmetry becoming actionable, or a binding becoming costly to reverse.

```text
A before B
→ B occurs under conditions partly shaped by A

B before A
→ A occurs under a different inherited condition
```

This does not mean every earlier occurrence causally produces the later one. The relevant question is narrower: does the later element enter a materially different praxis configuration because of the declared order?

The order claim must therefore distinguish at least three possibilities:

- **commutative for the tested claim** — exchanging the elements does not change the warranted reconstruction;
- **partially order-sensitive** — only a declared dimension such as cost or expectation changes;
- **constitutively order-dependent** — the tested relation cannot be reconstructed without the supported order.

```text
non-commutative analytical relation
≠ complete causal mechanism
```

A finding may also be underdetermined where sources support the actual order but not the consequence of a reorder. In that case chronology may remain admissible while order dependence remains formal-diagnostic or requires a bounded claim. The analyst may not manufacture a counterfactual effect merely to complete the temporal story.

#### C9-ORDER-01 — same elements, different order, different binding

Consider two bounded constructions using the same elements:

```text
construction A:
objection
→ revision
→ adoption

construction B:
adoption
→ objection
→ attempted revision
```

In construction A, the objection enters before the binding adoption event and may alter the adopted rule. In construction B, the objection appears after adoption and may require reopening, additional approval, or acceptance of implementation cost.

For the claim about the burden of changing the rule, the order is material:

```text
objection before adoption
→ lower reopening burden

objection after adoption
→ higher reopening burden
```

Where procedural and source support are adequate, the local result may be:

```text
admissible_with_bounded_claim
```

The claim remains bounded. It does not prove motive, causal completeness, or that every pre-adoption objection lowers cost under every procedure.

#### Order dependence is not path dependence

Order dependence may be one ingredient in later path-dependence testing, but it is not the same property.

```text
order dependence
≠ path dependence
```

Order dependence asks whether reordering load-bearing elements changes the tested result. Path dependence asks whether historically traversed structures materially constrain or shape later continuations under a stronger historical burden. A local order effect may exist without a path, trajectory, or strong historical dependence.

#### Historical order, source order, record order, and narrative order

Several orders must remain distinguishable:

| Order type | What it records | What it does not establish automatically |
| --- | --- | --- |
| historical/event order | supported temporal relation among occurrences | causality or path |
| transition order | supported order among configuration changes | trajectory or dependence |
| source order | order in which items appear within a source | historical order |
| record-production order | order in which records were produced or stored | occurrence order |
| narrative order | order used in a report, interview, or explanation | any historical relation |
| analyst presentation order | expository sequence selected for clarity | source or event order |

These orders may coincide, but coincidence must not be assumed.

```text
narrative order
≠ historical order
```

```text
record order
≠ event order
```

#### C9-ORDER-02 — document order presented as historical order

A compiled report lists:

```text
1. adoption decision
2. objections
3. proposed revisions
```

The report is organized by importance, not chronology. Independent records show that the objections and proposed revisions preceded adoption. Treating list order as historical order would reverse the sequence and distort the approval-burden claim.

The warranted result is:

```text
claim_reduction_required
```

The preserved weaker claim is:

```text
the report presents adoption, objections,
and proposed revisions in that document order.
```

The historical order must be reconstructed from appropriate sources. If the analyst knowingly continues to build a transition, path, or causal story from the document-order substitution, the continuation receives:

```text
mandatory_stop
```

The Stop is local to the invalid continuation. It does not erase the source-order fact or any independently supported temporal position.

#### Minimal order-dependence declaration

```yaml
order_dependence:
  ordered_elements:
  supported_order:
  ordering_basis:
  tested_claim:
  praxis_dimension:
  counterfactual_reorder:
  expected_reconstruction_change:
  source_basis:
  uncertainty:
  claim_ceiling:
```

Again, this is a conceptual handoff to the Shared Transformation Record, not a parallel schema.

<a id="9-5-duration"></a>

### 9.5 Duration

Duration in PATH is not clock time merely recorded. It is the bounded interval through which a declared structure, relation, exposure, expectation, cost, binding, opportunity, or unresolved residue remains praxeologically relevant to the tested claim.

```text
metric time
≠ praxeologically relevant duration automatically
```

A duration claim therefore requires more than two dates. It must identify:

- the reference object or relation whose duration is tested;
- the beginning and ending condition, or the reason an interval remains open;
- the frame and temporal scope;
- the praxis dimension affected across the interval;
- the source basis for continuity through the interval;
- relevant internal changes, interruptions, or uncertain segments;
- the bounded reconstruction difference attributed to duration;
- the Claim Ceiling.

Duration may concern an event-like object, a non-event structure, a frame, a binding, a cost, a transition candidate, or another supported relation. The same metric interval can carry different load under different frames. Different metric intervals can remain equivalent for a bounded claim where no praxis-relevant difference is supported.

```text
equal clock duration
≠ equal praxis load

unequal clock duration
≠ different praxis load automatically
```

#### Duration is not persistence, accumulation, or sedimentation

Duration states how long a declared relation remains relevant under the tested frame. Persistence additionally requires supported structural continuity across changing events or configurations. Accumulation requires an increase or layering of load. Sedimentation requires the stronger historical burden defined in Chapter 3.

```text
duration
≠ persistence
≠ accumulation
≠ sedimentation
```

A long interval can remain analytically neutral. A short interval can be decisive where a narrow decision window closes, an exposure becomes binding, or an alternative becomes unavailable. No universal duration threshold is permitted.

#### Duration and internal variation

An interval must not be represented as homogeneous merely because its endpoints are known. The record should disclose whether the relevant structure:

- remained stable;
- intensified or weakened;
- was interrupted and resumed;
- changed form while retaining the tested function;
- is source-visible only at selected points;
- contains an unknown segment.

```text
bounded interval
≠ homogeneous interval automatically
```

Where continuity through the interval is not supported, the analyst may retain dated observations without claiming an uninterrupted duration.

#### Comparative baseline and duration sensitivity

A duration claim is comparative even where only one realized interval is observed. The analyst must state the baseline against which duration matters. The baseline may be:

- the same relation under a shorter or longer supported interval;
- an explicit procedural window;
- an alternative continuation that remained available only for part of the interval;
- a source-supported threshold condition without turning it into a universal scale;
- the continuation of a cost, binding, or exposure beyond a declared point.

```text
interval length without comparative baseline
≠ demonstrated duration effect
```

The counterfactual question is bounded:

> If the relevant interval were materially shorter or longer, with other source-supported conditions held comparable, would the warranted reconstruction of the tested praxis relation change?

This question tests duration sensitivity. It does not predict an unobserved history or establish a causal mechanism. The sources may support only direction, not magnitude. For example, they may show that continued non-resolution closes an alternative without supporting a precise claim that each additional day adds equal cost.

```text
duration sensitivity
≠ linear dose-response
≠ universal temporal threshold
```

Duration can also interact with frame. A thirty-day interval inside a declared reconsideration window differs from the same thirty days before any objection is eligible. The metric quantity is identical; the temporal position and praxeological relation differ. Duration therefore cannot be evaluated independently of frame, reference object, and condition.

#### C9-DUR-01 — equal event types, different duration, different load

Two review requests receive the same formal acknowledgement. In `R_short`, a final answer follows within two days while all alternatives remain open. In `R_long`, the acknowledgement is followed by thirty days without resolution; during that interval the original decision remains effective, an objection window closes, and repeated documentation costs accrue.

The event type “acknowledgement” is the same. The praxeological duration is not.

```text
same event type
+ different source-traceable interval load
→ bounded duration relevance
```

For the claim that the longer unresolved interval changes exposure, available alternatives, and reopening cost, the local result may be:

```text
admissible_with_bounded_claim
```

The result does not establish intent, a universal threshold, path dependence, or an attractor function. A later claim that duration reinforces an attractor would require a separate `PROJECT_AS` or operator-occurrence analysis with its own source and target burdens.

<a id="9-6-delay"></a>

### 9.6 Delay

Delay is a temporally deferred realization relation whose praxeological relevance depends on what is deferred, relative to which expectation or process, under what conditions, and with what effects on costs, bindings, alternatives, asymmetries, or later interpretation.

Chapter 9 distinguishes two claim forms:

```text
delay as transition structure
≠ delay as framed non-event
```

The forms may concern the same interval, but they carry different burdens and require separate declarations.

#### Delay as transition structure

Delay as transition structure concerns temporal spacing or deferred realization between configurations. It may be relevant where the interval:

- shifts costs or exposure;
- changes which alternatives remain reachable;
- stabilizes an existing decision or asymmetry;
- alters expectations or reopening burden;
- changes the meaning or effect of a later event;
- leaves unresolved residue across the transition candidate.

This claim does not require a warranted expected occurrence in the strict `Λ` sense. It requires a supported deferred relation and a traceable praxis difference.

```text
deferred transition relation
≠ framed non-event automatically
```

#### Multiple clocks and the object of delay

A delay claim must identify what is delayed. Administrative clock time, contractual opportunity time, actor-exposure time, and decision-sequence time may diverge.

```text
one elapsed interval
≠ one delay relation automatically
```

A process can be formally “on time” while an actor’s usable alternative closes. Conversely, a missed internal target may carry no praxeological load for the tested claim. The record should therefore distinguish:

- the delayed object or realization;
- the clock or condition relative to which delay is measured;
- the actors or relations exposed during the interval;
- alternatives that remain, narrow, or disappear;
- whether the delay is continuous, interrupted, renewed, or retrospectively constructed.

Delay may also be strategically produced, accidentally produced, or source-underdetermined. Chapter 9 does not infer motive from temporal structure.

```text
benefit from delay
≠ proof of intentional delay
```

Where the same interval supports a transition-structure claim and a framed-non-event claim, the records may share sources but must not share conclusions automatically. The structural delay can remain valid if the expected-occurrence claim later fails, and the non-event can remain valid even where the precise downstream transition effect remains underdetermined.

#### C9-DELAY-01 — delay changes alternatives without a warranted expected occurrence

A working group postpones selection among three proposals. The sources establish that no deadline or promised decision date existed. They also establish that during the postponement one proposal becomes contractually unavailable and the incumbent arrangement continues to allocate costs asymmetrically.

The interval supports a transition-structure claim:

```text
delay
→ changed reachable alternatives
→ continued asymmetric cost allocation
```

It does not support a framed non-event because no warranted expected decision and bounded realization condition are established.

A bounded local result may be:

```text
admissible_with_bounded_claim
```

Calling the interval a `Λ` non-event would require reduction. If missing expectation evidence is knowingly replaced by an invented promise, continuation must stop.

#### Delay as framed non-event

A delay qualifies as a framed non-event only where the record supports:

1. an identifiable expected occurrence;
2. a warranted expectation relation;
3. a bounded realization window or condition;
4. non-realization within that window or condition;
5. praxeological load carried by the non-realization;
6. source and uncertainty disclosure.

```text
elapsed time
≠ non-event

missing information
≠ non-event
```

Positive sub-events do not automatically eliminate the non-event. Reminders, scheduling messages, partial measures, or postponement notices may occur while the expected occurrence remains unrealized.

#### C9-DELAY-02 — supported expected decision not realized

A written decision promises reconsideration within thirty days after a documented objection. The objection is submitted. Reminders and a scheduling exchange occur, but no reconsideration decision is issued within the declared window. The original approval remains effective and the objector bears additional procedural cost.

Two claims can be recorded separately:

```text
delay as transition structure
→ the interval changes cost and reopening burden

delay as framed non-event
→ the promised reconsideration is not realized
   within the warranted condition
```

The non-event claim preserves the `Λ` boundary. It does not transform the whole interval into an absence of events and does not infer motive. The local result may be:

```text
admissible_with_bounded_claim
```

If later evidence shows that the promise was withdrawn before the window began, the non-event claim must be revised without erasing the independently supported delay structure.

<a id="9-7-persistence"></a>

### 9.7 Persistence

Persistence is the continued structural relevance of a declared frame, binding, cost, residue, asymmetry, expectation, constraint, or accessibility relation across changing events or configurations.

```text
persistence
≠ stasis
≠ duration alone
≠ repetition alone
≠ sedimentation automatically
```

A persistent structure need not remain descriptively unchanged. Its carriers, visibility, or local expression may vary while the tested relation continues to shape praxis. Conversely, two similar snapshots do not prove persistence through the unobserved interval.

#### Persistence burden

A persistence claim should declare:

- the structure or relation claimed to persist;
- the configurations or interval across which persistence is tested;
- the continuity criterion;
- changing surrounding events and configurations;
- the source trace connecting the observations;
- interruptions, transformations, or uncertainty;
- the praxeological effect retained across the interval;
- the Claim Ceiling.

```text
same label at t1 and t2
≠ persistence through t1–t2
```

The continuity criterion may concern retained binding force, continued cost, continuing exclusion, durable expectation, residual interpretive load, or another bounded relation. It must not silently shift between observations.

#### Persistence can coexist with change

A formal rule may be amended while the same reopening burden persists. An actor may leave while a documented commitment continues to structure later review. New events may occur while an unresolved residue remains load-bearing.

```text
change in carrier
≠ disappearance of relation automatically
```

Equally, persistence of one relation does not establish persistence of the whole configuration.

#### Carrier continuity, functional continuity, and interruption

Persistence can be carried by the same material or institutional carrier, by a successor carrier, or by a distributed relation. These possibilities must not be collapsed.

```text
same carrier
≠ persistence automatically

changed carrier
≠ ended persistence automatically
```

A documented obligation may persist after personnel turnover because the obligation remains in force and continues to structure later review. A recurring phrase may fail to persist as a binding if its operative conditions disappear. The claim must therefore identify whether continuity concerns identity of carrier, continuity of function, continuity of burden, or continuity of reference.

Temporary interruption also requires care. A relation may be suspended and later restored. Whether this counts as persistence depends on the tested claim and continuity criterion. For a claim about uninterrupted access restriction, suspension defeats persistence. For a claim about continuing historical burden, the interruption may not erase accumulated cost.

```text
interrupted manifestation
≠ interrupted historical load automatically
```

The analyst should record negative evidence: occasions on which the alleged persistent relation should have appeared but did not. Persistence is weakened where later configurations are fully explicable without the relation or where counterexamples show that it ceased to structure action corridors.

#### C9-PERSIST-01 — binding persists through changing events

After adoption, three events occur: a clarification is issued, the responsible chair changes, and a partial procedural amendment is approved. The sources nevertheless show that the original reconsideration condition remains active, later requests continue to cite it, and reopening still requires the same additional justification.

The supported claim is not that the configuration stayed static. It is that a bounded binding relation persisted through changing events.

```text
changing events
+ continuous source-traced binding
→ persistence candidate
```

The local result may be:

```text
admissible_with_bounded_claim
```

A stronger claim that the binding has sedimented into a trajectory or become permanent remains untested. If the interval between the observations is undocumented, the result must become provisional, reduced, or formally diagnostic rather than falsely continuous.

<a id="9-8-irreversibility"></a>

### 9.8 Irreversibility

Chapter 3 defines irreversibility. Chapter 9 operationalizes it for transition reconstruction as a bounded claim that a specified earlier relation, condition, accessibility state, cost distribution, expectation, or reference position is not restored, neutralized, or made cost-equivalent under a declared restoration criterion.

```text
bounded irreversibility
≠ absolute irreversibility
≠ metaphysical impossibility
≠ permanence under every future condition
```

The controlling question is not simply whether an action can be formally reversed. It is:

> Under the declared criterion, does the attempted return restore the relevant prior relation without residual difference or additional cost?

#### Repetition, return, exit, and reset

```text
repetition
≠ return

formal reversal
≠ full restoration

exit
≠ reset
```

A repeated configuration may occur under changed expectations and accumulated residue. Formal repeal may remove a rule while leaving cost, exposure, public commitment, or interpretive history intact. Exit may terminate participation without restoring the earlier opportunity structure.

An irreversibility claim therefore requires:

- a bounded reference object or relation;
- a before/after relation;
- frame and temporal scope;
- an explicit restoration, neutralization, or cost-equivalent-return criterion;
- source-supported residual difference or additional cost;
- uncertainty and alternatives;
- Claim Ceiling and re-entry condition.

#### Local versus strong irreversibility

A relation can be irreversible under one criterion and reversible under another.

```text
formal-rule restoration: achieved
cost-equivalent restoration: not achieved
expectation restoration: underdetermined
```

This is not contradiction. It is claim segmentation. A universal statement such as “history can never be reversed” is outside the bounded architecture and requires reduction or Stop.

#### Criterion matrix and asymmetric restoration

Because restoration criteria can diverge, a responsible irreversibility record may use a criterion matrix rather than one global verdict:

| Criterion | Tested return | Possible finding |
| --- | --- | --- |
| formal rule | prior text reinstated | restored |
| access corridor | prior option set reopened | partially restored |
| cost distribution | accumulated burden neutralized | not restored |
| expectation relation | prior confidence recreated | underdetermined |
| public trace | prior commitment removed from record | not restored |

The rows are not weighted into a score. A positive row cannot compensate for a failed row when the claim concerns that failed criterion.

```text
multi-criterion record
≠ compensatory irreversibility score
```

Irreversibility can be asymmetric. Moving from `C0` to `C1` may require one event, while returning to a cost-equivalent `C0` may require additional actions, resources, consent, or impossible removal of historical exposure. This asymmetry supports a bounded claim only where the additional burden is source-traceable.

```text
asymmetric return burden
≠ inevitability of future continuation
```

A high restoration cost does not prove absolute impossibility. Where restoration remains possible but materially more burdensome, the claim should say so. Where sources cannot distinguish impossibility from unattempted repair, `non_capture`, a Formal Diagnostic, or Claim Reduction may be more responsible than an irreversibility verdict.

#### C9-IRREV-01 — apparent return leaves cost and residue

A review rule is formally withdrawn and the earlier procedural text is restored. The source record also shows that:

- the unresolved reconsideration promise remains documented;
- participants incurred repeated explanation and filing costs;
- later requests are interpreted against the withdrawn rule’s history;
- no mechanism neutralizes the accumulated burden.

Under the criterion **cost-equivalent return to the pre-adoption review relation**, the candidate is:

```text
admissible_with_bounded_claim
```

Under the criterion **formal restoration of the earlier rule text**, return may be achieved. The record must preserve both findings.

```text
one restoration criterion satisfied
≠ all restoration criteria satisfied
```

A claim of permanent, total, or metaphysical irreversibility requires:

```text
claim_reduction_required
```

Refusal to state any restoration criterion while continuing to derive trajectory or path-dependence claims triggers:

```text
mandatory_stop
```

<a id="9-9-temporal-recontextualization"></a>

### 9.9 Temporal Recontextualization

Temporal recontextualization is the bounded historical relation in which a later event, configuration, or frame changes the legibility, relevance, or claim-supporting role of an earlier structure while the earlier occurrence and sequence remain part of the historical trace.

```text
temporal recontextualization
≠ retroactive erasure
```

A later event may make an earlier commitment appear more consequential, reveal a previously hidden dependency, weaken an earlier interpretation, or change which features matter for a current claim. It does not alter the fact that the earlier structure occurred under its earlier conditions.

#### Three distinct claims

Chapter 9 preserves:

```text
temporal recontextualization as historical relation
≠ Φ operator type
≠ PROJECT_AS target function
```

A concrete later framing occurrence may separately be typed through PMS `Φ`. A source object may separately be projected as performing a bounded function through `PROJECT_AS`. Neither claim is implied by the historical relation alone.

```text
later event changes earlier legibility
≠ new target function automatically
```

#### Anti-erasure and dual dating

A responsible record should preserve at least two positions:

- what the earlier structure supported under the earlier frame and source state;
- what additional or revised claim becomes supportable after the later event.

```text
earlier warranted reading at t1
+ later recontextualized reading at t2
→ two historically located claims
```

The later reading may correct an earlier error where new evidence directly contradicts it. Even then, the earlier claim’s historical occurrence and prior support state should not be rewritten as if it had never existed.

#### Event time, evidence time, and claim time

Temporal recontextualization requires careful dating of at least three things:

- when the earlier structure occurred;
- when the later recontextualizing structure occurred or became visible;
- when the analyst’s revised claim becomes warranted.

```text
event time
≠ evidence-availability time
≠ claim-revision time
```

A later-discovered contemporaneous document may correct the evidential basis without being a later historical event. A genuinely later non-realization may change the historical relation itself. These are different routes to a revised interpretation.

Recontextualization is therefore not retrocausality. The later event need not cause the earlier event to have been different. It changes which bounded claims about the earlier event are warranted from the later historical position.

```text
later legibility
≠ later causation of the earlier occurrence
```

Anti-erasure applies in both directions. The earlier reading must not be silently replaced, but the later reading must not be weakened merely to preserve narrative consistency. The record should show whether the later evidence:

- adds a new relation;
- narrows an earlier claim;
- contradicts an earlier interpretation;
- changes the current relevance of an earlier structure;
- leaves rival historically located readings unresolved.

Where rival recontextualizations remain equally source-responsible, later Chapter 9 routing may require `non_capture` rather than a forced retrospective synthesis.

#### C9-RECTX-01 — later event changes earlier legibility

At adoption, a promise of reconsideration is treated as a procedural safeguard. Thirty days later, no reconsideration has occurred and the original decision remains effective. The later non-realization changes how the promise can be reconstructed: it now also marks an unresolved binding and increased reopening burden.

The responsible result preserves:

```text
t1:
promise as declared safeguard

t2:
promise plus non-realization
as unresolved binding and reopening burden
```

The later event does not erase the original sequence or prove that the promise was insincere from the start. A bounded temporal-recontextualization claim may receive:

```text
admissible_with_bounded_claim
```

A separate `Φ` occurrence or `PROJECT_AS` function claim requires its own record. Retrospectively rewriting the adoption record to say that no safeguard was ever present would violate historical traceability.

<a id="9-10-transition-preconditions"></a>

### 9.10 Transition Preconditions

A transition claim concerns a bounded relation between at least two reconstructible configurations. It states that, within a declared frame and temporal scope, source-supported events, non-events, retained structures, and temporal relations warrant a praxeologically relevant reconstruction of change between a source configuration and a target configuration.

```text
configuration difference
≠ transition automatically
```

A transition is therefore not produced by placing two descriptions side by side. The relation between them must itself be reconstructed. The source and target configurations may each be valid while the transition claim connecting them remains reduced, diagnostic, failed, or responsibly uncaptured.

Chapter 3 remains the primary definition site for transition as a temporal object. Chapter 9 operationalizes when a transition claim is sufficiently declared and supported for PATH work.

#### Conjunctive preconditions

A transition candidate requires all of the following burdens to be addressed:

1. **Reconstructible configurations.** At least two configurations must be identifiable under explicit object, frame, granularity, relative-level, and temporal-scope declarations.
2. **Reference and comparison basis.** The record must state what is being compared across the configurations and under which continuity or handoff relation.
3. **Relevant temporal relation.** Before/after, interval, partial order, delay, persistence, or another bounded temporal relation must connect the configurations.
4. **Determinate change object.** The claim must identify which relation, action corridor, asymmetry, binding, expectation, frame, residue, or accessibility condition is said to change or persist.
5. **Event/non-event separation.** Positive occurrences and structured non-realizations must be declared separately; missing information cannot fill either role.
6. **Constitutive Source Trace.** The sources must support not only the endpoints but the relation claimed between them.
7. **Intermediate-structure disclosure.** Known intervening events, non-events, gaps, branches, interruptions, and rival relations must be visible where they can alter the claim.
8. **Changed and retained fields.** The record must distinguish what changes from what remains load-bearing across the relation.
9. **Frame and scope control.** Any frame change must be declared, and the claim must remain bounded to the comparison it can support.
10. **Praxeological difference.** The transition must alter the warranted reconstruction of costs, expectations, bindings, action corridors, asymmetries, residues, alternatives, or another declared praxis dimension.
11. **Claim and authority ceilings.** The result must not exceed the source basis or inherit application authority.

```text
precondition completeness
≠ transition truth automatically
```

The preconditions are conjunctive and non-compensatory. Rich endpoint descriptions cannot compensate for an unsupported temporal relation. A strong temporal order cannot compensate for an unmarked frame change. A visible change cannot compensate for missing Reference Continuity. Practical usefulness cannot compensate for absent Constitutive Source Trace.

```text
well-described source configuration
+ well-described target configuration
+ unsupported relation
→ no warranted transition yet
```

#### Candidate, warranted transition, and operation boundary

A **transition candidate** is a delimited claim for which the required fields and burdens have been declared but not yet fully resolved. A **warranted transition** is a transition claim that passes the applicable continuity, admissibility, loss, governance, and routing tests for its bounded scope.

```text
transition candidate
≠ warranted transition
≠ STRATA operation occurrence
```

Neither status selects `COMPOSE`. Chapter 10 may later use a set of warranted transitions as source material for a path claim. Chapter 15 owns the complete `COMPOSE` procedure. The transition remains a temporal object or relation, not a fourth operation.

#### Directionality without teleology

A transition declaration is directional because it relates a source configuration to a target configuration under temporal order. Reversing the direction creates a different claim.

```text
Transition(K0, K1, Q)
≠
Transition(K1, K0, Q)
```

This directionality does not imply improvement, decline, purpose, destination, or inevitable continuation. `source_configuration` and `target_configuration` are analytical positions in the tested relation, not lower and higher developmental stages.

```text
source → target direction
≠ progress
≠ decline
≠ destiny
```

A later configuration may restore some earlier relation, intensify a burden, reopen an alternative, or combine restoration and residue. The transition record must state the dimension of change instead of assigning a global developmental sign.

#### Transition relation and causal mechanism

A transition claim can be warranted without a complete causal mechanism. It must nevertheless show a source-supported constitutive relation rather than mere succession.

```text
warranted transition relation
≠ complete causal explanation
```

The distinction protects two boundaries at once. First, absence of causal proof does not force every transition into failure where order, continuity, events, non-events, and praxis change are sufficiently supported. Second, a warranted transition cannot be inflated into a causal statement merely because its temporal relation is clear.

Where a causal claim is added, it must declare its own source basis, alternative mechanisms, counterfactual burden, and Claim Ceiling. Chapter 9 records only the transition relation needed for PATH.

#### Claim segmentation across change dimensions

One source-to-target pair may support several transition claims. A closing action corridor, persistent cost asymmetry, changed frame, and unresolved binding are not automatically one indivisible change.

```text
one configuration pair
≠ one omnibus transition claim automatically
```

The analyst should segment claims where different dimensions have different evidence, continuity conditions, uncertainty, or routing outcomes. For example:

- the action-corridor transition may be admissible;
- the asymmetry transition may remain provisional;
- the frame-change relation may be diagnostic;
- the intention claim may fail.

A single global result must not conceal this differentiation. Where a composite transition claim is retained, its constitutive relations and local results must remain reconstructible.

#### Comparison basis and constitutive change

A comparison basis specifies the dimension under which source and target configurations are treated as comparable. Examples include:

- accessibility of an alternative;
- reopening burden;
- allocation of decision cost;
- binding force of a commitment;
- persistence of an asymmetry;
- realization status of an expected occurrence;
- availability of a review corridor.

The comparison basis must not be inferred from a shared label alone.

```text
same object name at t1 and t2
≠ same comparison basis automatically
```

The record must also distinguish visible change from constitutive change:

```text
changed field
≠ constitutive transition field automatically
```

A chairperson, document label, or interface may change while the tested binding persists. Conversely, a formally unchanged rule may acquire a different praxis relation because an objection window closes or an alternative becomes unavailable.

Retained fields are equally important:

```text
retained field
≠ irrelevant field automatically
```

A continuing frame, cost asymmetry, or unresolved commitment may provide the continuity that makes a bounded transition reconstruction possible.

#### Intermediate structures and source gaps

A transition record must disclose intermediate structures in proportion to their possible effect on the claim. It need not reproduce every occurrence in the interval. Compression remains possible where selection and loss are declared.

```text
non-exhaustive interval reconstruction
≠ failed transition automatically
```

But an omitted intermediate structure is load-bearing where it could:

- reverse or suspend the claimed relation;
- change the relevant frame;
- reopen an alternative;
- satisfy or cancel an expected occurrence;
- replace the reference object;
- introduce a rival transition reconstruction.

Where such a structure is known to be missing, the result cannot be strengthened by treating the interval as empty. The appropriate state may be bounded support, `formal_diagnostic`, `claim_reduction_required`, `failed_transformation`, or `non_capture`, depending on what remains responsibly reconstructible.

#### C9-TRANS-01 — positive minimal transition candidate

At `K0`, a documented decision remains open to reconsideration after a written objection. The objection is submitted. During the next thirty days no reconsideration decision is issued, the original decision remains effective, and an alternative contractually closes. At `K1`, reopening requires an additional approval step and higher documentation cost.

The bounded comparison basis is the review corridor. The record supports:

- source configuration `K0` with an available reconsideration corridor;
- a warranted objection event;
- a separately warranted non-realization of promised reconsideration;
- a delay interval during which the original decision remains operative;
- target configuration `K1` with a narrowed action corridor and higher reopening burden;
- retained reference to the same decision and review relation;
- unresolved uncertainty about intention and causal mechanism.

The local transition claim may receive:

```text
admissible_with_bounded_claim
```

The result states that the review corridor changed under the documented temporal relation. It does not yet compose a path, prove intent, establish a trajectory, or establish path dependence.

<a id="9-11-transition-structure"></a>

### 9.11 Transition Structure

The minimal Chapter 9 transition structure is:

```yaml
transition:
  source_configuration:
  target_configuration:
  events:
  non_events:
  temporal_order:
  changed_frames:
  changed_action_corridors:
  changed_asymmetries:
  changed_bindings:
  unresolved_residue:
```

This form is a conceptual PATH declaration, not a second schema. Chapter 7 remains the owner of the Shared Transformation Record. Chapter 9 specifies what a transition claim must contribute to that record.

#### Source and target configurations

Each configuration must be reconstructible in its own right. The transition record should reference rather than silently rewrite those configuration records. It must declare:

- stable identifiers;
- object and occurrence typing;
- frame, granularity, relative level, and temporal scope;
- source basis and known gaps;
- the reference and comparison relation between them.

```text
valid configurations
≠ valid transition automatically
```

If source and target concern different reference objects, the analyst must declare the relation that permits comparison. If no such relation is supported, the configurations may remain separately valid while the transition claim fails.

#### Events and non-events

Events and non-events are separate contributors to the transition structure. An event may alter a configuration directly, while a non-event may preserve or intensify an existing relation under a warranted expectation frame.

```text
positive event list
≠ complete transition relation
```

```text
non-event
≠ blank interval
```

A transition may be supported by events alone, by a combination of events and non-events, or by a persistent relation across an interval. The record must state which elements are constitutive and which are contextual.

#### Temporal order and order uncertainty

The `temporal_order` field should preserve the strongest supported form:

- exact order;
- bounded relative order;
- partial order;
- interval relation;
- disputed order;
- unresolved relation.

It must not manufacture a total chronology where only a partial order is supported. Where the transition claim depends on the unresolved order, the uncertainty is load-bearing.

```text
order uncertainty material to Q
→ Q cannot be routed as if order were settled
```

Where rival orders produce the same bounded reconstruction for the tested claim, exact order may be unresolved without defeating the transition.

#### Changed frames and explicit frame handoff

A frame may remain stable, change as part of the transition, or become analytically re-specified. These possibilities must not be collapsed.

```text
frame change
≠ transition automatically
```

```text
unmarked frame change
≠ valid direct comparison
```

Where source and target use different frames, the record requires an explicit frame handoff:

1. source frame;
2. target frame;
3. reason for the change;
4. invariant or translation relation permitting comparison;
5. loss and uncertainty introduced by the handoff;
6. claim scope that remains valid across it.

A frame change can itself be part of a transition only where the historical or analytical relation is source-supported. It cannot be used to make incompatible descriptions appear continuous.

#### Changed action corridors, asymmetries, and bindings

These fields record distinct praxis dimensions:

- **action corridor:** which actions or alternatives remain reachable;
- **asymmetry:** how costs, access, information, exposure, or decision power are distributed;
- **binding:** which commitment, rule, expectation, or unresolved relation continues to constrain later praxis.

```text
action-corridor change
≠ asymmetry change automatically
≠ binding change automatically
```

A transition may affect one dimension while another remains stable. The record should not compress them into a single undifferentiated “change” label or scalar score.

#### Unresolved residue

`unresolved_residue` records what remains active, uncertain, excluded, contested, or insufficiently reconstructed after the source-to-target relation is stated. It may include:

- unresolved commitments;
- unclosed alternatives;
- disputed order;
- uncertain causal mechanism;
- rival frame handoffs;
- missing intermediate source structure;
- costs or expectations not restored by formal reversal.

```text
unresolved residue
≠ transition failure automatically
```

Residue may be constitutive of a bounded transition. It becomes disqualifying only where the tested claim requires its resolution or where it destroys Reference, Functional, Temporal, or Type Continuity.

#### Mapping into the Shared Transformation Record

The conceptual transition fields map into existing Chapter 7 families:

| Chapter 9 transition item | Shared Record carrier |
| --- | --- |
| source/target configurations | `source`, `target`, and record relations |
| events/non-events/order | source trace, temporal scope, claim, and operation-neutral relation payloads |
| changed/retained dimensions | admissibility rationale, continuity findings, and claim declaration |
| frame handoff | source/target frame fields plus continuity and loss |
| unresolved residue | loss, alternatives, formal diagnostics, capture, and governance |
| local result | routing state and one canonical Output Class where routed |

```text
record-field availability
≠ transition warrant
```

No new schema field is canonically required at WP3. The WP4 prose-to-model audit will verify whether the existing carriers remain sufficient after integrated Chapter 9 review.

#### Transition evidence matrix

A transition record should permit the reviewer to inspect at least four evidence relations separately:

| Evidence relation | Question | Non-compensatory boundary |
| --- | --- | --- |
| endpoint support | Are source and target configurations reconstructible? | strong endpoints cannot prove the connecting relation |
| temporal support | Is the relevant order or interval supported? | order cannot repair reference or frame discontinuity |
| constitutive support | Which events, non-events, retained fields, or intermediate structures carry the change? | visible difference cannot replace source-result dependency |
| praxis support | What warranted reconstruction changes for the tested claim? | source abundance cannot replace PraxisPurchase |

The matrix is not a score. A large amount of endpoint evidence cannot compensate for missing constitutive support, and strong praxis relevance cannot compensate for Type or Reference failure.

```text
evidence quantity
≠ transition admissibility
```

Where one relation is unresolved, the record should identify exactly which claims depend on it. This allows local diagnostic or reduction without collapsing every associated temporal finding.

#### C9-FRAME-01 — unmarked frame change

`K0` is reconstructed under a procedural frame that tracks whether formal review remains available. `K1` is reconstructed under an outcome frame that tracks whether the original decision remains effective. The analyst claims a direct transition from “open” to “closed” without marking that “open” refers to procedural accessibility while “closed” refers to substantive outcome.

The configurations may each be valid. The direct transition comparison is not.

```text
valid K0
+ valid K1
+ incompatible unmarked comparison basis
→ failed direct transition claim
```

The result is `formal_diagnostic` while an explicit frame handoff remains possible. If no invariant comparison relation can be established, the stronger direct transition receives `failed_transformation`. The two configurations and their source-specific findings remain preserved.

#### C9-UNCERT-01 — indispensable but unresolved temporal order

Two dated sources establish that an objection and a restriction both occurred during the same week, but not which came first. The tested claim states that the restriction was imposed in response to the objection. The order is indispensable to that claim and remains unresolved.

The record may preserve:

- both occurrences;
- the bounded week;
- the fact that both precede `K1`;
- rival orders;
- the evidence needed for re-entry.

It may not route the response-order claim as established. The current state is:

```text
formal_diagnostic
```

A weaker claim that both occurrences contributed to the later configuration may be separately tested. Uncertainty is neither automatically `non_capture` nor permission to choose the narratively convenient order.

<a id="9-12-transition-failure"></a>

### 9.12 Transition Failure

A transition claim fails when the source-to-target relation required by that claim cannot be responsibly reconstructed within its declared frame, source basis, comparison basis, and Claim Ceiling.

```text
transition failure
≠ absence of all temporal information
```

The analyst must preserve every weaker finding that remains warranted: valid configurations, dated events, partial order, duration, delay, persistence, frame-specific observations, rival candidates, or formal diagnostics.

#### Primary failure modes

No sufficient transition is established where:

- only two isolated snapshots are available;
- the relevant temporal relation is unknown or source-indifferent;
- change is asserted without a determinate change object;
- the source supports endpoint difference but not the claimed relation;
- load-bearing intermediate structures are omitted;
- the reference object changes without handoff;
- the frame changes without declaration or comparability rationale;
- event and non-event claims are collapsed;
- retained structures required for continuity are ignored;
- unresolved uncertainty is converted into false precision;
- the claim exceeds the Source or Claim Ceiling.

These modes do not all route identically.

#### Routing separation

**Formal Diagnostic** applies where a required declaration or relation remains unresolved but responsible re-entry is possible. It has no canonical Output Class.

**Claim Reduction Required** applies where a narrower temporal claim remains supportable but the declared transition claim is too strong.

**Failed Transformation** applies where the delimited transition claim, treated as a testable STRATA claim, cannot be responsibly sustained and no mere formal completion would repair it.

**Mandatory Stop** applies where analysis continues from a known failed load-bearing transition into a path, trajectory, path-dependence claim, causal story, or authority transfer.

**Non-Capture** applies where rival transition reconstructions are each source-responsible, materially consequential, and not responsibly decidable under the available sources and frame.

```text
formal_diagnostic
≠ claim_reduction_required
≠ failed_transformation
≠ mandatory_stop
≠ non_capture
```

A local rule finding such as unresolved order or frame mismatch is not itself an Output Class. Claim delimitation and routing remain necessary.

#### C9-TRANS-02 — isolated snapshots without relation

`K0` and `K1` are documented six months apart. `K0` records decentralized review; `K1` records centralized approval. No source establishes when the change occurred, what intermediate configurations existed, whether the reference process remained the same, or which event or non-event carried the relation.

The endpoint descriptions remain valid. The claim “decentralized review transitioned directly into centralized approval” does not.

A narrower result may be:

```text
claim_reduction_required
```

for the statement that the two dated configurations differ. If the direct transition remains the delimited claim after the missing relation is acknowledged, it receives:

```text
failed_transformation
```

#### C9-STOP-01 — failed transition used as path and causal story

The `C9-TRANS-02` direct relation is known to have failed. The analyst nevertheless orders `K0 → K1`, calls the pair a path, and explains the later centralized configuration as caused by the alleged direct transition.

```text
failed load-bearing transition
+ continued path and causal derivation
→ mandatory_stop
```

The Stop applies to the path and causal continuation. It preserves:

- `K0` and `K1` as separately supported configurations;
- their dated difference;
- any bounded interval claim;
- the missing relation;
- the re-entry requirement for intermediate sources.

Stop does not convert the interval into a non-event and does not erase valid endpoint evidence.

#### C9-NC-01 — rival transition reconstructions

The sources establish `K0`, a delayed review interval, and `K1` with a narrower action corridor. Two reconstructions remain equally source-responsible:

```text
candidate A:
non-realized reconsideration preserves the original binding,
which narrows the later corridor

candidate B:
a separately documented rule clarification changes the corridor,
while the non-realization remains only concurrent
```

Both candidates preserve the same endpoint configurations and temporal interval. Available sources do not determine which relation is constitutive for the tested transition claim. Forcing a synthesis would hide the rivalry; choosing either candidate would exceed the Source Ceiling.

The claim-relative result is:

```text
non_capture
```

The record preserves both candidates, shared evidence, candidate-specific loss, the unresolved constitutive relation, and the re-entry evidence that could distinguish them. `non_capture` validates neither candidate as the transition.

#### Handoff to Chapter 10

Chapter 9 may hand Chapter 10 a set of individually delimited transition records containing:

- source and target configuration references;
- supported temporal order;
- comparison basis;
- changed and retained dimensions;
- events, non-events, and relevant gaps;
- frame handoff where applicable;
- loss, alternatives, and unresolved residue;
- routing state and local result;
- Stop and Non-Capture preservation.

```text
warranted transition set
≠ path automatically
```

Chapter 10 must separately test actual traversal, selection, sequence, constitutive relation, branch and omission handling, and Path identity. Chapter 9 does not pre-authorize that result.

#### Chapter 9 completion boundary

Sections 9.1–9.12 jointly establish the PATH entry conditions for temporal order and transition:

- PATH as a Part rather than an operation or an undeclared target-function layer;
- the bounded contribution of `Θ` to temporal structuring;
- temporal position, partial order, uncertainty, and retrospective periodization;
- claim-relative order dependence without causal proof or path-dependence inflation;
- duration, delay, persistence, bounded irreversibility, and temporal recontextualization;
- conjunctive, non-compensatory transition preconditions;
- comparison-basis, frame-handoff, constitutive-change, and intermediate-structure control;
- a minimal transition declaration mapped into the Shared Transformation Record;
- separate action-corridor, asymmetry, binding, residue, loss, and uncertainty burdens;
- distinct Formal Diagnostic, Claim Reduction, Failure, Mandatory Stop, and Non-Capture routes;
- preservation of weaker temporal findings when a stronger transition claim fails;
- a bounded Chapter 10 handoff that supplies individually warranted transitions without forming a path.

The integrated Chapter 9 claim is:

```text
A transition is a frame-bound, source-supported relation
between configurations whose temporal order,
constitutive events and non-events,
changed and retained praxis conditions,
and unresolved residue remain reconstructible.
```

This claim remains bounded by several non-equivalences:

```text
configuration difference
≠ transition automatically

warranted transition
≠ path automatically

transition relation
≠ causal mechanism

PATH
≠ COMPOSE
```

The Chapter 9 completion test is satisfied:

1. source and target configurations plus their comparison basis are explicit;
2. temporal position, order, duration, delay, and uncertainty can be represented without false precision;
3. events and non-events remain separately testable;
4. changed frames, action corridors, asymmetries, bindings, retained fields, and residue can be declared without a composite change score;
5. `Θ` is not treated as sufficient for trajectory, sedimentation, path dependence, causality, or authority;
6. transition candidates, warranted transitions, operation occurrences, and paths remain distinct;
7. a failed transition remains a valid local result and does not erase its endpoints or weaker temporal findings;
8. Stop and Non-Capture remain available and preserve re-entry conditions;
9. the existing Shared Record and Formal Model provide adequate carriers without creating a second transition schema or automatic semantic decision procedure;
10. Chapter 10 receives only bounded transition records and must independently establish actual traversal, selection, constitutive ordering, branches, omissions, and Path identity.

The integrated boundary is intentionally asymmetric. Chapter 9 may determine that a proposed transition is insufficient while retaining its configurations, event records, interval, partial order, duration, delay, persistence, or rival reconstructions. It may not reverse that relation by treating the preserved material as proof that a transition, path, or causal mechanism must exist. Likewise, a later successful Path reconstruction cannot retroactively repair an earlier transition claim that failed under its own comparison basis or source record. Chapter 10 may formulate a new, independently testable claim from revised or additional evidence, but the new claim must preserve the earlier failure, its loss record, and the reason re-entry became possible.

```text
preserved temporal material
≠ preserved stronger transition claim

later path success
≠ retroactive transition repair
```

This anti-laundering rule also governs changes of frame, granularity, relative level, label, or target function. A different representation can generate a new testable relation; it cannot silently convert missing constitutive support into historical continuity. The Chapter 9 handoff therefore transfers reconstructible records and explicit limits, not a presumption that those records will compose into one path. This preserves local failure, bounded uncertainty, rival reconstruction, and source-specific re-entry as positive analytical content for later PATH work.

The chapter-level result is:

```text
admissible_but_provisional
```

The provisionality does not identify a known local defect. It preserves later pressure from Chapter 10 Path formation, Chapter 11 Trajectory, Chapter 12 Path Dependence, Chapter 15 `COMPOSE`, Chapter 16 PATH Boundary Conditions, Chapter 17 cases and local audit, later Parts, LIMITS, the Corpus Audit, and Model Finalization.

```text
Chapter 9 provisional lock
≠ transition truth proof
≠ path preauthorization
≠ causal confirmation
≠ higher authority
```

The next controlled production step is:

```text
Chapter 10 — Preparation:
Path
```

<a id="chapter-10-path"></a>

## 10. Path

Chapter 9 established when two or more configurations may be connected by a warranted transition. Chapter 10 asks a stronger question:

> What additional structure turns chronology, a sequence, or a set of warranted transitions into a warranted path?

A path is not discovered merely by placing records in date order. It is reconstructed by showing that selected configurations and transitions were actually traversed by a bounded reference object, that their connection is constitutive for the tested claim, and that the analyst has disclosed the frame, selection rule, omissions, alternatives, uncertainty, and loss through which the path is represented.

This first work package establishes the definition, chronology boundary, component architecture, selection discipline, path frame, and evidence burden. It does not yet fully define realized, blocked, aborted, or deferred status, path comparison, similar-endpoint divergence, path without strong dependence, or the minimal path record. Those duties remain in Sections 10.7–10.14.

The local result of Sections 10.1–10.6 is therefore a controlled path candidate or warranted path claim, not a trajectory, path-dependence result, causal explanation, target function, or completed `COMPOSE` occurrence.

<a id="10-1-definition-of-path"></a>

### 10.1 Definition of Path

A **path** is the actually traversed, selectively reconstructed chain of relevant configurations and transitions within a declared frame.

```text
A path is the actually traversed, selectively reconstructed chain
of relevant configurations and transitions within a declared frame.
```

The definition contains four conjunctive burdens:

1. **actual traversal** — the source object or bounded reference relation passed through the selected configurations and transitions;
2. **selective reconstruction** — inclusion, compression, exclusion, and uncertainty are declared rather than hidden;
3. **constitutive connection** — the selected units form one claim-relevant chain rather than a merely adjacent list;
4. **declared frame** — reference, periodization, granularity, relative level, environment, and claim scope are bounded.

```text
actual traversal
+ selective reconstruction
+ constitutive connection
+ declared frame
→ path candidate
```

A path candidate becomes a warranted path only after its source, continuity, admissibility, loss, alternative, governance, and routing burdens are satisfied for the declared claim.

```text
path candidate
≠ warranted path
```

#### Definition ownership and operational use

Chapter 3 remains the primary Foundations definition site for the temporal object chain. Chapter 10 operationalizes the path threshold for Part I. It does not redefine configuration, transition, sequence, trajectory, or path dependence.

The path is an analytical object. It is not one of the three STRATA operations.

```text
path object
≠ COMPOSE occurrence
```

Several source structures may later be formed into a path composite by a declared `COMPOSE` occurrence. Chapter 15 owns that full procedure. Chapter 10 specifies what a path claim must carry even before, outside, or independently of an operation record.

A path also remains distinct from stronger or different claims:

```text
path
≠ trajectory automatically
≠ path dependence automatically
≠ causal mechanism automatically
≠ target function automatically
```

Historical extension does not grant functional or explanatory authority. A path may later serve as the source object of `PROJECT_AS`, but the contextual target function requires its own operation occurrence and continuity test.

#### Actual traversal

Actual traversal means that the selected chain corresponds to the realized historical passage of the bounded reference object or relation. The source record must support more than the plausibility that the chain could have occurred.

Traversal may be supported by direct records, by linked indirect evidence, or by a bounded inferential reconstruction. The evidence mode must remain visible. Retrospective narrative coherence cannot substitute for traversal support.

```text
plausible continuation
≠ actual traversal
```

```text
possible route through the materials
≠ route actually taken
```

Actual traversal is reference-relative. Different actors, institutions, rules, commitments, or material carriers may traverse different chains during the same calendar period. A path attributed to one reference object cannot be inherited by another merely because their records overlap.

#### Constitutive connection without causal inflation

The selected configurations and transitions must be connected for the tested praxis claim. This means that their relation changes the warranted reconstruction of action corridors, expectations, costs, bindings, asymmetries, alternatives, residue, or another declared praxis dimension.

It does not require a complete causal mechanism.

```text
constitutive path connection
≠ complete causal explanation
```

Nor does it imply necessity. A realized chain can be contingent, contested, interrupted, weakly constraining, or partly underdetermined.

#### C10-DEF-01 — short path with a non-realized continuation and open residue

Consider three configurations:

```text
K0 — review remains open and two procedural continuations are available
K1 — objection is recorded and reconsideration is promised
K2 — adoption proceeds after the realization window closes without reconsideration
```

Chapter 9 supplies two separately warranted transitions:

```text
T1: K0 → K1
T2: K1 → K2
```

The record also supports that the review object actually passed through `K0`, `K1`, and `K2`; that `T1` changed the expectation structure; and that `T2` changed the action corridor and left an unresolved commitment. One continuation—reconsideration before adoption—was source-supported as available at `K1` but was not realized. Its precise blocked/deferred status remains for Sections 10.8–10.10; WP1 records it only as a non-realized continuation with a supported availability relation and an unresolved status.

The bounded path is:

```text
K0
→ T1
→ K1
→ T2
→ K2
```

Its open residue includes the unresolved reconsideration commitment and uncertainty about later reopening. The result may be:

```text
admissible_with_bounded_claim
```

The result establishes neither a trajectory nor path dependence. The non-realized continuation is not upgraded to a blocked path before the status-specific burden is tested.

<a id="10-2-path-versus-chronology"></a>

### 10.2 Path versus Chronology

Chronology, sequence, transition set, and path record different degrees of structure.

A **chronology** places dated or relatively ordered items in temporal order.

A **sequence** preserves an ordered succession of declared objects or occurrences.

A **warranted transition set** contains individually supported relations between configurations.

A **path** adds actual traversal, selective reconstruction, constitutive connection, a declared frame, and disclosed loss and alternatives.

```text
chronology
≠ sequence
≠ warranted transition set
≠ path
```

The relation is not a simple ladder in which more entries automatically produce a stronger object. A chronology can be highly detailed and still remain below the path threshold. A short record can qualify as a path where traversal and constitutive connection are sufficiently supported.

#### Correct order is necessary but not sufficient

Chronological accuracy prevents one class of error. It does not show that the listed items belong to one path, that the same reference object traversed them, or that each item is constitutive for the tested claim.

```text
correct temporal order
≠ path membership automatically
```

A calendar may place a policy decision, a staffing change, a market event, and an internal objection in the correct order. Unless their relation to the bounded reference object and claim is reconstructed, the result remains a chronology.

#### Sequence and path

A sequence may preserve relevant order without demonstrating why the ordered units form a single path. The missing burden may concern:

- reference continuity;
- an unsupported transition;
- omitted intermediate configurations;
- an unmarked frame change;
- a missing selection rule;
- uncertain traversal;
- absence of praxeological purchase.

```text
ordered relation
≠ constitutive path relation automatically
```

This distinction prevents the analyst from treating documentary abundance or visual continuity as historical formation.

#### Transition set and path

Individually warranted transitions can still fail to form one path. Their reference objects may differ; their frames may be incompatible; a load-bearing interval may be absent; or the selected order may not represent actual traversal.

```text
warranted T1
+ warranted T2
≠ warranted path automatically
```

A path claim must therefore test the chain as a chain. It cannot borrow admissibility from its components without examining their handoffs.

#### C10-CHRON-01 — correct chronology below the path threshold

A record correctly orders:

```text
E1 — objection filed
E2 — leadership changed
E3 — revised rule published
E4 — adoption confirmed
```

The dates are secure. However, the sources do not establish whether the leadership change affected the review object, whether the revised rule governed this adoption, or whether the same procedural reference connects all four entries. No transition record links `E2` to the tested review claim.

The chronology remains valid:

```text
temporal order supported
```

The path claim requires:

```text
claim_reduction_required
```

If the analyst nevertheless uses the chronology to derive a trajectory or causal history, the continuation exceeds the available relation and may require `mandatory_stop`. The weaker chronological finding is preserved.

<a id="10-3-path-components"></a>

### 10.3 Path Components

A path may contain the following component roles:

```yaml
path_components:
  source_configuration:
  transitions:
  intermediate_configurations:
  event_clusters:
  non_event_structures:
  branch_points:
  selected_continuation:
  foreclosed_alternatives:
  current_endpoint_or_open_continuation:
```

The list identifies analytical roles, not a universal requirement that every path instantiate every role. Each included component must be relevant to the bounded path claim, and each absent role must not be silently presumed.

#### Source configuration

The source configuration is the bounded entry configuration for the path claim.

```text
path source
≠ origin of the whole history
```

A path can begin at a declared analytical boundary without claiming that nothing relevant preceded it. Earlier residue or inherited conditions must be disclosed where they affect the source configuration.

#### Transitions

Transitions connect configurations under the Chapter 9 burden. Path membership does not revalidate a failed or provisional transition.

```text
path membership
≠ transition revalidation
```

A path can include a provisional transition only if the path claim remains bounded by the same uncertainty and does not treat provisionality as settled fact.

#### Intermediate configurations

Intermediate configurations preserve load-bearing changes within the path. They prevent endpoint comparison from replacing historical reconstruction.

An intermediate configuration is required where its omission would materially alter:

- the identity of the reference object;
- the order or direction of the path;
- the availability of a continuation;
- the meaning of a later event or non-event;
- a frame handoff;
- the cost, asymmetry, binding, or residue attributed to the path.

Compression is permitted, but the compressed interval and its uncertainty must remain declared.

#### Event clusters and non-event structures

An event cluster groups related occurrences where the grouping preserves rather than hides the claim-relevant relations. A non-event structure records a warranted pattern of non-realization, delay, silence, or absent fulfillment under the Chapter 9 and later Chapter 14 burdens.

```text
event cluster
≠ undifferentiated event mass
```

```text
non-event structure
≠ empty interval
```

Grouping does not erase internal order, source differences, or contradictory occurrences where those differences are load-bearing.

#### Branch points, selected continuation, and alternatives

A branch point marks a configuration at which more than one continuation was source-supported as available, prepared, or contested. Chapter 13 owns the full ontology of branches and unrealized alternatives. Chapter 10 records only the minimum needed to prevent the realized continuation from appearing necessary.

```text
unrealized alternative
≠ imagined possibility
```

The selected continuation is the continuation actually traversed. A foreclosed alternative requires a supported relation showing that an earlier continuation became unavailable, prohibitively costly, institutionally blocked, or otherwise closed within the bounded frame.

#### Endpoint and open continuation

The endpoint is the final configuration included in the current path claim. It may be closed for the analytical interval while remaining historically open.

```text
path endpoint
≠ historical closure
```

An open continuation records that later development remains outside the present source or claim boundary. It is not evidence that every future continuation remains possible.

#### C10-COMP-01 — load-bearing intermediate configuration

Suppose an analyst compresses:

```text
K0 — review open
K1 — temporary reconsideration protocol adopted
K2 — protocol expires without use
K3 — adoption finalized
```

into:

```text
K0 → K3
```

`K1` is load-bearing because it changes the expectation structure and makes the later non-use at `K2` intelligible. Omitting it converts a specific non-realization into an unexplained gap and changes the basis of the path claim.

The responsible path preserves `K1` and `K2`, or explicitly compresses them while retaining their constitutive roles and loss declaration. The endpoint-only representation requires claim reduction.

<a id="10-4-path-selection"></a>

### 10.4 Path Selection

Every path is analytically selected. Selection is not a defect when it is explicit, source-bounded, claim-relevant, and reversible in the record. Hidden selection is a defect because it makes a constructed path appear self-given.

A Path Selection Declaration must state:

- the tested claim;
- the inclusion rule;
- the unit of selection;
- the reason each included configuration or transition is constitutive;
- what is compressed;
- what is excluded;
- which alternatives remain visible;
- what is uncertain or irrecoverable;
- how another responsible selection could differ.

#### Inclusion and exclusion

Inclusion requires more than relevance in a broad thematic sense. The included unit must contribute to the path claim through traversal, constitutive connection, frame definition, alternative structure, loss, or residue.

Exclusion is permissible where an item is incidental to the tested claim or belongs to a different frame. It becomes inadmissible where the excluded item would reverse, interrupt, rival, or materially qualify the selected path.

```text
selection
≠ permission to remove counterpressure
```

#### Compression

Compression reduces resolution while preserving the reference object and claim-relevant relation. It must identify the compressed interval or cluster and state what detail is no longer recoverable from the compact representation.

The canonical loss structure remains:

```yaml
loss:
  preserved:
  compressed:
  excluded:
  uncertain:
  irrecoverable:
```

```text
compact path
≠ lossless path
```

#### Retrospective reconstruction

Paths are often reconstructed after the endpoint is known. Endpoint knowledge can improve source access and reveal relations that were not legible earlier. It can also generate retrospective plausibilization, in which every earlier element is selected because it appears to lead to the known result.

```text
retrospective reconstruction
≠ retrospective inevitability
```

The analyst must therefore preserve contemporaneously open alternatives, failed initiatives, interruptions, and unresolved residue where supported.

#### Rival selections and claim lineage

Two selections from overlapping source materials may both be admissible if they answer different bounded questions or use different declared periodizations. They are separate testable claims.

```text
revised path construction
= new testable claim
```

A later preferred selection does not erase an earlier rejected or provisional construction. Claim lineage must preserve the prior selection rule, result, loss, and reason for revision.

#### C10-SEL-01 — two defensible selections from overlapping sources

The same source bundle supports two bounded reconstructions:

- **Selection A** follows the formal review object from objection through adoption;
- **Selection B** follows the resource commitment from budget reservation through cancellation.

The paths overlap at one meeting and one decision but have different reference objects, source boundaries, and constitutive transitions. Neither is the uniquely true complete history of the institution.

The responsible result is two separately declared path claims with their own inclusion, compression, exclusion, loss, and residue. Combining them without a new formation rule would create an undeclared composite and require claim reduction.

<a id="10-5-path-frame"></a>

### 10.5 Path Frame

A **path frame** declares the bounded conditions under which a chain is reconstructed as one path.

It includes at least:

- reference object;
- beginning and endpoint or open edge;
- relevant roles and institutions;
- included and excluded environments;
- temporal scope;
- source scope;
- granularity and relative level;
- comparison basis;
- admissible claim reach;
- periodization rationale.

```text
path boundary
≠ objective universal boundary
```

The frame does not create historical continuity by declaration. It controls which continuity relation must be demonstrated.

#### Beginning and endpoint

The beginning identifies the source configuration for the bounded claim. It may be analytically chosen, source-limited, or event-bounded. The record must disclose inherited structures that predate the boundary where they carry load into the path.

The endpoint may be a dated configuration, an open interval boundary, a source ceiling, or the present analytical cut. It does not imply finality.

#### Included and excluded environments

A path can be institutionally internal, cross-institutional, materially distributed, or actor-relative. The frame must state which environments are inside the path claim and which are context only.

An environmental change may be constitutive, permissive, constraining, or merely concurrent. Inclusion in the same calendar period does not settle its role.

#### Granularity and relative level

Path identity depends partly on the level and resolution at which the chain is reconstructed. A high-granularity path may preserve transitions that a coarse path compresses. Neither receives automatic truth priority.

```text
finer path reconstruction
≠ truer path automatically
```

A change of granularity or relative level creates a new comparison burden. It cannot rescue a failed path by making the missing relation invisible.

#### Periodization and path identity

Periodization selects the temporal boundary through which a path is represented. Different bounded periodizations may yield different path identities from overlapping history.

```text
same path label
≠ same path identity
```

Path identity requires continuity of reference, frame, constitutive transitions, selection rule, segment order, and declared status. Shared segments do not make two complete paths identical.

```text
shared history
≠ same complete path
```

#### Frame handoff

A path may cross a source-supported change of institutional, legal, technical, or analytical frame. The handoff must state:

1. source frame;
2. target frame;
3. the historical or analytical basis of the change;
4. the invariant or translation relation preserving reference;
5. resulting loss and uncertainty;
6. the claim scope that remains valid.

An unmarked frame change can create a false appearance of continuous path identity.

#### C10-FRAME-01 — unmarked periodization changes path identity

One reconstruction begins with the filing of an objection and ends at adoption. Another begins with an earlier budget commitment and ends at implementation. Both are labeled “the adoption path,” but they use different reference objects, inherited bindings, and endpoints.

Without explicit frames, the second path appears to prove that adoption was already fixed before the objection. With frames declared, the source supports two overlapping but non-identical path claims.

The unmarked unified claim remains `formal_diagnostic` until reference, periodization, and comparison basis are repaired. If no responsible handoff is available, the identity claim requires reduction or failure.

<a id="10-6-path-evidence"></a>

### 10.6 Path Evidence

Path evidence must support the chain as a chain. It is not sufficient to accumulate records about its endpoints or to count the number of dated items.

The WP1 evidence architecture distinguishes six relations:

| Relation | Control question |
| --- | --- |
| Component Support | Are the selected configurations, transitions, events, non-events, and branch notes reconstructible? |
| Traversal Support | Did the bounded reference object actually pass through the selected chain? |
| Constitutive Support | Why do the selected units form one claim-relevant path? |
| Selection Support | Why is material included, compressed, excluded, or retained as uncertainty? |
| Branch Support | Were non-realized continuations genuinely available, prepared, blocked, or merely imagined? |
| Praxis Support | What warranted reconstruction changes because the chain is treated as a path? |

```text
evidence quantity
≠ path admissibility
```

The relations are non-compensatory. Strong Component Support cannot repair missing Traversal Support. Direct dates cannot repair an unmarked frame change. High PraxisPurchase cannot replace Type Integrity or source continuity.

#### Direct and indirect traversal evidence

Direct traversal evidence may include contemporaneous logs, decisions, state records, version histories, transaction traces, or linked witness records that explicitly connect configurations.

Indirect traversal evidence may include mutually constraining documents, stable identifiers, consistent state changes, dependency records, or absence patterns whose relation is independently warranted. The inferential chain must be stated rather than concealed behind a definitive path diagram.

```text
indirect evidence
≠ weak evidence automatically
```

```text
inferential reconstruction
≠ direct observation
```

The claim ceiling must reflect the weakest load-bearing evidence relation, not the average richness of the source bundle.

#### Source gaps and uncertainty

A gap does not automatically defeat a path. The record must determine whether the missing material is incidental, compressible, load-bearing, or irrecoverable.

A gap is load-bearing where it prevents determination of:

- actual traversal;
- reference continuity;
- transition order;
- branch availability;
- frame handoff;
- constitutive connection;
- a claimed endpoint or status.

Known gaps remain declared. They cannot be rendered as empty intervals or as evidence that no rival continuation occurred.

#### Alternative sequence reconstructions

Where the sources permit more than one order or selection, each candidate must state its distinct support and loss. If the difference is immaterial to the tested claim, a bounded path may remain available. If the difference changes path identity or constitutive relation, the result may remain provisional, diagnostic, reduced, failed, or non-captured depending on the later full routing test.

#### C10-EVID-01 — indirect but traceable traversal evidence

No single document records the complete passage from `K0` through `K1` to `K2`. The source bundle contains:

- a version identifier linking the objection record to the revised draft;
- a dated access log showing the revised draft entered the adoption workflow;
- a later decision record carrying the same identifier;
- an unresolved gap concerning one internal review step.

The chain is inferential but traceable. The gap does not alter reference continuity or the supported order, but it limits any claim about the internal mechanism of review.

The bounded path may therefore receive:

```text
admissible_but_provisional
```

The record must preserve the inferential bridge, the missing review step, and the re-entry evidence that could strengthen or defeat the claim. It may not present the path as directly observed or use it to infer intention, trajectory, or path dependence.

#### WP1 completion boundary

Sections 10.1–10.6 establish:

- the path as an actually traversed, selectively reconstructed, constitutively connected chain within a declared frame;
- the candidate/warranted distinction;
- the separation of path object from `COMPOSE`, trajectory, path dependence, causality, and target function;
- the chronology/sequence/transition-set/path threshold;
- component roles and load-bearing omission control;
- selection, compression, loss, rival construction, and claim-lineage duties;
- path-frame, periodization, identity, granularity, and frame-handoff control;
- a six-relation evidence matrix with direct, indirect, gap, and rival-reconstruction handling;
- six canonical pressure cases from `C10-DEF-01` through `C10-EVID-01`.

The WP1 result is bounded. It does not yet settle the distinct burdens of realized, blocked, aborted, and deferred paths. It also does not perform path comparison, establish path dependence, supply a trajectory, or complete the Shared Transformation Record.

```text
WP1 path threshold established
≠ Chapter 10 provisional lock
```

The next controlled production step is:

```text

Realized, Blocked, Aborted,
and Deferred Paths
```

<a id="10-7-realized-path"></a>

### 10.7 Realized Path

A **realized path** is a path whose declared chain was actually traversed by the bounded reference object through the stated analytical cut.

The adjective *realized* does not add a second traversal burden to the path definition in Section 10.1. It makes the status explicit when the realized chain must be distinguished from a blocked, aborted, or deferred continuation.

```text
realized path
= warranted path through the declared cut
```

It does not mean:

```text
realized
≠ necessary
≠ rational
≠ intended
≠ successful
≠ complete
≠ closed
```

A path may be realized even where the actors did not plan the full chain, where the result was contested, where the endpoint remains open, or where an available continuation was not realized. Realization states what was traversed, not why it occurred or whether it should have occurred.

#### Qualified status is segment- and cut-relative

Path status is not a timeless label attached to an entire history. It is declared for a bounded segment, continuation, or analytical cut.

The same record may responsibly state:

```text
K0 → T1 → K1 → T2 → K2
= realized through K2

K2 → possible K3
= continuation status separately tested
```

This permits a realized prefix and a blocked, aborted, deferred, unresolved, or later realized continuation to coexist without contradiction. The statuses answer different questions about different portions of the path.

```text
realized prefix
≠ realized continuation automatically
```

```text
qualified path status
≠ global essence of the path
```

Every status declaration must therefore identify:

- the bounded reference object;
- the segment or continuation to which the status applies;
- the temporal cut at which status is assessed;
- the source basis;
- the relevant event, non-event, delay, or condition;
- status-specific uncertainty and residue;
- the claim ceiling.



#### Status vectors and divided reference objects

A single institutional episode may contain different statuses for different bounded reference objects. The formal decision may be realized, the review route blocked, the resource commitment aborted, and a technical implementation deferred during the same calendar interval.

```text
same calendar interval
≠ same status for every reference object
```

The analyst must not compress these relations into one global label such as “the process was blocked.” The status declaration must state what was realized, what continuation is tested, whose or which reference relation it concerns, and at which cut.

A useful local representation is a non-aggregated status vector:

```yaml
status_vector:
  decision_object: realized
  reconsideration_continuation: blocked_candidate
  implementation_segment: deferred_candidate
  resource_route: aborted_candidate
```

This is a conceptual aid, not a new Record field or formal enum. The entries remain separate claims with separate evidence burdens and may receive different later routing results.

```text
multiple local statuses
≠ one compensatory status score
```

Nor does one strongly supported status repair another weakly supported status. A well-documented realized decision cannot compensate for missing evidence that an alternative route was available; a clear cessation cannot compensate for missing initiation evidence.

#### Status at event time and status at reconstruction time

Status must also preserve the difference between what was historically the case at the tested cut and what became knowable later. A later-discovered document may warrant revising a former unresolved continuation to blocked or deferred. The later evidence changes the responsible reconstruction; it does not move the historical block or postponement to the evidence-discovery date.

```text
status-event time
≠ status-evidence time
≠ status-revision time
```

The claim lineage should preserve the earlier diagnostic or provisional record, the later source, and the reason for revision. New evidence supports a new testable status claim rather than silently rewriting production history.

#### Open endpoints

A realized path can end at an open analytical boundary. The last supported configuration may be current, source-limited, or selected because later material falls outside the claim scope.

```text
realized through K2
≠ historically finished at K2
```

The endpoint record must distinguish:

- **closed endpoint claim** — the sources support termination of the bounded object or relation;
- **open continuation** — further development remains possible or currently unresolved;
- **source ceiling** — later continuation may exist but is outside available materials;
- **analytical cut** — later material exists but is excluded by the declared frame.

A source ceiling cannot be rewritten as historical closure. An analytical cut cannot be rewritten as a claim that nothing followed.

#### Realization and alternatives

A realized path may preserve non-realized alternatives where their availability is source-supported. The realized chain does not make every alternative equally possible, nor does the survival of an alternative invalidate the realized path.

```text
realized continuation
≠ only possible continuation
```

```text
non-realized alternative
≠ blocked continuation automatically
```

The later status of an alternative depends on whether it remained available, was prevented, was initiated and ceased, was postponed, or was merely conceivable.

#### C10-REAL-01 — realized continuation with an open endpoint

A review object traverses:

```text
K0 — objection open
K1 — reconsideration promised
K2 — adoption completed without reconsideration
```

The two transitions and the passage of the reference object through all three configurations are supported. At the analytical cut, a reopening procedure remains legally possible, but no source establishes whether it will be used.

The bounded path is realized through `K2`. Its endpoint remains open with respect to later reopening.

```text
realized through K2
+ open continuation after K2
```

The result may be:

```text
admissible_with_bounded_claim
```

It does not establish necessity, closure, success, trajectory, path dependence, or a prediction about reopening.

<a id="10-8-blocked-path"></a>

### 10.8 Blocked Path and Blocked Continuation

A **blocked continuation** is a source-supported continuation that was genuinely available or structurally prepared and whose further realization was prevented by an identifiable blocking condition.

Because an untraversed continuation is not itself a realized path, the more precise Chapter-10 form is normally:

```text
realized path prefix
+ blocked continuation
```

The shorthand **blocked path** is admissible only when the record makes that internal structure explicit. It must not suggest that the untraversed continuation was actually realized.

```text
blocked continuation
≠ realized continuation
```

```text
blocked path shorthand
≠ exception to actual traversal
```

#### Blocking burden

A blocked-continuation claim requires conjunctive support for:

1. a bounded realized prefix or prepared starting configuration;
2. a specific continuation object or transition;
3. prior availability, authorization, preparation, or accessible capacity;
4. an identifiable blocking condition;
5. temporal placement of the block before or during attempted continuation;
6. a source-supported relation between the condition and non-realization;
7. resulting effects on alternatives, costs, bindings, asymmetries, or residue;
8. uncertainty, rivals, and claim ceiling.

```text
prior availability
+ identifiable blocking condition
+ supported prevention relation
→ blocked-continuation candidate
```

Completeness of these declarations does not by itself prove substantive blockage. The source relation remains independently testable.

#### Availability is stronger than conceivability

A continuation is not available merely because the analyst can imagine it. Availability may be supported by:

- an authorized option;
- an open procedural route;
- committed resources;
- a prepared draft or implementation state;
- a contemporaneous actor plan with execution capacity;
- a branch already entered but not completed;
- a conditionally accessible continuation whose conditions were then obstructed.

```text
conceivable alternative
≠ available continuation
```

```text
retrospective preference
≠ prior availability
```

Availability is also time-indexed. A route available at `t1` may already be closed at `t2`; a later reference to it does not restore prior accessibility.

#### Blocking condition versus mere non-selection

A continuation can remain unrealized because it was not selected, because actors abandoned it, because it was postponed, because no decision occurred, or because a condition prevented it. Only the last relation supports blocked status.

```text
non-selection
≠ blockage
```

```text
non-realization
≠ prevention automatically
```

The blocking condition may be formal, material, temporal, institutional, informational, or relational. It need not be intentional. A benefit received from the blockage does not prove that an actor caused or intended it.

```text
benefit from block
≠ authorship of block
≠ intention to block
```



#### Blocking location and partial traversal

A blocking condition can operate at different positions relative to the proposed continuation:

- **pre-entry block** — the continuation was available or prepared, but entry was prevented;
- **in-course block** — traversal began, but a condition prevented the next constitutive step;
- **completion block** — most steps occurred, but the bounded completion criterion could not be met.

These positions matter because an in-course or completion block may also satisfy the initiation burden of an aborted segment. The analyst must identify the tested claim rather than force one exclusive label over the whole record.

```text
blocked next step
+ initiated earlier segment
→ blocked-continuation claim may coexist with aborted-segment claim
```

The claims are not duplicates. One concerns prevention of further realization; the other concerns cessation of a segment already entered. Their reference segment, evidence relation, and residue may differ.

#### Nominal and effective availability

Formal availability is not always effective availability. A route may remain legally listed while required resources, access, jurisdiction, information, or time have already disappeared. Conversely, a route may lack a polished formal label while a source-supported institutional capacity remains accessible.

The record should therefore distinguish:

```text
nominal availability
≠ effective availability automatically
```

A blocked claim cannot be supported merely by pointing to a formal option if the source shows that the option was already inaccessible before the alleged block. Likewise, the analyst should not deny availability merely because the route was informal where actual access and preparation are documented.

#### Actor-relative blockage

The same condition may block one actor or institutional unit while leaving another continuation open. An access rule may prevent external appeal but leave internal reconsideration available. Resource withdrawal may block one implementation team while permitting another carrier to proceed.

```text
blocked for reference A
≠ blocked for reference B automatically
```

This actor- or carrier-relative structure must not be converted into a universal claim that “the path was blocked.” The frame must retain the relevant access, capacity, and authority relation without using STRATA to decide legitimacy or fault.

#### Blocked status and causality

A blocked-continuation claim is stronger than a statement that the route did not occur, but narrower than a complete causal explanation. It identifies a bounded prevention relation under the available sources.

```text
supported blocking relation
≠ complete causal mechanism
```

Where multiple conditions jointly carry the prevention claim, their roles must remain separated. A necessary condition, enabling background, triggering event, and actor decision are not interchangeable.

#### Block removal and later resumption

A later removal of the blocking condition may permit resumption. It does not erase the earlier blocked interval.

```text
later resumption
≠ retroactive non-blockage
```

Nor does resumption automatically restore uninterrupted path identity. The record must test whether reference, frame, commitments, costs, alternatives, and constitutive transitions remain continuous.

```text
resumed continuation
≠ uninterrupted continuation
```

A later realized continuation is a new status claim at a later cut. The prior blocked claim remains in lineage if it was warranted at the earlier cut.

#### C10-BLOCK-01 — genuinely available continuation prevented

At `K1`, a reconsideration procedure is authorized, scheduled, and supported by a prepared review file. Before the scheduled review, a rule change removes the responsible body’s jurisdiction. The file remains intact, but the authorized route cannot proceed under the new rule.

The record supports:

- prior availability and preparation;
- a specific continuation;
- an identifiable rule change;
- temporal precedence of the rule change;
- supported prevention of the scheduled route;
- residual commitment and increased reopening cost.

The responsible form is:

```text
realized path through K1
+ blocked reconsideration continuation
```

The bounded blocked-continuation claim may receive:

```text
admissible_with_bounded_claim
```

The result does not establish intention, inevitability, permanent impossibility, or a complete causal history.

#### C10-BLOCK-02 — imagined possibility mislabeled as blocked

After adoption, an analyst proposes that the institution *could have* created an external review panel. No contemporaneous rule, proposal, resource commitment, actor plan, or accessible procedure supports that route.

The possibility may be retained as an analytical or normative suggestion outside the path claim. It cannot be registered as a blocked continuation.

```text
imagined possibility
→ bounded alternative note at most

blocked status
→ failed
```

If the path history is rewritten around this imagined branch, the status claim requires `claim_reduction_required` or `failed_transformation`, depending on its scope and use. If the invented block is then used to infer trajectory, path dependence, blame, or authority, later routing may require `mandatory_stop`.

<a id="10-9-aborted-path"></a>

### 10.9 Aborted Path

An **aborted path** is a path segment or continuation that was initiated, authorized, committed, or partially traversed and then ceased before its bounded continuation criterion was met.

```text
initiation or partial traversal
+ cessation before continuation criterion
→ aborted-path candidate
```

The abortion claim requires more than the existence of an unused option. Something must have begun in a source-supported sense.

```text
aborted
≠ never begun
≠ merely unselected
≠ blocked before initiation automatically
```

#### Initiation burden

Initiation may be shown by:

- formal authorization followed by execution steps;
- allocation of resources to the route;
- entry into the first constitutive transition;
- partial implementation;
- actor commitment coupled to observable action;
- a material or technical state that begins the continuation.

A declaration of interest without commitment or action may remain below the initiation threshold. The required threshold depends on the object and frame; Chapter 10 introduces no universal initiation score.

#### Cessation and abortion point

The record must identify the best-supported abortion point or bounded abortion interval. Exact dating may remain uncertain where relative order is sufficient.

Cessation may result from withdrawal, failure, revocation, loss of capacity, changed frame, internal contradiction, or another source-supported condition. The status claim does not automatically assign cause, fault, or intention.

```text
cessation point
≠ complete causal explanation
```

A path may contain multiple initiated segments, only one of which is aborted. The status must attach to the relevant segment rather than globalize across the whole history.



#### Abortion of a segment versus abortion of the complete path

A path may contain one aborted segment while another continuation remains realized or available. The cessation of a review route does not necessarily terminate the decision path; cancellation of one implementation method does not prove that the implementation object ceased.

```text
aborted segment
≠ aborted complete path automatically
```

The scope of the abortion claim must match the continuity criterion that failed. Where the reference object changes carriers or continuation type, the record must decide whether the old segment ended and a new related path began, or whether one path continued through an explicit handoff. Neither conclusion follows from the shared label alone.

#### Voluntary and involuntary cessation

Aborted status does not encode motive or voluntariness. Withdrawal by an actor, expiry of capacity, formal revocation, material failure, or unresolved internal contradiction may all coincide with cessation. The status claim states that the initiated route ceased before the bounded continuation criterion; it does not by itself classify the cessation as chosen, imposed, negligent, strategic, or legitimate.

```text
aborted status
≠ motive classification
≠ responsibility verdict
```

Where motive matters for a later claim, it requires separate source support and remains outside automatic STRATA inference.

#### Degree of partial realization

The amount of work completed before cessation may affect residue and later reopening cost, but it does not create a universal abortion threshold. A route can be aborted after one constitutive step or near completion. The record must identify which steps were actually traversed and which continuation criterion remained unmet.

```text
more partial completion
≠ stronger abortion truth automatically
```

Additional completion may instead change the appropriate reference object: an implementation may be realized while a later review is aborted. Claim segmentation remains prior to status routing.

#### Residue of abortion

Abortion does not imply reset. Initiated action may leave:

- sunk costs;
- altered expectations;
- partial infrastructure;
- documentary or reputational residue;
- changed access or asymmetry;
- unresolved commitments;
- narrowed or newly opened alternatives;
- learned procedural capacity.

```text
aborted continuation
≠ no historical effect
```

```text
cessation
≠ restoration of source configuration
```

The residue may later become relevant to another path or trajectory claim, but that later use requires a separate test. Abortion itself does not establish sedimentation or dependence.

#### Restart, resumption, and identity

A later attempt can reuse the same label, resources, or objective. It is not automatically the uninterrupted continuation of the aborted path.

```text
restart
≠ uninterrupted continuation
```

The record must test:

- continuity of reference object;
- preserved versus replaced commitments;
- changed actors, rules, or technical carriers;
- retained residue;
- new initiation event;
- selection and loss across the interruption;
- whether one path with an interruption or two related paths is the better bounded claim.

Neither representation receives automatic priority. Each is a separately testable construction.

#### C10-ABORT-01 — initiated route ceased with residue

A review body authorizes an appeal route, assigns staff, opens a case file, and completes an initial hearing. Funding is then withdrawn and the route ceases before decision.

This is not a blocked-before-initiation route: constitutive traversal occurred. It is not mere non-selection: the continuation was entered. The record supports an aborted continuation after the initial hearing.

Residue includes the case file, sunk staff time, changed claimant expectations, and a later higher cost of reopening. The result may be:

```text
admissible_with_bounded_claim
```

The claim does not establish that funding withdrawal was the sole cause, that the route could never resume, or that the residue already constitutes a trajectory.

<a id="10-10-deferred-path"></a>

### 10.10 Deferred Path and Deferred Continuation

A **deferred continuation** is a source-supported continuation whose realization is postponed while some bounded form of availability, authorization, preparation, or commitment remains operative at the relevant analytical cut.

The preferred structure is:

```text
realized path prefix
+ deferred continuation
```

The shorthand **deferred path** is admissible only where the record keeps the realized prefix, postponed continuation, and current availability relation separate.

```text
deferred continuation
≠ uninterrupted continuation
```

```text
deferral
≠ permanent non-realization
```

#### Deferral burden

A deferred-continuation claim requires:

1. a specific continuation;
2. prior availability, authorization, preparation, or commitment;
3. a source-supported postponement relation;
4. no supported termination or blocking condition at the declared cut;
5. the form and degree of continued availability;
6. delay effects on costs, expectations, bindings, frames, asymmetries, or identity;
7. uncertainty, review condition, and claim ceiling.

```text
continued bounded availability
+ supported postponement
→ deferred-continuation candidate
```

The claim remains time-indexed. Availability at one cut does not guarantee availability at a later cut.

#### Deferral versus delay as transition structure

Chapter 9 defined delay as a temporal relation that may alter costs, expectations, bindings, asymmetries, or alternatives. Deferred continuation is a path-status claim built on a more specific relation: a particular continuation remains boundedly available while realization is postponed.

```text
delay as transition structure
≠ deferred continuation automatically
```

Delay may exist where no continuation remains available. Deferral requires both postponement and continuing availability or commitment.

#### Deferral versus framed non-event

A promised action may be both deferred and, under a different claim, a framed non-event at a missed realization condition. The two claims must remain separate.

```text
missed promised date
→ possible framed non-event claim

continuation still available after postponement
→ possible deferred-continuation claim
```

Neither claim substitutes for the other. A missed date does not prove that the route remains available; continued availability does not erase the non-realization at the promised date.

#### Temporal load and changing identity

Deferral is not neutral waiting. During the interval:

- costs may accumulate;
- actors or institutions may change;
- authority or jurisdiction may shift;
- resources may expire;
- expectations may weaken or harden;
- alternatives may close;
- the continuation may require a new initiation event;
- the later route may no longer preserve the same path identity.

```text
same named continuation after delay
≠ same path identity automatically
```

The record should state a review condition for continued deferral. Once availability is no longer supported, the status must be re-tested as blocked, aborted, failed, unresolved, or permanently non-realized under the appropriate claim.



#### Continued availability can decay

Deferral requires more than a nominal statement that the route remains “on hold.” The source should support the relevant form of continued availability at the declared cut. That support may weaken over time as resources expire, jurisdiction changes, actors leave, technical dependencies become obsolete, or prerequisite information loses validity.

```text
availability at t1
≠ availability at t2 automatically
```

The record should therefore state what would trigger status review, such as:

- expiry of authorization;
- loss of a required carrier;
- closure of an action window;
- a blocking rule or resource condition;
- withdrawal of the initiating commitment;
- a new event that restarts or replaces the route.

Without review conditions, “deferred” can become an indefinite label that protects a weak claim from failure.

#### Nominal deferral versus inactive residue

An institution may continue to call a route postponed even though no responsible body, resource, schedule, or operative commitment remains. Such a label is not sufficient evidence of continued availability.

```text
nominally pending
≠ effectively deferred automatically
```

Where only documentary residue remains, the responsible result may be an unresolved or failed deferral claim while the historical commitment and its residue are preserved. Conversely, the absence of a fixed date does not defeat deferral if operative capacity, authorization, and an explicit postponement relation remain supported.

#### Multiple clocks of deferral

The same continuation may be deferred under one clock and effectively blocked under another. A legal authorization may remain open while a budget window closes; a technical route may remain possible while an actor-specific access period expires.

The record must separate the clocks relevant to the claim:

```text
legal availability time
≠ resource availability time
≠ actor access time
≠ analytical review time
```

A global deferred label is inadmissible where one load-bearing clock has already terminated the relevant continuation. The analyst may preserve partial or actor-relative availability, but must reduce the status scope accordingly.

#### Deferral and repeated postponement

Repeated postponement does not automatically prove stronger deferral, blockage, bad faith, or trajectory. It may increase temporal load, weaken availability, or alter path identity. Each repetition must be assessed for what changed in the continuation relation.

```text
repeated postponement
≠ unchanged deferred status automatically
```

A series of deferrals can eventually require a new claim because the later continuation no longer preserves the same carrier, frame, cost structure, or initiation relation.

#### Status transition without erasure

A continuation can move through statuses over time:

```text
deferred at t1
→ blocked at t2
→ newly realized after repair at t3
```

These are not contradictory if each is bounded by its temporal cut and evidence. Later status does not erase earlier status.

```text
later realization
≠ retroactive uninterrupted realization
```

A later continuation may preserve lineage while requiring a new Path Identity test.

#### C10-DEFER-01 — continued availability with changing load

A reconsideration route is authorized and rescheduled twice. The file remains active, the responsible body retains jurisdiction, and no blocking or termination event is supported. During the delay, one supporting actor leaves, documentation requirements increase, and the cost of reopening rises.

At the declared cut, the continuation remains available but postponed. The responsible form is:

```text
realized path through current review state
+ deferred reconsideration continuation
```

The result may be:

```text
admissible_with_bounded_claim
```

The record must preserve the increased cost, actor change, uncertainty, and review condition. It may not describe the continuation as uninterrupted, guarantee later realization, or assume unchanged path identity.

#### WP2 status matrix

| Status | Minimum historical relation | What remains prohibited |
| --- | --- | --- |
| realized | actual traversal through the declared cut | necessity, success, closure, or intention |
| blocked continuation | prior availability/preparation plus supported prevention | imagined branch, mere non-selection, complete causality |
| aborted path | initiation or partial traversal plus cessation | never-started option, reset, automatic dependence |
| deferred continuation | postponement plus continued bounded availability | uninterrupted identity, guaranteed realization, permanent non-event |

The matrix is non-compensatory. Rich evidence for the realized prefix does not prove the status of the continuation. A strong blocking condition does not prove prior availability. Clear postponement does not prove continued availability. Documented cessation does not prove initiation.

```text
status declaration completeness
≠ status truth automatically
```

#### WP2 completion boundary

Sections 10.7–10.10 establish a qualified path-status architecture without creating four ontologically distinct path kinds. The statuses are bounded historical relations attached to segments, continuations, and analytical cuts.

```text
path status
≠ new PMS operator
≠ new STRATA operation
≠ canonical Output Class
```

WP2 does not authorize a path-status enum, a new schema field, a status score, or an automatic status detector.

WP2 does not yet settle Path Comparison, Similar Endpoints, Path without Strong Dependence, the Minimal Path Record, Stop and Non-Capture integration, or the Chapter-11 handoff. Those duties remain in Sections 10.11–10.14 and WP4.
