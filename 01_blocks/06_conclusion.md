## Chapter 55 — What PMS-STRATA Provides

<a id="55-1-explicit-vertical-transformation-discipline"></a>

### 55.1 Explicit Vertical Transformation Discipline

#### C55-VERTICALDISCIPLINE-01 — PMS-STRATA makes vertical analytical movement explicit, typed, and inspectable

PMS-STRATA provides a controlled discipline for moving among temporal structures, granular reconstructions, composite objects, relative levels, and contextual functions. Its first positive provision is not a new object ontology but an explicit account of analytical movement that would otherwise remain implicit.

A valid vertical movement declares at least:

- the source reference object;
- the source and target frames;
- source and target granularities;
- the relevant relative level;
- the temporal scope;
- the selected operation occurrence;
- the expected praxeological difference;
- the claim before and after transformation;
- the five-field Loss profile;
- the Claim and Authority Ceilings.

```text
unmarked level change
→ analytically opaque movement

declared source, coordinates, operation, Loss, and claim
→ inspectable transformation occurrence
```

This provision replaces intuitive movement with a recordable claim. It does not guarantee that the movement is admissible, empirically correct, or necessary. It makes the movement available for audit.

#### C55-CAPABILITYBOUNDARY-01 — Every positive capability remains bounded by source, coordinates, context, claim, Loss, and authority

No capability listed in this chapter is freestanding. Each remains conditional on:

```text
Source Support
+ declared Frame
+ declared Granularity
+ declared Context
+ bounded Claim
+ disclosed Loss
+ prohibited Authority Inheritance
```

A capability statement therefore means that STRATA supplies a method for making a certain kind of reconstruction explicit and testable. It does not mean that every attempted reconstruction will pass, that every object can be captured, or that a successful structural result authorizes application.

<a id="55-2-controlled-temporal-composition"></a>

### 55.2 Controlled Temporal Composition

#### C55-TEMPORALCOMPOSITION-01 — PATH and COMPOSE provide controlled temporal composition without collapsing sequence, path, trajectory, and path dependence

PATH supplies the temporal method Part, and `COMPOSE` supplies the operation by which many or sequential source structures may form a new composite analytical object. Their positive provision is a disciplined way to construct temporal objects while preserving distinctions among:

```text
sequence
path
trajectory
path dependence
```

A sequence records ordered occurrences. A path requires a claim-bearing route through alternatives or transitions. A trajectory adds bounded continuity, development, or directed historical structure. Path dependence requires a stronger claim about how prior states constrain later possibilities. None follows automatically from the previous term.

Controlled temporal composition requires disclosure of:

- selected occurrences and ordering;
- branches, alternatives, events, and Non-Events;
- constitutive relations;
- periodization and temporal scope;
- composite identity;
- excluded or uncertain elements;
- the claim produced by the composition.

The positive capability is therefore not automatic macro-generation. It is the ability to construct a bounded temporal composite while preserving the evidence and distinctions required to challenge it.

<a id="55-3-granularity-controlled-decomposition"></a>

### 55.3 Granularity-Controlled Decomposition

#### C55-DECOMPOSITION-01 — SUB and DECOMPOSE open compressed occurrences and composites without claiming final constituents or truth priority for finer resolution

SUB supplies the granularity method Part, and `DECOMPOSE` supplies the operation by which a compressed occurrence or composite is opened into a finer reconstruction of the same reference object.

The method provides:

- explicit source and target granularity;
- a preservation criterion for the same reference object;
- component and relation reconstruction;
- a return path to the coarser source function;
- a test of whether the finer distinction adds praxeological purchase;
- explicit Loss and uncertainty at the finer resolution.

```text
finer resolution
≠ final constituent
≠ deeper truth automatically
≠ greater relevance automatically
```

A decomposition is useful where the finer distinctions alter the bounded claim or reveal a load-bearing relation. It may also return `resolution_neutral`, require Claim Reduction, stop, fail, or yield `non_capture` after adequate bounded attempts. The capability consists in controlling the opening, not in privileging depth.


The origin type remains visible. The target function is contextual, derived, and claim-bound. It is not a new PMS primitive and does not overwrite the source object.

Examples already established in the corpus include a trajectory functioning as a frame element, macro-event, attractor-like form, or distributed profile. Chapter 55 adds no new example or promise. It records that STRATA provides a typed procedure for such claims and a method for rejecting projection where source trace, context, sensitivity, or TypeIntegrity fails.

### 55.5 Operator-Occurrence Discipline

#### C55-OCCURRENCEDISCIPLINE-01 — STRATA preserves the distinctions among operator type, occurrence, composite, derived object, and contextual function

STRATA provides a disciplined grammar for keeping apart:

```text
operator type

```

The Δ–Ψ inventory belongs to PMS Base. STRATA may analyze concrete occurrences and source-supported relations involving those operators. This distinction prevents two recurrent errors: treating a shared operator label as proof of occurrence identity, and treating a useful derived function as if it changed the origin type.

### 55.6 Explicit Loss Accounting

#### C55-LOSSACCOUNTING-01 — Every transformation carries the exact five-field Loss account

STRATA provides a shared Loss vocabulary:

```yaml

  preserved:
  compressed:
  excluded:
  uncertain:
  irrecoverable:
```

The account makes selection and reduction inspectable across operations and handoffs. It can disclose inherited, newly introduced, uncertain, and irrecoverable limits. It can also reveal Compression Debt or Hidden Loss without adding a sixth field.

The capability is explicit accounting, not losslessness. A large but transparent Loss may support a narrow claim; a small hidden exclusion may defeat a strong one.

A successful STRATA representation does not establish PMS superiority. Rival openness is a positive methodological capability because it prevents closure by translation alone.

### 55.8 Counterfactual Load Testing

#### C55-COUNTERFACTUALTESTING-01 — Counterfactual Sensitivity tests declared source dependence without proving causation

The closed vocabulary remains:

```text

insensitive
```

```text
counterfactual load test
≠ causal proof
≠ empirical alternate-history proof
```

A highly sensitive result does not by itself identify a causal mechanism. An insensitive result does not automatically establish robustness. An untestable result does not immunize the claim.

### 55.12 Stop and Non-Capture

A bounded method may therefore produce no further transformation. That result can be scientifically stronger than a forced positive representation.

## Chapter 56 — What PMS-STRATA Does Not Provide

Chapter 55 stated the positive capabilities of PMS-STRATA. This chapter fixes their negative ceilings. The two inventories are symmetrical but not interchangeable:

```text
positive capability
+ explicit negative ceiling
→ bounded method scope
```

A negative ceiling is not an optional disclaimer appended after the method has done its real work. It is part of the method's admissibility conditions. Nor does a limit become an opposite metaphysical thesis. To state that STRATA does not establish final constituents is not to prove that final constituents cannot exist. To state that it does not guarantee full capture is not to claim that every object is uncapturable.

```text
negative boundary
≠ optional disclaimer

method limit
≠ method defect

no guarantee
≠ impossibility claim
```

<a id="56-1-no-new-pms-base"></a>

### 56.1 No New PMS Base

#### C56-NONEWBASE-01 — STRATA does not add, rename, reorder, decompose, or revise Δ–Ψ

PMS-STRATA remains subordinate to the unchanged PMS Base. Its three transformation operations may work with source-supported operator occurrences, composites, relations, temporal structures, and contextual functions. They do not modify the operator grammar that makes those structures typable.

STRATA therefore does not:

- add an operator beyond Δ–Ψ;
- rename an existing operator;
- change the order or dependency relations of Δ–Ψ;
- revise an `operator_layer`;
- split an operator type into supposedly deeper operator types;
- promote a composite, profile, derived object, or target function into a PMS primitive.

```text
operator occurrence analysis
≠ operator type revision

new derived object or function
≠ new PMS primitive
```

A source-supported reconstruction may show that a concrete occurrence was misidentified, that several occurrences were conflated, or that an earlier occurrence-level relation was too broad. Such a correction changes the reconstruction claim. It does not change PMS Base.

<a id="56-2-no-superior-pms-layer"></a>

### 56.2 No Superior PMS Layer

#### C56-NOSUPERIORLAYER-01 — STRATA is not positioned above PMS Base and cannot validate it from a higher authority

The four-Part architecture supplies explicit transformation discipline. It does not create a superior theoretical layer from which PMS Base is judged, completed, or authorized.

```text
PMS Base
→ unchanged typing and dependency foundation

PMS-STRATA
→ bounded transformation method

more explicit method
≠ higher theory authority
```

The integrated model of Chapter 54 may make relations among PATH, SUB, RETYPE, and LIMITS easier to inspect. Increased internal legibility may expose contradictions or unsupported claims. Neither result establishes that STRATA stands above PMS or that PMS is true because STRATA can formalize it.

A technically consistent model can reveal formal consistency. It cannot confer ontological, empirical, semantic, normative, or application authority on the basis it represents.

<a id="56-3-no-ontology-of-reality"></a>

### 56.3 No Ontology of Reality

#### C56-NOONTOLOGY-01 — Frames, granularities, and relative levels are reconstructive relations, not objective strata of reality

PMS-STRATA does not claim that reality is intrinsically divided into micro, meso, macro, or any other discrete level system. A level is declared relative to a reference object, question, frame, granularity, temporal scope, and claim.

```text
analytical level
≠ ontological layer

stable reconstruction at level L
≠ reality objectively partitioned at L
```

The same reference object may support more than one legitimate reconstruction. A coarse reconstruction may preserve a praxis-relevant relation that a finer one obscures. A finer reconstruction may expose an asymmetry that a coarse representation compresses. These results concern bounded reconstruction performance, not the metaphysical architecture of the world.

Chapter 42 already established the anti-ontology boundary. Chapter 56 restates it as a terminal exclusion: no successful transformation, integrated model, executable implementation, or repeated case passage may convert reconstructive coordinates into objective strata.

### 56.4 No Final Constituents

`DECOMPOSE` opens a compressed occurrence or composite into a finer reconstruction of the same reference object. Its result remains conditioned by:

```text
finer reconstruction
```

The absence of a further admissible decomposition does not prove that no finer structure exists. It may instead mark a Source Ceiling, Relevance Floor, Traceability Ceiling, Calibration limit, Mandatory Stop, or current Non-Capture.

Competing composites may each preserve different load-bearing structures. STRATA does not require them to be merged into one final representation. A forced totality can itself destroy calibration, heterogeneity, or TraceableLoad.

```text
functional resemblance
```

<a id="56-10-no-unlimited-recursive-method"></a>

### 56.10 No Unlimited Recursive Method

#### C56-NOUNLIMITEDRECURSION-01 — Further transformability creates no obligation to continue

An object can often be decomposed further, recomposed differently, or projected into another context. Analytical possibility is not analytical necessity.

```text
further operation available
≠ further operation required
```

STRATA preserves:

- Optional Stop where continuation remains admissible but adds no needed result;
- `mandatory_stop` where continuation would violate a load-bearing boundary;
- Claim Reduction where a stronger claim cannot be retained;
- Non-Capture where adequate bounded attempts fail to preserve the capture object.

Recursion must stop where relevance ends, sources are exceeded, TraceableLoad disappears, calibration collapses, TypeIntegrity fails, or continuation primarily rescues a challenged claim.

```text
no universal threshold
```

Local thresholds must be declared and justified relative to sources, frame, granularity, temporal scope, comparison class, and claim. Where several thresholds remain source-supported and materially alter classification, Calibration Openness or Calibration Non-Capture may remain appropriate.

<a id="56-12-no-causal-proof"></a>

### 56.12 No Causal Proof

#### C56-NOCAUSALPROOF-01 — Transformation and Counterfactual Sensitivity do not prove causal necessity, universality, prediction, or law

STRATA reconstructs structural relations and tests whether a bounded claim depends on declared source features. This can identify a load-bearing relation within a reconstruction. It does not by itself identify a causal mechanism or establish an empirical alternate history.

```text
strongly_sensitive
≠ causal proof

reconstructed sequence
≠ causal necessity

recurrent pattern
```

### 57.4 The Transformation Rule

#### C57-TRANSFORMATIONRULE-01 — A bounded STRATA transformation must satisfy the exact ten-condition rule

A STRATA operation is legitimate only if it:

1. **identifies its source object;**
2. **declares its frame, granularity, and relative level;**
3. **specifies `COMPOSE`, `DECOMPOSE`, or `PROJECT_AS`;**
4. **states the expected praxeological difference;**
5. **remains traceable to its constitutive source structures;**
6. **preserves reference and type integrity;**
7. **discloses selection and Loss;**
8. **permits counterfactual failure;**
9. **defines its validity scope;**
10. **preserves Stop and Non-Capture.**

The rule is conjunctive and non-compensatory. It is not a score, weighted checklist, majority test, or presumption of passage.

```text
nine conditions passed
+ one load-bearing condition failed
≠ legitimate by majority
```

The ten conditions do not replace the full twelve-stage audit. They state the terminal compact boundary that the detailed audit makes inspectable.

#### C57-OPERATIONINVENTORY-01 — The terminal rule preserves exactly three operations and no fourth operation

```text
many or sequential source structures
→ COMPOSE
→ new composite analytical object

compressed occurrence or composite
→ DECOMPOSE
→ finer reconstruction of the same reference object

origin-typed source object
→ PROJECT_AS
→ bounded contextual target function
```

`COMPOSE` does not automatically generate a target function. `DECOMPOSE` opens occurrences and composites, never abstract operator types. `PROJECT_AS` preserves the origin type and does not create a new primitive. Operation chains retain one record per occurrence and one testable handoff claim per transition.

Within the present STRATA grammar, every admitted transformation must therefore be typed as `COMPOSE`, `DECOMPOSE`, `PROJECT_AS`, or a finite declared chain of their occurrences. This closes the operative vocabulary of the method; it does not prove that every conceivable PMS-relevant transformation is representable by that vocabulary.

```text

≠ proved representational completeness
```

- source identity and source scope;
