## 3. Contract Lock

### 3.1 Governing question

> How can vertical analytical movement be classified as composition, decomposition, or functional projection so that each movement carries its own source, target, preservation, loss, and failure conditions?

### 3.2 Required claims

Chapter 4 must establish:

1. STRATA has exactly three core operations: `COMPOSE`, `DECOMPOSE`, and `PROJECT_AS`;
2. one operation occurrence has exactly one operation identity, although separately declared occurrences may form a chain;
3. `COMPOSE` forms a new composite analytical object from multiple or sequential source objects and must declare ordering, selection, constitutive relations, preservation, compression, and loss;
4. `DECOMPOSE` reconstructs the finer relational structure of a provisionally compressed occurrence or composite while retaining that source object as reference and test target;
5. `PROJECT_AS` preserves source reference and origin type while assigning a bounded target function in a declared target context;
6. every operation has a distinct source signature, target relation, preservation duty, loss profile, confusion boundary, and failure condition;
7. operations may chain only through separate declarations and independently testable claims;
8. the three canonical non-invertibility statements express transformed information and relation, not merely a generic inability to undo an action;
9. a minimal operation declaration is conceptual prose mapped to the existing Shared Transformation Record paths, not a second schema.

### 3.3 Required distinctions

| Distinction | Required Chapter 4 burden |
| --- | --- |
| operation identity vs. direction metaphor | classify by source–target relation and preservation burden, not by “up,” “down,” “wider,” or “finer” |
| source object vs. target object | state whether a new composite object is formed or the same reference object is reconstructed |
| target object vs. target function | distinguish object formation from contextual function assignment |
| composition vs. aggregation or chronology | require constitutive relation, selection rule, praxeological gain, and loss account |
| decomposition vs. description or added detail | require a provisionally compressed occurrence/composite, same reference object, relational reconstruction, and source-function test |
| decomposition vs. new PATH construction | a different selection and formation relation requires a new `COMPOSE` occurrence |
| projection vs. recontextualization | frame change alone does not establish a bounded source-dependent target function |
| projection vs. analogy or renaming | resemblance or a rhetorically apt label does not establish functional continuity |
| operation chain vs. collapsed multi-operation claim | every link needs a separate occurrence identity, source/target relation, loss, and result |
| non-invertibility vs. simple reversibility failure | explain why selection, compression, visibility, function, and context prevent identity recovery |

### 3.4 Prohibited claims

Chapter 4 must not claim that:

- a fourth implicit operation exists;
- comparison, translation, recontextualization, calibration, or validation is a hidden fourth operation;
- chronology is sufficient for `COMPOSE`;
- any finer description is `DECOMPOSE`;

## 4. Three-Operation Closure

### 4.1 Closure claim

Chapter 4 will justify the exact operation inventory **within STRATA’s declared transformation grammar**, not as an ontological proof that all possible analytical activity in reality consists of three movements.

The closure is relational:

```text
many or sequential source structures
→ new composite analytical object
= COMPOSE
```

```text
provisionally compressed occurrence or composite
→ finer relational reconstruction of the same reference object
= DECOMPOSE
```

```text
origin-typed source object
→ bounded contextual target function
= PROJECT_AS
```

A proposed fourth candidate must therefore be tested against the following possibilities:

1. it is only a coordinate change;
2. it is a comparison, audit, validation, or declaration act rather than a transformation operation;
3. it is an occurrence or chain of the three existing operations;
4. it is a local procedure inside one operation;
5. it is an output, failure, Stop, or Non-Capture condition;
6. it is a label, analogy, recontextualization, or type jump;
7. it exposes genuine non-capture or PMS Base revision pressure rather than a hidden STRATA operation.

```text
three-operation closure
≠ ontological totality
≠ immunity from future non-capture
```

### 4.2 Mutual exclusivity at occurrence level

For one declared occurrence:

```text
exactly one operation kind
```

An occurrence cannot simultaneously be `COMPOSE` and `DECOMPOSE`, or `DECOMPOSE` and `PROJECT_AS`, merely because a description includes several movements. Where more than one signature is required, the analysis must create a chain of separate occurrence records.

### 4.3 Chainability without a compound fourth type

```text
operation chain
= ordered sequence of separately declared operation occurrences
```

The chain is not itself a fourth operation. It may carry emergent chain-level loss or conflict, but each link retains its own identity and result.

## 5. Core Signature Architecture

### 5.1 COMPOSE preparation card

**Canonical relation**

```text
many or sequential source structures
→ new composite analytical object
```

**Minimum source burden**

- at least two source structures or one declared sequential source family;
- typed source objects and bounded reference relation;
- declared frame, granularity, relative level, temporal scope, source scope, and claim scope where relevant;
- ordering rule where temporal or sequential structure matters;
- selection rule and constitutive relation.

**Target identity**

- a new composite analytical object;
- not a target function merely because the composite is later useful elsewhere;
- not an exhaustive totality of its sources.

**Preservation duty**

- source references remain traceable;
- ordering and constitutive relations remain reconstructible at the declared claim level;
- relevant heterogeneity and non-events are not erased;
- the composite’s identity burden is declared.

**Characteristic loss**

- compression;
- excluded details or branches;
- reduced visibility of alternatives;
- uncertain or irrecoverable source relations.

**Central confusions**

```text
chronology
≠ COMPOSE

aggregation
≠ COMPOSE

summary
≠ COMPOSE automatically
```

**Central failure**

No warranted composite relation or praxeological gain is established, or the selection/loss destroys the relation needed to identify the proposed target object.

### 5.2 DECOMPOSE preparation card

**Canonical relation**

```text
provisionally compressed occurrence or composite
→ finer relational reconstruction of the same reference object
```

**Minimum source burden**

- an identifiable compressed occurrence or composite;
- a stated finer target granularity;
- a stable reference object;
- traceable source material capable of supporting the added distinctions.

**Target identity**

- the same relevant reference object reconstructed more finely;
- not a newly selected competing path or composite;
- not a decomposition of an abstract operator type.

**Preservation duty**

- source reference remains recoverable;
- constitutive component relations remain connected to the source object;
- the coarser source function is reconstructed, revised, bounded, or explicitly lost;
- new detail creates discriminative praxeological gain or a valid resolution-neutral result.

**Characteristic loss**

- uncertainty in recovering compressed components;
- irrecoverable source compression;
- altered visibility and selection under finer reconstruction;
- possible revision of the coarser source-function claim.

**Central confusions**

```text
added detail
≠ DECOMPOSE

description
≠ DECOMPOSE

atomization
≠ relational decomposition

new path formation
≠ opening the same path
```

**Central failure**

The proposed target no longer reconstructs the same source object, component relations cannot be traced, or finer detail adds no warranted analytical difference and instead produces resolution drift or escape.

### 5.3 PROJECT_AS preparation card

**Canonical relation**

```text
origin-typed source object
→ bounded contextual target function
```

**Minimum source burden**

- a typed source object and preserved source reference;
- a declared target context and validity scope;
- a bounded target function;
- constitutive source trace sufficient to support that function;
- explicit alternatives, including analogy-only or no projection.

**Target identity**

- a contextual target function, not a replacement origin type;
- a derived, bounded relation rather than a new PMS primitive;
- a function that may cease outside the declared context.

**Preservation duty**

- origin type remains unchanged;
- source reference and constitutive source trace remain visible;
- the target function remains contextually bounded and counterfactually sensitive to material source changes.

**Characteristic loss**

- foregrounding and backgrounding under the target context;
- compression of source complexity into a bounded function;
- excluded alternative functions;
- validity loss outside target scope.

**Central confusions**

```text
recontextualization
≠ PROJECT_AS

analogy
≠ PROJECT_AS

renaming
≠ PROJECT_AS

origin-type replacement
≠ PROJECT_AS
```

**Central failure**

The claimed target function is source-indifferent, unbounded, merely analogous, produced by label substitution, or requires replacement of the origin type.

```text

primarily changes contextual function
```

These are tendencies, not identities.

```text

≠ COMPOSE

relative downwardness
≠ DECOMPOSE

≠ PROJECT_AS
```

No direction is ontological. Operation direction, coordinate relation, claim direction, and authority direction remain distinct.

### 7.2 Coordinate stability and change

Any operation may involve stable or changed frame, granularity, relative level, temporal scope, source scope, or claim scope. The operation is identified by its source–target and preservation relation, not by the mere fact of coordinate change.

### 7.3 Stop against vertical metaphor

Where an analyst can state only “upward,” “deeper,” “higher,” “zoomed in,” or “reframed” without satisfying one signature, operation identity remains unsupported. The claim must be reduced or stopped.

### 8.1 Required chain architecture

Every link requires:

- a unique occurrence identity;
- exactly one operation kind;
- a source object or function available at that link;
- a target object or function produced or tested at that link;
- an independent justification and expected praxeological difference;


```text

≠ rescue of earlier failed link
```

A failed link may require Claim Reduction, Mandatory Stop, Failed Transformation, or Non-Capture while other chain links retain their separately warranted results.

## 9. Non-Invertibility

### 9.1 Canonical statements

```text
DECOMPOSE(COMPOSE(X))
≠ X
```

```text
COMPOSE(DECOMPOSE(X))
≠ X
```

```text
PROJECT_AS(X)
≠ X as a new origin type
```

### 9.2 Required interpretation

The first statement means that composition has selected, ordered, compressed, foregrounded, and possibly made source detail irrecoverable. A later decomposition reconstructs from the composed object and available sources; it does not restore the untouched pre-composition source family.

The second means that a finer reconstruction changes the available distinctions, evidence, and selection possibilities. A later composition therefore creates a new composite occurrence under a new selection and formation rule.

The third means that contextual function does not become origin-type identity. Reversing or removing the projection does not reveal a newly retyped source object because no origin-type replacement was admissible in the first place.

```text
non-invertibility
≠ permission to ignore preservation
≠ proof of total loss
≠ automatic irreversibility claim
```
