## 1. Preparation Status and Scope

This record prepares Chapter 23 as the primary SUB site for decomposing event-like objects, Non-Event structures, and the internal temporal order through which they are produced, delayed, completed, repeated, blocked, or left unresolved. The chapter does not redefine Event, Non-Event, Transition, Sequence, Path, or Trajectory. It applies the generic Chapter-20 `DECOMPOSE` procedure to source objects whose categorical identity depends on temporal organization.

The governing question is:

> How can an apparently punctual, extended, clustered, delayed, or absent temporal structure be opened under finer resolution without inflating events, dissolving Non-Events, inventing intention, or confusing missing information with structured non-occurrence?

The bounded Chapter-23 architecture is:

```text
warranted event-like or Non-Event source object
+
declared source category and boundary
+
source-supported internal phases, sub-events, delays, roles, thresholds, and temporal relations
+
preservation or warranted revision of the source category
→
temporal DECOMPOSE candidate
```

Chapter 23 must reject two symmetrical reductions:

```text
more timestamps or micro-changes
→ event inflation

positive internal events identified
→ Non-Event erased
```

The first replaces praxeological relevance with observation density. The second confuses the positive processes through which a Non-Event is produced or maintained with the expected structure that still failed to occur. A committee may meet, circulate documents, postpone, reassign responsibility, request information, and close an agenda item while the expected decision remains unrealized. The positive sub-events are real. Their reality does not by itself cancel the higher-level `Λ` claim.

This Preparation Gate produces no canonical §23 prose, standalone Case, Transformation Record, Smoke Record, appendix expansion, schema extension, new operation, new Output Class, new Rule, new audit stage, temporal ontology, intention model, person type, or authority mechanism.

## 3. Contract Lock

### 3.1 Required core claim

Chapter 23 must establish:

> Events and Non-Events may contain internal phases, decisions, delays, roles, blockages, thresholds, and positive sub-events, but a valid decomposition must preserve or explicitly revise the categorical and temporal relations that make the source the same Event or Non-Event.

The source category is not immune to finer evidence. An apparently single Event may be better reconstructed as an Event Cluster. An alleged Non-Event may fail if no warranted expectation frame exists. An alleged Extended Event may fragment into several independent events if no supported completion relation binds its phases. Category preservation is therefore a test, not a required verdict.

### 3.2 Event rule

An Event-like source object requires a bounded, praxis-relevant change within a declared Frame. Decomposition may reconstruct:

- preparation;
- activation;
- partial decisions;
- role handoffs;
- parallel actions;
- delays;
- threshold crossings;
- closure conditions;
- aftermath necessary to determine completion.

The source Event must remain identifiable through these phases or be explicitly revised. A timestamp, document edit, utterance fragment, or minimal state difference is not an Event component merely because it can be isolated.

### 3.3 Non-Event rule

A Non-Event source requires:

- an expected structure;
- a warranted expectation Frame;
- an expected temporal window or completion condition;
- documented non-realization;
- a praxeological difference produced by the non-realization;
- sufficient sources to distinguish non-occurrence from missing information.

Decomposition may identify positive sub-events such as meetings, deferrals, requests, reassignment, procedural checks, or communications. The source remains a Non-Event where those positive structures jointly produce, maintain, or fail to overcome the higher-level non-realization.

### 3.4 Temporal floor rule

Finer temporal resolution is warranted only where an added distinction changes a supported reconstruction of:

- event boundary;
- internal phase;
- causal or functional sequence claim within the allowed Claim Ceiling;
- role access or responsibility capacity;
- delay or threshold structure;
- completion condition;
- expectation support;
- categorical preservation;
- Source-Function Effect;
- Loss or uncertainty.

If smaller timestamps merely multiply observation points while no new transition or praxis difference becomes visible, the analysis falls below the Praxeological Relevance Floor as temporal granularity drift.

## 5. Temporal Source Entry

### 5.1 Source-object threshold

A Chapter-23 source must be independently identifiable before the present operation begins. The minimum entry declaration is:

```yaml
temporal_source_entry:
  reference_object: bounded review decision occurrence R-23
  source_category: Non-Event
  source_frame: formal review process
  source_granularity: one recorded non-decision
  temporal_scope: opening of decision window through expiry
  expected_structure: binding decision
  expectation_basis: agenda commitment, role mandate, and stated deadline
  current_coarse_function: leave the review issue unresolved while preserving procedural continuation
  known_internal_structure:
    - two deferrals
    - responsibility reassignment
    - information request
  unresolved_internal_structure:
    - relation among deferral, reassignment, and expiry
  decomposition_reason: determine whether the non-decision is one structured Non-Event and where further temporal detail ceases to add purchase
```

For an Event source, `expected_structure` may be absent or used only where completion expectation is part of the Event boundary. For a Non-Event source, expectation support is mandatory.

### 5.2 Source category is a claim

The source category must be stated before component selection:

```text
Event
Extended Event
Event Cluster
Non-Event
Delay Structure
Repeated Non-Decision
```

These labels do not form a closed ontology or model enum. They are bounded analytical claims under Chapter-23 ownership. Finer evidence may preserve, refine, split, cluster, or reject the initial category.

### 5.3 Event boundary

The Event boundary must declare:

- what marks the beginning;
- what marks the completion or endpoint;
- which phases belong to the same Event;
- which preceding conditions are context rather than Event components;
- which aftermath is necessary to determine completion;
- which boundary alternatives remain plausible.

The event boundary is relational and claim-dependent. It is not fixed by the smallest timestamp or by the analyst's preferred narrative.

### 5.4 Non-Event boundary

The Non-Event boundary must declare:

- the expected structure;
- the Frame that makes it expected;
- the expected window or completion condition;
- the point at which non-realization becomes praxeologically relevant;
- the continuation or closure of the non-realization;
- whether later realization changes but does not erase the earlier Non-Event.

A delayed later decision may recontextualize the earlier non-decision. It does not retroactively make the earlier expected-window failure nonexistent.

## 6. Event Decomposition

### 6.1 Apparently punctual Event

An apparently punctual Event may compress a temporally extended formation. Candidate internal structures include:

- preparatory selection;
- authorization;
- trigger;
- role transfer;
- parallel enactment;
- threshold crossing;
- public or formal registration;
- closure;
- stabilization of the changed configuration.

The decomposition question is not how many detectable changes occurred. It is which temporally and relationally supported distinctions alter the warranted reconstruction of the Event.

### 6.2 Extended Event

An Extended Event is one bounded event-like object whose identity depends on multiple phases across a non-trivial interval. Chapter 23 must test:

- phase relation;
- continuity of reference;
- beginning marker;
- completion marker;
- interruption or suspension;
- return or continuation;
- role changes;
- partial realization;
- conditions under which the Event should instead be split.

Duration alone does not establish one Extended Event. Several related activities may still constitute an Event Cluster or a sequence of independent events.

### 6.3 Event Cluster

An Event Cluster is a group of local events treated at a coarser granularity as one event-complex because a supported relation binds them under the same bounded claim. Relations may include:

- coordinated formation;
- shared completion condition;
- common decision object;
- mutual dependence;
- parallel contribution to one transition;
- common threshold or closure.

If the cluster is newly formed from separate source events during analysis, a prior or separate `COMPOSE` claim may be required. Chapter 23 may determine that a coarse single-Event label should be revised to Event Cluster; it may not silently perform an unrecorded formation operation.

### 6.4 Event Inflation

Event Inflation occurs where observation density substitutes for event relevance. Warning signs include:

- every utterance, click, document edit, pause, or clock tick is treated as a separate Event;
- no event-unit criterion is stated;
- the same practical change is multiplied across several recording systems;
- internal phases are reified as independent events without changed claim load;
- temporal resolution destroys the action unit;
- finer distinctions cannot affect source-function testing or Loss.

The local stop rule is:

> Do not introduce another Event distinction unless it changes a warranted reconstruction of transition, role, threshold, completion, expectation, cost, alternative, source function, or Loss.

This stop rule prepares but does not replace Chapter 25's complete resolution taxonomy.

## 7. Non-Event Decomposition

### 7.1 Positive processes can produce non-realization

A Non-Event may be internally active. It can contain:

- meetings that do not reach a binding decision;
- repeated requests for further information;
- role transfers that leave responsibility unresolved;
- procedural checks that repeatedly reset the decision window;
- communications that preserve ambiguity;
- resource allocation that remains below the required threshold;
- local decisions that do not realize the expected higher-level structure.

The decomposition must state how these positive structures relate to the same expected non-realization.

### 7.2 Categorical preservation test

The Non-Event character is preserved where:

1. the expected structure remains clearly identified;
2. the expectation Frame remains warranted;
3. the relevant expected window or completion condition remains bounded;
4. the expected structure did not occur within that boundary;
5. the positive sub-events help produce, stabilize, defer, fragment, or fail to overcome the non-realization;
6. the non-realization produces a supported praxeological difference.

If expectation support fails, the `Λ` claim must be reduced or rejected. Positive sub-events cannot compensate for an unsupported expectation.

### 7.3 Source absence versus Non-Event

Missing records can support uncertainty, Source Ceiling, or Non-Capture. They do not themselves support a Non-Event. The following remain distinct:

```text
no record of a decision
≠ decision did not occur

record gap
≠ expected decision failed

unknown intermediate phase
≠ delay automatically
```

A Non-Event claim requires positive support for the expectation and for the relevant non-realization, not merely absence of contrary evidence.

## 8. Delay and Repeated Non-Decision

### 8.1 Delay Structure

A delay structure may contain:

- repeated postponements;
- queueing or backlog;
- changing responsibility;
- information bottlenecks;
- resource unavailability;
- unresolved jurisdiction;
- strategic waiting where supported;
- missing decision capacity;
- external dependency;
- threshold conditions not yet met.

The decomposition must distinguish the structural mechanism from attributed intention.

### 8.2 Delay does not prove obstruction

Delay may be intentional, emergent, distributed, accidental, capacity-bound, rule-bound, or underdetermined. Chapter 23 may describe supported waiting practices or strategic timing. It may not infer motive from duration alone.

```text
delay
≠ intentional obstruction automatically
≠ guilt
≠ person property
```

### 8.3 Repeated Non-Decision

A repeated non-decision may include:

- deferred votes;
- failed quorum;
- recurring reframing of the issue;
- reassignment among roles or committees;
- requests that reopen information collection;
- temporary closure without binding resolution;
- repeated expiry of decision windows;
- absence of a binding `Ψ` occurrence.

The analysis must determine whether the repetitions belong to one continuing Non-Event, several Non-Events, an Event Cluster, or a PATH object. Repetition alone does not settle the object category.

### 8.4 Binding boundary

The absence of a binding decision can be relevant without becoming a claim about the character, maturity, responsibility, or moral quality of any person. Chapter 23 reconstructs whether a structurally required commitment or closure occurrence emerged under the declared Frame. It does not diagnose reluctance, indecision, avoidance, or intention as person properties.

## 9. Internal Temporal Order

### 9.1 Relational order

Chapter 23 must represent internal time relationally, not merely through a timestamp list. Relevant relations include:

- precondition before activation;
- partial order;
- overlap;
- concurrency;
- interruption;
- delay;
- repetition;
- threshold crossing;
- closure;
- reopening;
- irreversibility of a partial transition.

A timestamp is evidence for placement. It is not by itself an explanation of the relation.

### 9.2 Multiple clocks

One source object may contain:

- formal deadline time;
- interaction time;
- institutional processing time;
- information-availability time;
- responsibility-transfer time;
- practical consequence time.

These clocks may diverge. Chapter 23 may reconstruct their relation where sources support it. It must not collapse them into one universal event time or use one well-documented clock to compensate for missing evidence about another.

### 9.3 Overlap and parallelism

Positive sub-events may overlap rather than form a simple line. The temporal map may therefore require:

- partial order;
- parallel branches;
- synchronized thresholds;
- independent delays;
- convergence at a completion condition.

If the analysis forms a Path or Trajectory from these relations, Chapter 24 or PATH ownership must be respected. Chapter 23 remains focused on the internal temporal organization of the same bounded source Event or Non-Event.

## 11. Failure, Mandatory Stop, and Non-Capture

### 11.1 Failed temporal decomposition

Failure pressure includes:

- no independently identifiable temporal source object;
- event-unit multiplication without praxeological purchase;
- source Event disappearing into unrelated micro-changes;
- positive sub-events erasing the expected Non-Event by category mistake;
- unsupported expectation Frame;
- record absence treated as non-occurrence;
- delay treated as intention;
- invented phases, thresholds, order, or closure;
- silent formation of a new Event Cluster through `COMPOSE`;
- silent Path or Trajectory construction;
- target-function assignment through unmarked `PROJECT_AS`;
- person, guilt, legitimacy, sanction, or authority inference.

A failed Chapter-23 operation does not invalidate Event or Non-Event as PMS analytical object families. It rejects or reduces the bounded transformation claim.

### 11.2 Mandatory Stop

Mandatory Stop applies where continuation would require:

- invented expectation support;
- invented positive sub-events or temporal relations;
- treating inaccessible records as proof of non-occurrence;
- selecting an event boundary beyond the Source Ceiling;
- converting delay into motive or blame;
- preserving a source label after reference or category continuity is lost;
- hiding a required `COMPOSE`, PATH, or `PROJECT_AS` operation;
- changing PMS operator identities or dependencies;
- person typing, legitimacy determination, sanction, irreversible label, or authority transfer;
- further timestamp multiplication below the Relevance Floor.

Optional Stop remains available where the coarse source claim is sufficient and additional temporal detail would not alter any warranted reconstruction.

### 11.3 Non-Capture

`non_capture` remains possible where the source question is legitimate but no stable finer temporal map can be responsibly selected. Typical conditions include:

- rival event boundaries remain equally supported;
- expectation support is partial but not sufficient for a Non-Event verdict;
- positive sub-events are documented but their relation to the non-realization remains unclear;
- internal order is underdetermined;
- several clocks cannot be aligned;
- any available decomposition would destroy source identity.

Non-Capture does not:

- confirm the coarse Event or Non-Event claim;
- make all rival temporal maps equally true;
- authorize invented compromise order;
- protect an unsupported expectation;
- turn source absence into `Λ`.

### 11.4 Non-compensation

```text
many timestamps
+ complete phase table
+ valid YAML
+ coherent narrative
≠ admissible temporal decomposition
```

Formal completeness cannot compensate for missing expectation support, reference continuity, category integrity, praxeological purchase, or traceable temporal relations.
