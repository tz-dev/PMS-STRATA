## 1. Role, Status, and Authority

This index consolidates the non-equivalences required to preserve the object, coordinate, temporal, operation, type, function, admissibility, output, and authority distinctions of PMS-STRATA before production of the corpus Blocks.

It is a reference and audit artifact. It does not define Δ–Ψ, create a fourth STRATA operation, replace Chapters 0–8, decide empirical truth, or establish application authority. Primary definitions remain at the designated chapter or PMS Base location. The index records where an identity collapse is prohibited and where a declared relation may nevertheless remain admissible.

The governing rule is:

```text
A non-equivalence does not prohibit comparison,
relation, analogy, or transformation.

It prohibits unmarked identity,
category collapse, and authority transfer.
```

The symbol `≠` is therefore an audit constraint. It is not an empirical negation operator, a proof of semantic incomparability, or a universal prohibition on relation.

## 2. Meaning and Limits of Non-Equivalence

### 2.1 What a non-equivalence blocks

- unmarked identity between distinct object or claim categories;
- silent replacement of source type by contextual function;
- collapse of frame, granularity, relative level, and scope;
- promotion of a derived object, profile, or function into a PMS primitive;
- transfer of evidential, normative, practical, or application authority;
- retroactive erasure of failure through another transformation;
- substitution of analogy, chronology, description, or labeling for a declared operation.

### 2.2 What a non-equivalence does not block

- comparison between distinct terms;
- a declared relation between distinct objects;
- an admissible `COMPOSE`, `DECOMPOSE`, or `PROJECT_AS`;
- bounded analogy explicitly classified as `analogy_only`;
- co-valid descriptions at different granularities;
- a later new claim, provided the earlier result remains recorded;
- revision of an occurrence typing without changing the PMS operator type.

### 2.3 Non-equivalence and direction

The identity denial is logically symmetric: if `A ≠ B`, then `B ≠ A`. Audit explanations can nevertheless be direction-sensitive because the characteristic error may be a promotion, reduction, replacement, or authority transfer from one side to the other. This index stores each unordered pair once and explains the most relevant collapse direction.

### 2.4 Non-equivalence and evidence

A non-equivalence can flag that an argument crosses a category boundary. It cannot by itself establish that a source object exists, that a causal mechanism is real, that one typing is empirically correct, or that an action is warranted.

### 4.1 `finer granularity` ≠ `higher truth`

- **Registry status:** foundational canonical
- **Controlled variants:** finer resolution ≠ higher truth; additional detail ≠ additional warrant
- **Collapse blocked:** Treats increased distinction density as an automatic increase in truth, warrant, or explanatory rank.
- **Invalid identity claim:** This reconstruction is finer; therefore it is truer or more authoritative.
- **Admissible relation or transformation:** A finer reconstruction may outperform a coarser one for a declared claim when it adds source-supported praxeological discrimination.
- **Primary definition sites:** Chapter 2; Chapter 8; Chapters 25, 43, and 44

### 4.2 `relative level` ≠ `ontological layer`

- **Registry status:** foundational canonical
- **Controlled variants:** analytical position ≠ real stratum; higher composite ≠ higher being

- **Invalid identity claim:** The target is at a higher relative level; therefore it belongs to a higher ontological layer.
- **Admissible relation or transformation:** Relative levels may be declared for a specific source–target relation without claiming a universal hierarchy.

### 6.1 Coordinate declaration rule

Whenever a transformation changes more than one coordinate, each change must be separately declared. For example, a new target context may coexist with stable granularity, and a finer granularity may coexist with the same frame and reference object. No coordinate inherits truth, rank, or authority from another.

## 14. Identity-Collapse and Authority-Transfer Audit

For any strong equivalence-like statement, apply the following sequence:

1. **Identify both terms.** Are they object classes, coordinates, operator types, occurrences, functions, operations, claims, methodological concepts, or output values?
2. **Locate primary definitions.** Does each term point to a distinct primary site?
3. **Test identity language.** Does the statement use `is`, `becomes`, `therefore`, or inherited fields to erase the distinction?
4. **Test direction.** Is a source being promoted, reduced, replaced, or retyped without an operation?
5. **Test relation availability.** Would comparison, analogy, composition, decomposition, or projection be the correct declared relation instead?
6. **Test source load.** Does the relation remain sensitive to relevant source changes?
7. **Test scope.** Is a local result being generalized across frames, levels, periods, persons, or domains?
8. **Test authority.** Is truth, causality, legitimacy, diagnosis, recommendation, or application mandate being inherited?
9. **Test output vocabulary.** Has a local result or method concept been turned into a new output class?
10. **Record the result.** Preserve the invalid identity claim, the admissible relation if any, and the required claim effect.

### 14.1 Typical audit effects

| Detected collapse | Minimum effect |
| --- | --- |
| Terminological identity where only relation is supported | Rewrite as comparison or bounded relation. |
| Unmarked operation substitution | Classify and declare COMPOSE, DECOMPOSE, or PROJECT_AS. |
| Origin-type replacement | Restore origin type and bound the target function. |
| Analogy presented as projection | Reduce to `analogy_only` unless projection duties are satisfied. |
| Chronology presented as path | Reduce the claim or supply transition and selection structure. |
| Finer detail presented as higher truth | Apply Relevance Floor, source, and claim checks. |
| Derived function presented as primitive | Remove primitive status and restore reference handoff. |
| Formal validity presented as truth or authority | Apply claim and authority ceiling; prohibit inheritance. |
| Prior failure erased by a new transformation | Restore the earlier result and test the new claim separately. |

## 15. Anti-Immunization and Transformation-Change Rules

The governing anti-immunization rule is:

```text
A change of granularity, level, composition, frame,
or target function constitutes a new testable claim.

It does not erase the failure of the claim
from which the transformation began.
```

Therefore:

- a finer DECOMPOSE does not automatically answer an objection to the coarse claim;
- a higher COMPOSE does not automatically neutralize a local counterexample;
- PROJECT_AS elsewhere does not rescue a failed origin-type claim here;
- recontextualization does not remove historical consequences;
- Non-Capture does not make the attempted claim immune;
- translation into PMS language does not prove PMS superiority or completeness.

| warranted transition set ≠ path | individually valid transitions treated as one path automatically | transitions may be selected and connected under an additional path burden |
| plausible route ≠ traversed route | retrospective coherence treated as realization | indirect traversal may be supported where inferential steps remain traceable |
| path component list ≠ path | inventory treated as connected path | components may support a path candidate after selection and relation testing |
| path selection ≠ cherry-picking | disclosure treated as permission to hide counterevidence | bounded selection under relevance, loss, and alternatives duties |
| path frame ≠ objective universal boundary | analyst periodization treated as natural history | rival bounded frames may be separately tested |
| path endpoint ≠ historical closure | end of reconstruction treated as final process end | endpoint may remain open or source-limited |
| realized path ≠ retrospective plausibilization | endpoint knowledge makes prior chain inevitable | bounded reconstruction with alternatives and uncertainty visible |
| blocked continuation ≠ imagined alternative | conceivable option treated as formerly available and blocked | source-supported availability plus blocking condition |
| aborted path ≠ blocked-before-initiation | cessation after initiation collapsed with prevention before start | separately warranted aborted or blocked status |
| deferred continuation ≠ uninterrupted continuation | postponement erased from path identity | resumed route may remain linked while delay load stays visible |
| same endpoint ≠ same path | endpoint identity erases costs, bindings, residue, and alternatives | controlled path comparison |
| path ≠ trajectory | traversal treated as sedimented historical development | path may become trajectory only under Chapter-11 burdens |
| path ≠ strong path dependence | reconstructible history treated as strong present constraint | path may remain valid with weak dependence |
| minimal path record ≠ admissibility | complete fields treated as path proof | record may remain diagnostic, reduced, failed, or non-captured |
| path object formation burden ≠ completed `COMPOSE` procedure | local path construction treated as full operation passage | Chapter 15 may later test a separate operation occurrence |
