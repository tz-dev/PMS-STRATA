## 5. Core Conceptual Architecture

### 5.1 Functional projection

A functional projection adds one bounded source-to-context relation. It does not rewrite the source record.

```text
source object X of origin type T
+
declared target context C
+
source-traceable contextual relation
→
bounded target function F
```

The source object remains what it was in its origin reconstruction. Projection adds a claim about what it does within C.

### 5.2 Origin-Type Preservation

Origin-Type Preservation requires the source type to remain visible before, during, and after the projection claim.

```text
Trajectory X functions as a frame in C
≠
Trajectory X becomes Frame operator □
```

Preservation does not immunize a faulty origin-type claim. If later source evidence defeats the source typing, the projection must be re-tested against the revised source claim. A target function cannot rescue a failed origin reconstruction.

### 5.3 Target function

A target function is a relational, context-bound, claim-limited performance of the retained source object. Candidate function vocabulary may include frame-function, attractor-function, asymmetry-function, binding-function, modulating function, integration-function, macro-event function, or boundary function, but Chapter 29 creates no closed inventory and no new primitive.

```text
functions as □
≠
is □
```

The target label must name an actual difference in the target context. It cannot be supported solely by usefulness, narrative fit, visual grouping, or resemblance.

### 5.4 Source-object integrity

Projection must preserve enough of the source object for the target-function claim to remain traceable. At minimum, the assessment must keep visible:

- source identity and source Record;
- origin type and source Frame;
- historical or structural load;
- constitutive source relations relevant to the projection;
- source-function and prior claim disposition where material;
- uncertainty, exclusions, and irrecoverable Loss;
- boundaries of the source reconstruction.

Source-object integrity does not require every source feature to be reproduced in the target account. It requires declared selection and Loss without replacement of the source identity.

### 5.5 Functional Continuity

Functional Continuity asks whether the proposed target function depends on identifiable source features in the declared target context.

```text
source feature set S
materially altered or removed
→
target function F changes, weakens, or fails
```

The counterfactual is bounded. It tests constitutive dependence of the projection claim; it does not automatically prove empirical causality, intention, necessity across all contexts, or normative importance.

### 5.6 Contextual Boundedness

The target function requires:

- a declared target object or scene;
- a target Frame or contextual coordinate where relevant;
- a relative target level;
- relevant roles and relations;
- temporal and functional scope;
- Geltungsdauer or termination condition;
- Claim Ceiling;
- alternatives and no-projection account;
- Stop and Non-Capture conditions.

No projection automatically generalizes to all later contexts, scenes, roles, levels, or durations.

## 7. Counterpressure and Anti-Elasticity Controls

The proposed function must face at least the following counterpressure:

1. the source object may merely be relevant background;
2. the target scene may be reconstructible without the projection;
3. current Frames, Attractors, Bindings, or other present structures may carry more of the target function;
4. the proposed function may survive radically different or opposite source structures, indicating label elasticity;
5. the target function may be rhetorical rather than praxeologically discriminating;
6. the selected source features may be modulating rather than load-bearing;
7. the target claim may exceed source precision or Claim Ceiling;
8. the projection may compress exclusions, uncertainty, or failed prior claims.

```text
target label fits many opposite source structures
→
label elasticity pressure
→
claim reduction, failure, stop, or non_capture
```

## 8. Operation-Boundary Discipline

### 8.1 RETYPE versus recontextualization

Recontextualization changes legibility, perspective, or salience. `PROJECT_AS` additionally asserts a source-traceable target function in a declared context.

```text
new Frame or display
≠ target function automatically
```

Reader panels, graph layers, spatial grouping, filters, temporal scrubbing, or interface roles can expose a projection claim but cannot execute or warrant it.

### 8.2 RETYPE versus COMPOSE

`COMPOSE` forms a new analytical object from several sources. `PROJECT_AS` retains an already formed source object and assigns a bounded contextual function.

```text
configurations
COMPOSE
Trajectory X

Trajectory X
PROJECT_AS
frame-function in C
```

These are separate occurrences with separate Records, Loss, and results.

### 8.3 RETYPE versus DECOMPOSE

`DECOMPOSE` opens the source object's internal constitution. `PROJECT_AS` keeps the source object as a unit and tests its target-context function.

A source trace inherited from SUB may support a later projection, but successful decomposition does not establish the target function. A projection may also fail while the decomposition remains admissible.

Local target-function descriptions do not create new Output Classes. Potential pressure includes:

- responsible discrimination among rival functions unavailable → `non_capture`.

No mapping is automatic. Chapter 29 establishes conceptual pressure only; Chapter 30 owns the full operation-level result architecture.

## 10. Loss, Alternatives, Stop, Non-Capture, and Re-entry

Every later projection must retain canonical Loss:

```yaml
loss:
  preserved:
  compressed:
  excluded:
  uncertain:
  irrecoverable:
```

Projection-specific Loss includes foregrounded source features, compressed source heterogeneity, excluded relations, uncertain functional links, and irrecoverable source history. A successful projection is not lossless.

Mandatory Stop pressure arises where continuation would require:

- replacing the origin type;
- inventing a target context or target function;
- treating resemblance or usefulness as Functional Continuity;
- extending the function beyond its declared scope;
- erasing failed source claims or inherited Loss;
- creating a new operator or person type;
- deriving legitimacy, recommendation, sanction, or authority.

`non_capture` remains available where several target functions or no-projection accounts remain supportable without responsible discrimination.

A new target context, revised target function, materially new source evidence, repaired functional trace, or changed target conditions may permit re-entry. It creates a new testable claim and does not erase the earlier failure, stop, Loss, or no-projection result.
