## 1. Preparation Status and Scope

This Record prepares the RETYPE boundary chapter that separates **valid functional projection**, **structural analogy**, and **label substitution**. Chapter 37 does not redefine `PROJECT_AS`, analogy in every possible domain, semantic truth, the ten Output Classes, the Admissibility Band, or the Shared Transformation Record. It establishes non-overlapping minimum burdens and a cross-domain semantic-preservation discipline.

The governing question is:

> What distinguishes a source-dependent target function from a useful structural resemblance or a rhetorically strong PMS label with no new praxeological work?

```text
valid functional projection
≠ structural analogy
≠ label substitution

formal correspondence
≠ semantic preservation

translation success
≠ model superiority
```

Chapter 37 may classify a mapping as `analogy_only`, require Claim Reduction, stop an unsupported projection, or retain Non-Capture. It may not convert formal similarity, executable mapping, symbolic consistency, domain familiarity, or translation breadth into empirical truth, semantic identity, a new PMS primitive, person judgment, recommendation, sanction, governance, or authority.

## 3. Chapter Contract Lock

Chapter 37 must establish:

- non-overlapping minimum requirements for functional projection, structural analogy, and label substitution;
- a valid projection as a bounded source-dependent target function with typed source, declared target context, PraxisPurchase, Constitutive Source Trace, Counterfactual Sensitivity, exact Loss, and Claim Ceiling;

- formal and executable correspondence as insufficient for praxeological projection;
- analogy as a legitimate terminal status and `analogy_only` as a legitimate canonical result;
- label substitution as use of a PMS-derived label without target-function warrant, new discrimination, Source Trace, relevant alternatives, Loss, or material-source sensitivity;
- signs of substitution including label invariance, undefined target context, metaphor-only function, missing Loss, missing rivals, and rhetorical strength without test load;
- analogy drift where a bounded resemblance becomes identity, authority, primitive, or automatic projection;
- translation breadth as expression or compression capacity rather than completeness, superiority, or exhaustive capture;
- an integrated Analogy Stress Test;
- cross-domain Claim Reduction, Mandatory Stop, Failure, Non-Capture, and source preservation.

Chapter 37 must not claim:

- that formal similarity establishes semantic identity;
- that executable mapping proves a valid projection;
- that a useful analogy must be upgraded to `PROJECT_AS`;
- that translation breadth proves PMS completeness or superiority;
- that familiar PMS labels create PraxisPurchase;
- that source residuals or target-only features may be discarded;
- that analogy is failure by default;
- that analogy-only establishes a target function;

## 6. Scientific Pressure and Counterfactual Architecture

The triad method must remain vulnerable to at least the following pressures:

1. **Source-feature removal:** does the mapping change when a purportedly constitutive source feature is removed?
2. **Target-feature removal:** does the claimed target function survive when a target-only feature is removed?
3. **Residual pressure:** which source features have no target equivalent, and which target features have no source equivalent?
4. **Semantic-role pressure:** are source and target elements merely positionally similar, or do they perform comparable praxeological work?
5. **Artificial-fitting pressure:** were target features redescribed solely to match the source vocabulary?
6. **Countercase pressure:** do relevant counterexamples break, narrow, or reverse the mapping?
7. **Label-invariance pressure:** does the PMS label remain unchanged under material source or target variation?
8. **Executable-correspondence pressure:** does implementation success reveal only technical consistency rather than semantic preservation?
9. **Translation-breadth pressure:** does broad translatability increase expression without increasing discrimination?
10. **Analogy-drift pressure:** does a bounded resemblance later become identity, target function, source type, authority, or new primitive?
11. **No-projection pressure:** is analogy sufficient while functional projection remains unwarranted?
12. **Non-Capture pressure:** do domain-specific semantics resist responsible translation or analogy classification?

The integrated Analogy Stress Test must vary:

- source features and candidate subsets;
- target features and context;
- mapping direction;
- role and function assignments;
- formal/symbolic/executable correspondence;
- semantic-preservation claims;
- residual structures;
- countercases;
- alternative analogies;
- no-projection and Non-Capture.

The test remains qualitative. It does not infer empirical truth, semantic identity, causal equivalence, model superiority, person classification, legitimacy, recommendation, sanction, governance, or authority.

```yaml

  preserved:
  compressed:
  excluded:
  uncertain:
  irrecoverable:
```

For cross-domain mappings, the Loss declaration must distinguish:

- source features preserved by the mapping;
- source semantics compressed into formal relations;
- source features excluded because no target equivalent exists;
- uncertain correspondences;
- irrecoverable semantic differences;
- target-only features not inherited from the source.

Target-only features are not added to the source Loss schema. They remain explicit mapping residuals or target declarations.

```text

≠ sixth Loss field
```

A failed projection or analogy claim does not invalidate the independently warranted source object. A failed mapping does not imply that either domain is false, inferior, or irrelevant.
