## 3. Contract Lock

### 3.1 Governing question

> What additional structure turns chronology, a sequence, or a set of warranted transitions into a warranted path?

### 3.2 Required chapter claim

```text
A path is the actually traversed,
selectively reconstructed chain
of relevant configurations and transitions
within a declared frame.
```

The path claim requires both:

```text
actual traversal
+ disclosed analytical selection
```

Neither can replace the other.

### 3.3 Required selection rule

Path construction must disclose:

- included configurations and transitions;
- compressed intermediate structure;
- excluded records, contexts, or branches;
- uncertain relations;
- irrecoverable gaps;
- unrealized but source-supported alternatives;
- open residue;
- the praxis dimension that makes the selection relevant.

```text
selection
≠ archival completeness
≠ discretionary storytelling
```

### 3.4 Required non-dependence rule

```text
warranted path
≠ strong path dependence automatically
```

A path may be reconstructible while the current state remains largely present-determined, while historical order adds little explanatory load, or while alternatives remain broadly open. Chapter 12 owns the separate dependence test.

### 3.5 Required distinctions

Chapter 10 must preserve:

```text
chronology
≠ sequence
≠ path
```

```text
realized path
≠ blocked continuation
≠ aborted continuation
≠ deferred continuation
```

```text
path endpoint
≠ historical closure
```

```text
path reconstruction
≠ retrospective plausibilization
```

```text
same endpoint
≠ same path
```

```text
path
≠ trajectory
≠ path dependence
```

### 3.6 Qualified path-status rule

The unqualified term **path** remains reserved for an actually traversed chain. `blocked`, `aborted`, and `deferred` are qualified continuation or path-status claims with additional burdens.

- A **blocked continuation** was genuinely available or structurally prepared and prevented by an identifiable condition.
- An **aborted path** includes source-supported initiation, authorization, or partial traversal followed by cessation.
- A **deferred continuation** remained available but was postponed under a temporally relevant condition.

```text
qualified path status
≠ realized traversal automatically
```

This rule resolves the apparent tension between the core actual-traversal definition and the chapter’s required blocked, aborted, and deferred categories.

## 5. Path Threshold Architecture

### 5.1 Chronology, sequence, and path

A chronology sorts events or records by time. A sequence provides a warranted order among selected temporal units. A path adds actual traversal, one bounded reference object, a declared selection rule, constitutive connectedness, and branch/omission/loss disclosure.

```text
correct chronology
≠ warranted sequence automatically
≠ warranted path automatically
```

A chronology can remain valid when a path claim fails. A sequence can remain valid when actual traversal or constitutive connectedness is not established.

### 5.2 Actual traversal

“Actually traversed” is not omniscient reconstruction. It requires enough source trace to show that the selected chain was realized rather than merely:

- conceivable;
- narratively smooth;
- retrospectively plausible;
- institutionally typical;
- inferred from the endpoint;
- selected because it supports a preferred explanation.

Traversal evidence may be direct or indirect, but indirect evidence must expose its inferential steps and alternatives.

```text
plausible route
≠ traversed route
```

### 5.3 Constitutive connectedness

A path requires more than adjacent transitions. The selected units must form one chain for the tested claim.

A relation is constitutive where removing or materially changing it would alter the warranted path reconstruction. This does not establish complete causality.

```text
constitutive path relation
≠ complete causal mechanism
```

### 5.4 Path candidate versus warranted path

```text
path candidate
≠ warranted path
```

A path candidate has a delimited frame, components, selection rule, evidence declaration, and claim. A warranted path has also passed applicable continuity, admissibility, loss, alternatives, governance, and routing tests.

Record completeness alone cannot perform that passage.

## 6. Path Components

The chapter must make the following components independently inspectable:

```yaml
path_components:
  source_configuration:
  transitions:
  intermediate_configurations:
  event_clusters:
  non_event_structures:
  branch_points:
  selected_continuation:
  foreclosed_alternatives:
  current_endpoint_or_open_continuation:
```

### 6.1 Source configuration

The source configuration is the declared beginning of the path reconstruction, not necessarily the absolute historical beginning.

```text
path start
≠ origin of the whole history
```

### 6.2 Transitions

Each included transition must remain identifiable and must not lose its Chapter-9 result, uncertainty, or failure history when placed inside a path candidate.

```text
path membership
≠ transition revalidation
```

### 6.3 Intermediate configurations

Intermediate configurations may be compressed where they are not load-bearing. They must be represented where omission would change traversal, frame, branch availability, binding, asymmetry, or residue.

### 6.4 Event clusters and non-event structures

A path may group multiple events for analytic economy, but clustering must not erase order, opposing effects, or relevant gaps. Non-events remain expectation-bound and must not be inferred from silence.

### 6.5 Branch points and alternatives

A branch point requires source-supported divergence in accessible continuation. A foreclosed alternative requires support for prior availability plus the condition of foreclosure.

```text
unrealized alternative
≠ imagined possibility
```

Chapter 13 later owns the full alternative ontology.

### 6.6 Endpoint or open continuation

The endpoint is the end of the declared reconstruction. It may be closed, provisional, open, or source-limited.

```text
path endpoint
≠ historical closure
≠ completed process automatically
```

## 7. Selection and Formation Burden

### 7.1 Selection rule

The selection rule must state why the chosen configurations and transitions carry the tested praxis relation. Legitimate criteria may include changes in:

- review or decision authority;
- expectation structures;
- action corridors;
- costs or exposure;
- asymmetries;
- bindings;
- residue;
- continuation possibilities.

Selection based only on narrative convenience, moral evaluation, present importance, or endpoint knowledge is insufficient.

### 7.2 Retrospective selection and hindsight

Every historical path is reconstructed retrospectively to some degree. Retrospective reconstruction is not prohibited. What is prohibited is retrospective plausibilization that treats the realized endpoint as proof that each earlier selected element belonged to one inevitable chain.

```text
retrospective reconstruction
≠ retrospective inevitability
```

### 7.3 Compression, exclusion, and uncertainty

The path declaration must distinguish:

```text
preserved
compressed
excluded
uncertain
irrecoverable
```

Compression may preserve path identity while reducing detail. Exclusion may be legitimate when records are non-constitutive for the tested claim. Uncertainty and irrecoverability must remain visible.

### 7.4 Local formation versus full COMPOSE

Chapter 10 defines the path-object formation burden. Chapter 15 owns the complete `COMPOSE` occurrence procedure, including operation declaration, formation mapping, preservation/loss mechanics, alternatives, and operation-specific result.

```text
path object formation burden
≠ completed COMPOSE procedure
```

No path claim at Chapter 10 may be treated as automatic authorization of a `COMPOSE` occurrence.

## 8. Path Frame and Periodization

A path frame must declare:

- reference object;
- path start and end or open edge;
- relevant roles and institutions;
- included and excluded environments;
- temporal, source, and claim scope;
- granularity and relative level;
- comparison basis where paths are compared;
- rationale for periodization.

```text
path boundary
≠ objective universal boundary
```

Two analysts may construct different bounded paths from overlapping materials where they declare different, defensible frames and selection rules. This possibility does not make every path equally warranted.

### 8.1 Frame continuity

A frame may change within a path where the change is itself historically supported and the handoff remains reconstructible. An unmarked analytical frame switch cannot manufacture a path relation.

### 8.2 Periodization pressure

Changing the path start can change whether an event appears initiating, responsive, persistent, or residual. Changing the endpoint can change whether continuation appears blocked, deferred, or open.

```text
periodization difference
≠ arbitrary equivalence
```

Periodization must therefore be claim-sensitive and source-bounded.

## 9. Path Evidence Architecture

A path evidence declaration must distinguish:

- direct event evidence;
- documented temporal order;
- transition records and their result states;
- indirectly reconstructed traversal;
- supported non-event structures;
- branch and availability evidence;
- endpoint evidence;
- uncertainty and gaps;
- rival path constructions.

```text
evidence quantity
≠ path admissibility
```

### 9.1 Evidence matrix

| Evidence relation | Control question |
| --- | --- |
| component support | Are selected configurations and transitions reconstructible? |
| traversal support | Is the selected chain shown to have been realized? |
| constitutive support | Why do these units form one path for the claim? |
| selection support | Why are included, compressed, and excluded materials treated as stated? |
| branch support | Were alternatives genuinely available, blocked, aborted, or deferred? |
| praxis support | What warranted reconstruction changes because of this path? |

Strong endpoint evidence cannot compensate for missing traversal. Rich chronology cannot compensate for no selection rule. Practical usefulness cannot compensate for an invented branch.

### 9.2 Evidence-status routing

The evidence status may be:

- supported;
- bounded;
- provisional;
- underdetermined;
- source-limited;
- contested.

These are local evidence findings, not canonical Output Classes.

## 10. Path Status Architecture

### 10.1 Realized path

A realized path is the actually traversed selected chain to the declared endpoint or open continuation. It makes no claim of necessity, optimality, rationality, or inevitability.

```text
realized
≠ necessary
≠ rational
≠ intended
```

### 10.2 Blocked continuation

A blocked continuation requires:

- source-supported prior availability or structural preparation;
- identifiable blocking condition;
- relevant temporal position;
- effect on accessible continuation;
- evidence distinguishing blockage from non-selection, abandonment, or missing information.

```text
blocked continuation
≠ counterfactual fantasy
```

### 10.3 Aborted path

An aborted path requires source-supported initiation, authorization, commitment, or partial traversal followed by cessation. It may leave sunk costs, bindings, changed expectations, or residue.

```text
aborted
≠ never begun
≠ merely blocked before initiation automatically
```

### 10.4 Deferred continuation

A deferred continuation remains available but is postponed. Delay may change cost, expectation, frame, or later path identity.

```text
deferred continuation
≠ uninterrupted continuation
≠ permanent non-realization
```

A later resumed path must not be represented as if the intervening delay carried no load.

### 10.5 Multiple statuses across one reconstruction

A path may contain a realized main chain plus blocked, aborted, and deferred continuations at different branch points. These statuses must remain local to their claims and must not be compressed into one global label.

## 11. Path Comparison Architecture

Path comparison requires a declared comparison object and basis. At minimum, test:

- same or comparable source configuration;
- compatible frame;
- compatible granularity and relative level;
- comparable temporal span;
- comparable selection rule;
- comparable alternatives and branch evidence;
- comparable costs, asymmetries, and bindings;
- comparable source quality and gaps.

```text
path comparison
≠ endpoint comparison alone
```

### 11.1 Similar endpoints, different paths

Two paths may reach formally similar endpoints while carrying different:

- histories;
- costs;
- bindings;
- residues;
- foreclosed alternatives;
- continuation possibilities.

```text
same endpoint status
≠ same path
```

### 11.2 Different endpoints, partially shared paths

Different endpoints do not imply wholly different paths. Paths may share initial configurations and transitions before diverging. Comparison should preserve shared and divergent segments.

### 11.3 Incomparability

Where frame, temporal span, source scope, or selection rule cannot be responsibly aligned, the comparison may remain `formal_diagnostic`, require claim reduction, or fail. It must not be forced into a universal distance score.

## 12. Path Identity, Segment Lineage, and Overlap

Path identity cannot be reduced to one label, one endpoint, or one list of components. A path identity claim states why a bounded set of selected configurations and transitions is treated as one traversed historical object for the tested claim.

The minimum identity burden includes:

- a stable or explicitly handed-off reference object;
- a declared frame and periodization;
- identifiable source and endpoint or open continuation;
- constitutive transition relations;
- an explicit selection rule;
- traceable segment order;
- treatment of interruptions, branches, and status changes;
- preservation of known losses, alternatives, and residue.

```text
same path label
≠ same path identity
```

A later reconstruction may use the same path name while changing its source configuration, periodization, constitutive relation, or selection rule. Where those changes are material, it is a revised or rival path claim rather than the automatic continuation of the earlier identity.

```text
revised path construction
= new testable claim
```

### 12.1 Segment identity

A path may be represented through segments. Segment identity must remain subordinate to the whole-path claim without being erased by it.

A segment should state:

- its local source and target configurations;
- included transition records;
- relation to preceding and following segments;
- local evidence and uncertainty;
- local loss and alternatives;
- whether its endpoint is closed, open, blocked, aborted, or deferred.

```text
path segment
≠ complete path
```

A valid segment does not prove that all segments form one path. Conversely, a failed later segment does not erase a previously warranted earlier segment.

### 12.2 Shared segments and divergence

Two path constructions may share an initial segment and diverge later. They may also reach a similar endpoint through partially overlapping histories.

A responsible comparison must preserve:

```text
shared segment
+ divergence point
+ separately traversed continuation
```

It must not compress the relation into either total identity or total difference.

```text
shared history
≠ same complete path

different endpoint
≠ wholly unrelated path automatically
```

This matters for later trajectory and dependence tests. A shared segment may carry common historical load while divergent continuations produce different residue, asymmetry, or accessibility. Chapter 10 records the segment relation; Chapters 11–12 test the stronger historical properties.

### 12.3 Overlapping frames

Two valid path claims may use overlapping but non-identical frames. One may track procedural review, another responsibility allocation. The same events can appear in both paths while carrying different constitutive roles.

```text
shared source event
≠ shared path function automatically
```

Overlap is admissible where each claim separately declares reference, frame, selection, loss, and scope. It becomes inadmissible where one path silently inherits another path’s traversal proof, branch availability, or result.

### 12.4 Identity preservation under status change

A realized path may later include a deferred continuation; an aborted route may later be restarted; a previously blocked continuation may become available after a changed condition. Such changes require explicit temporal and record lineage.

A resumed continuation is not automatically identical to the route as originally available. Delay, new costs, changed actors, altered frames, and residual commitments may change the later path identity.

```text
resumption
≠ restoration of uninterrupted path identity
```

The record must therefore state what is preserved, what changed, and whether the later continuation is:

- the same path under a qualified interruption;
- a revised continuation;
- a new path sharing earlier segments;
- or a rival reconstruction that remains unresolved.

### 12.5 Identity failure and routing

Where reference, segment order, formation rule, or frame continuity cannot be established, the path-identity claim may remain `formal_diagnostic`. Where a bounded segment remains supported, `claim_reduction_required` can preserve that segment while refusing the whole-path identity. Where the selected materials demonstrably belong to incompatible objects or frames, the whole-path claim may receive `failed_transformation`.

If a known identity failure is ignored to derive trajectory, dependence, or authority, continuation requires `mandatory_stop`. Where two source-responsible identity constructions remain materially undecidable, `non_capture` preserves both and names the evidence required for re-entry.

## 13. Path without Strong Dependence

A warranted path may possess little additional explanatory load for the present state.

```text
reconstructible path
≠ strong path dependence
```

A present configuration may be largely explainable through current conditions even though its traversed history remains reconstructible. Historical order may matter descriptively without materially constraining current alternatives.

This possibility is necessary to prevent PATH from inflating every temporal reconstruction into historical determination.

A path-without-strong-dependence case must preserve:

- path validity;
- current-condition evidence;
- weak or limited historical load;
- open alternatives;
- the separate Chapter-12 test boundary.

```text
low dependence
≠ no history
```

## 15. Failure, Stop, and Non-Capture Architecture

A path claim is under pressure where:

- chronology is substituted for traversal;
- transition records are linked without one bounded reference object;
- constitutive connectedness is absent;
- path selection hides load-bearing evidence or rival chains;
- frame or periodization changes are unmarked;
- an imagined possibility is called blocked;
- a never-started route is called aborted;
- missing information is called deferred;
- endpoint similarity is used as path identity;
- path existence is used as trajectory, path-dependence, causal, normative, or authority proof.

Possible local dispositions remain separated:

```text
formal_diagnostic
≠ claim_reduction_required
≠ failed_transformation
≠ mandatory_stop
≠ non_capture
```

- **Formal Diagnostic:** a required relation—often traversal, comparison basis, branch availability, or frame handoff—remains unresolved and re-entry is possible.
- **Claim Reduction Required:** a chronology, sequence, component set, or bounded segment remains supportable while the full path claim is too strong.
- **Failed Transformation:** the delimited path claim cannot be sustained under the declared source basis and frame.
- **Mandatory Stop:** a known failed path is used to construct trajectory, path dependence, causality, universal function, or authority.
- **Non-Capture:** two or more materially different, source-responsible path reconstructions remain non-decidable under available sources.

```text
failed path claim
≠ erased chronology
≠ erased transitions
≠ erased rival reconstruction
```

A later new path claim requires explicit lineage and a new test.
