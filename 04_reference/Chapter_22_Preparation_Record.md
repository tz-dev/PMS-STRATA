## 1. Preparation Status and Scope

This record prepares Chapter 22 as the primary SUB site for relational decomposition of already-composite analytical objects. The chapter does not define composite structure, reopen `COMPOSE`, or infer a composite merely because several items, operator labels, or records appear together. Its source object must already satisfy the Chapter-1 object burden and, where applicable, preserve lineage to the `COMPOSE` occurrence that formed it.

The chapter must answer one governing question:

> How can an already-composite source object be opened under finer granularity while retaining the relations, selection history, compression, function, and loss that make it the same composite?

The bounded answer is:

```text
already-composite source object
+
source-supported finer component and relation reconstruction
+
retained composite reference and coarser-function trace
→
composite DECOMPOSE candidate
```

The chapter must reject two opposite failures:

```text
parts list without constitutive relations
→ atomistic fragmentation

unchanged macro-label without reconstructible internal load
→ abstraction without traceable load
```

Chapter 22 changes the source-object problem introduced in Chapters 20 and 21. Chapter 21 opened one operator-typed occurrence into production and maintenance conditions. Chapter 22 opens an object that already contains multiple selected constituents and declared constitutive relations. The operation must therefore retain not only source reference and coarser function, but also the composite boundary, composition trace where available, inherited compression, component-role structure, relation map, and internal distribution of function and load.

This Preparation Gate produces no canonical §22 prose, standalone case, Transformation Record, schema extension, new operation, new Output Class, new Rule, new audit stage, component ontology, operator score, person profile, or authority mechanism.

## 5. Composite Source Entry

### 5.1 Source-object threshold

A Chapter-22 source object must already be warranted as a composite. Minimum entry requires:

1. more than one identifiable constituent;
2. a declared composite boundary;
3. at least one source-supported constitutive relation;
4. a bounded composite claim or function under test;
5. internal traceability sufficient to challenge the composite;
6. known selection, compression, and Loss limits;
7. a same-reference route into the proposed finer reconstruction.

A label such as “institution,” “system,” “governance arrangement,” “culture,” “process,” or “network” does not establish a composite. The chapter must identify why the bounded object is one composite for the claim at issue.

### 5.2 Source composite versus source bundle

```text
source bundle
≠ source composite
```

A source bundle collects materials. A source composite is an analytical object whose constituents and relations support one bounded identity or function claim. Chapter 22 may use a source bundle as evidence, but `DECOMPOSE` acts on the composite object, not on the archive container.

### 5.3 Composite identity and continuity

The finer reconstruction must preserve enough of the source composite's identity to answer the same bounded question. Continuity may depend on:

- constituent lineage;
- constitutive relation continuity;
- function under test;
- composite boundary;
- temporal scope;
- institutional or spatial coordination;
- selection and compression history;
- declared substitutions or repairs.

A composite may remain the same reference object while some components are replaced, provided the constitutive relation and bounded function relevant to the claim remain supported. Conversely, retaining the same label does not preserve identity if the relation map and boundary have materially changed.

### 5.4 Inherited Loss

The source composite enters Chapter 22 already selective. The operation must distinguish:

```yaml
inherited_composite_loss:
  preserved:
  compressed:
  excluded:
  uncertain:
  irrecoverable:
```

This is not a second canonical Loss structure. It is a source-side view of the earlier five-part declaration. Chapter 22 must then record any additional operation-level Loss introduced by the finer reconstruction.

```text
inherited Loss
≠ new DECOMPOSE Loss

both remain visible
```

## 6. Internal Composition Map

### 6.1 Map purpose

The internal composition map identifies which components belong to the same source composite and how they bear on the tested function. It must make visible:

- component identity and source pointer;
- component role for the current claim;
- component-to-component relations;
- temporal ordering where relevant;
- spatial or institutional distribution where relevant;
- dependence, substitution, compensation, inhibition, repair, and feedback relations;
- operator-typed occurrence load where relevant;
- uncertainty and rival maps;
- relation to the coarser composite function.

### 6.2 Parts list prohibition

```text
component inventory
≠ internal composition map
```

A valid map need not include every local detail. It must include enough relational structure to explain why the selected components belong to the same composite and how changing their relations would affect the bounded composite claim.

### 6.3 Relation classes remain open

Relevant relations may include:

- hierarchy;
- sequence;
- mutual constraint;
- coordinated function;
- feedback;
- threshold;
- routing;
- redundancy;
- substitution;
- compensation;
- repair;
- inhibition;
- load transfer;
- conflict;
- residual persistence.

This list is open and descriptive. It does not establish a closed schema enum or causal proof.

### 6.4 Selection history and current map

The current composition map may differ from the map through which the composite was originally formed. Component replacement, repair, institutional transfer, or changing relations may preserve the bounded composite while revising its internal organization.

Chapter 22 must therefore distinguish:

```text
formation map
≠ current maintenance map
≠ proposed finer reconstruction
```

Where the formation map is partly irrecoverable, the chapter may still reconstruct the current composite if reference, current constitutive relations, and claim-relevant lineage remain supported. It may not invent a complete origin story.

## 7. Component Hierarchy

### 7.1 Claim-bound roles

Chapter 22 prepares five component roles:

```text
constitutive component
modulating component
replaceable component
compensatory component
incidental detail
```

These roles are local to a declared composite, claim, Frame, time, and granularity. The same source element may receive a different role under a different bounded claim. A role assignment is not a universal property of the element.

### 7.2 Constitutive component

A constitutive component participates in the relation structure without which the stated composite identity or function would materially change. Constitutive does not automatically mean:

- ontologically fundamental;
- causally sufficient;
- irreplaceable in every implementation;
- normatively superior;
- permanently present.

A role may be constitutive while its current carrier is replaceable.

### 7.3 Modulating component

A modulating component changes the accessibility, cost, threshold, direction, temporal efficacy, intensity, or stabilization burden of the composite function without alone defining the composite identity.

Modulation must be evidenced through a changed relation or warranted difference. Merely describing a component as “important” is insufficient.

### 7.4 Replaceable component

A replaceable component currently carries part of the composite function but can be substituted by another carrier while the bounded composite identity or function persists. Replacement may still alter:

- cost;
- speed;
- burden distribution;
- reliability;
- accessibility;
- residual conflict;
- Loss.

```text
replaceable
≠ irrelevant
≠ incidental
```

### 7.5 Compensatory component

A compensatory component offsets weakness, failure, delay, conflict, or unequal load elsewhere. Compensation may stabilize the macrofunction while concealing local breakdown or transferring costs.

```text
macrofunction preserved by compensation
≠ local failure absent
```

### 7.6 Incidental detail

An incidental detail is source-supported but does not alter the tested composite identity or function under the current claim. Incidental does not mean globally meaningless. It may become relevant under another Frame or claim, but it cannot be promoted into the current composition map merely because it is available.

### 7.7 Local hierarchy without ontology

Chapter 22 may describe one component as dominant, peripheral, upstream, downstream, carrying, or residual relative to the tested claim. It may not infer universal levels of being or a permanent component hierarchy.

## 8. Dominant Operator Weighting

### 8.1 Weighting object

Operator weighting concerns relative load among existing operator-typed occurrences or relations inside the composite. The weighting claim must identify:

- the bounded composite;
- the tested function;
- the operator-typed occurrence carriers;
- the dimension of weighting;
- temporal scope;
- source support;
- counterpressure;
- what would change if the weighting changed.

### 8.2 Non-numeric default

Chapter 22 does not require or authorize a universal numerical score. Terms such as “dominant,” “strongly shaping,” “peripheral,” or “countervailing” remain bounded relational descriptions.

```text
operator weighting
≠ additive operator score
≠ universal strength rank
```

### 8.3 PMS dependency protection

A composite may be described as, for example, `Λ/Θ`-dominant or `Ω/Θ`-dominant for a declared function. This means that source-supported Non-Event/Temporality or Asymmetry/Temporality occurrences carry a large share of the current composite load. It does not mean that operator order or dependency has changed.

```text
composite weighting profile
≠ PMS dependency graph
```

### 8.4 Dominance is not exclusivity

A dominant weighting does not erase other operator occurrences, residual structures, or countervailing relations. A composite may have several dimension-specific weightings rather than one total profile.

## 9. Modulating Profiles

### 9.1 Source-side profile

A Chapter-22 modulating profile is a bounded description of how existing operator relations are differently accessible, activated, delayed, stabilized, or burdened inside one source composite.

Possible profile dimensions include:

- access;
- threshold;
- temporal efficacy;
- persistence;
- coordination cost;
- exposure;
- repair burden;
- stabilization load.

### 9.2 Profile anti-type boundary

```text
modulating profile
≠ operator type
≠ composite type
≠ person type
```

The profile belongs to the bounded composite claim. It does not become a stable trait of the people participating in the composite.

### 9.3 SUB versus RETYPE profile ownership

Chapter 22 reconstructs source-side modulation within the same composite. RETYPE Chapters 34–35 later own claims that an origin-typed composite functions as a higher-level Frame, Attractor, Asymmetry, or another target function in a declared context.

```text
source-side modulation
≠ contextual target function
```

### 9.4 Profile multiplicity and non-compensation

Different profile dimensions must remain separately supported. Strong evidence for temporal persistence cannot compensate for missing evidence about access, burden, or threshold. Profiles are not averaged into one synthetic score.

## 10. Distributed Function

### 10.1 Distribution forms

A composite function may be carried across:

- spatially separated units;
- institutionally separated roles;
- temporally alternating carriers;
- parallel channels;
- layered decision and repair structures;
- distributed records and expectations.

### 10.2 Coordination burden

Distribution becomes one composite function only where the analysis identifies:

1. the distributed elements;
2. their relation to the same bounded composite;
3. a coordination or dependency mechanism;
4. the common function under test;
5. the effects of partial change or failure;
6. source support and uncertainty.

```text
distribution
≠ aggregation
```

Co-presence across locations or institutions is insufficient. The analysis must show how the separated elements jointly carry the function.

### 10.3 Partial failure

A distributed function may persist when one element changes or fails. Persistence may reflect redundancy, substitution, compensation, or delayed load transfer. The operation must record what persists and what changes.

### 10.4 Distributed function versus new macro-object

If Chapter 22 selects previously separate structures and asserts that they jointly form a new macro-composite, the analyst has crossed into `COMPOSE`. The source composite must not be enlarged silently during decomposition.

## 11. Redundant and Substitutable Components

### 11.1 Redundancy

Redundancy exists where more than one component can carry the same or overlapping claim-relevant function. It may improve persistence while increasing cost or concealing unequal burden.

The local removal pressure asks:

> If this component were removed, disabled, or rendered unavailable while the rest of the supported relation map remained fixed as far as possible, what composite function, load, relation, or identity claim would change?

This pressure prepares but does not replace Chapter 27's complete Counterfactual Component Test.

### 11.2 Substitution

Substitution asks whether another supported component or carrier can assume the relevant role. A valid substitution claim must identify:

- current carrier;
- substitute carrier;
- preserved function;
- changed cost, timing, burden, access, or uncertainty;
- transition conditions;
- source support.

### 11.3 Persistence without equivalence

Two components may be functionally substitutable for one bounded claim while remaining structurally different.

```text
substitutable for function F
≠ identical components
≠ lossless replacement
```

### 11.4 Qualitative threshold

A composite may tolerate several local substitutions before crossing a qualitative threshold. Chapter 22 may prepare the threshold question but must not invent a universal percentage or score. The threshold is source-, function-, Frame-, and claim-bound.

## 12. Internal Conflict

### 12.1 Conflict forms

Internal conflict may involve:

- incompatible local functions;
- competing operator-typed occurrences;
- resource or access gradients;
- conflicting temporal demands;
- formal rule versus practical routine;
- repair versus stabilization burden;
- constituent-level path divergence.

### 12.2 Open outcomes

Chapter 22 must permit at least five outcomes:

```text
conflict destabilizes the composite function
conflict is functionally integrated
conflict is suppressed through asymmetry
conflict persists as residue
conflict generates competing subpaths
```

These are local analytical descriptions, not new Output Classes or a closed enum.

### 12.3 Conflict is not automatic destruction

```text
internal conflict
≠ composite failure automatically
```

A composite may persist by integration, suppression, repair, redundancy, or unequal load. Persistence does not validate the conflict arrangement or authorize legitimacy judgments.

### 12.4 Conflict and source-function testing

The finer reconstruction must state whether conflict:

- confirms a bounded composite function;
- differentiates it;
- partially preserves it;
- rejects it;
- leaves it underdetermined.

The Chapter-20 result axes remain separate.

## 13. Composite Stability

### 13.1 Stability mechanisms

Composite stability may arise through:

- stable constitutive relations;
- repeated repair;
- redundancy;
- substitution;
- compensatory components;
- institutional binding;
- distributed load;
- suppression of conflict;
- temporal alternation;
- retained expectations and Non-Events.

### 13.2 Stability object and time

The stability claim must identify what remains stable and over which interval. Stability of output, reference, role structure, access pattern, burden distribution, or label are not interchangeable.

### 13.3 Stability with churn

A composite can retain a stable macrofunction while local carriers change. The operation must show which relations preserve continuity and which substitutions alter the claim.

### 13.4 Stability and unequal load

Macro-stability may be purchased through concentrated burden, inaccessible repair, or suppressed conflict. Chapter 22 may reconstruct that structure but cannot infer moral rank, legitimacy, sanction, or intervention authority.

## 14. Decomposition without Fragmentation

### 14.1 Positive standard

A valid composite decomposition:

- keeps the source composite reference visible;
- retains the coarser function as a test target;
- reconstructs components and relations together;
- distinguishes component roles;
- preserves or revises distributed function;
- records redundancy, substitution, conflict, and stability mechanisms where relevant;
- retains inherited and new Loss;
- permits rival maps and underdetermination;
- stops below the Praxeological Relevance Floor or above the Traceability Ceiling.

### 14.2 Fragment versus component

A fragment is a selected detail whose inclusion no longer carries a reconstructible relation to the source composite and tested function. A component has a source-supported role and relational placement.

```text
small detail
≠ fragment automatically

large subsystem
≠ component automatically
```

Size does not decide the distinction.

### 14.3 Macrofunction remains testable

The macrofunction may be confirmed, refined, internally differentiated, partially preserved, rejected, or left underdetermined. It may not disappear silently while the analysis celebrates local detail.

### 14.4 No anti-macro privilege

Finer local detail receives no automatic privilege over the composite claim. A source-supported macrofunction may remain warranted despite component substitution or local variation. Conversely, a stable label may fail when constitutive relations disappear.

## 15. Failure, Mandatory Stop, and Non-Capture

### 15.1 Failed composite decomposition

The operation fails where the attempted reconstruction:

- produces an atomistic parts list;
- loses constitutive relations;
- overprivileges local detail;
- treats correlation as constitutive function;
- assigns unsupported component roles;
- invents hierarchy, weighting, profile, coordination, or conflict outcomes;
- erases inherited selection or Loss;
- allows the source composite to disappear;
- silently forms a new composite;
- silently assigns a target function;
- treats operator weighting as operator revision;
- converts a profile into a person type.

### 15.2 Mandatory Stop

Mandatory Stop is required where continuation would require:

- inventing constituents or relations beyond the source ceiling;
- treating a source bundle as an established composite;
- recovering irrecoverable formation history as fact;
- preserving a composite label after reference or constitutive relation loss;
- creating a new `COMPOSE` or `PROJECT_AS` claim without a separate record;
- changing PMS operator dependencies;
- inferring person traits, legitimacy, sanction, or action authority;
- continuing below the Relevance Floor or above the Traceability Ceiling.

### 15.3 Non-Capture

`non_capture` remains possible where the composite source object and decomposition question are legitimate, but available evidence does not support one stable finer composition map. This may occur where:

- several incompatible relation maps remain equally source-supported;
- distributed coordination is inaccessible;
- component roles change across the relevant interval without a warrantable common mapping;
- inherited Loss removes decisive relation evidence;
- the source composite remains recognizable but its finer internal organization cannot be responsibly stabilized.

```text
non_capture
≠ coarse composite claim rescued
≠ all rival maps equally true
≠ permission to invent a profile
```

The prior composite function may remain reduced, rejected, or underdetermined.

### 15.4 Non-compensation

Record completeness, detailed mapping, source volume, formal symmetry, or operator vocabulary cannot compensate for missing reference continuity, constitutive relations, source support, PraxisPurchase, or Type Integrity.
