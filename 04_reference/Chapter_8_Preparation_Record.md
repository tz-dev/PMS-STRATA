## 1. Purpose and Boundary

This record prepares Chapter 8 before canonical drafting. It fixes the chapter’s definition ownership, audit meaning, catalogue closure, pair order, contrast form, example family, work packages, case obligations, reference handoff, formal-model relation, local audit criteria, and completion test.

Chapter 8 is the final Foundations chapter. Its task is not to introduce another theoretical layer. It converts the distinctions already defined in Chapters 0–7 into a compact, reusable audit catalogue that later chapters can apply without re-deriving the Foundations.

It does **not**:

- draft or provisionally lock Chapter 8;
- redefine any object, coordinate, temporal object, operation, continuity criterion, admissibility rule, record field, Output Class, PMS operator, or authority boundary;
- treat `≠` as an empirical negation operator, a prohibition on comparison, or a proof that two terms can never be related;
- claim that the thirteen-pair catalogue is exhaustive for every future domain or confusion case;
- create a fourteenth foundational pair merely because a local wording variant exists;
- turn a useful analogy into a valid `PROJECT_AS` claim without its separate source, type, function, context, continuity, and admissibility tests;
- make finer resolution, higher relative position, formal precision, technical implementation, or machine validity a source of truth or authority;
- allow a new frame, granularity, level, composite, target function, or record to erase a previously failed, reduced, stopped, or non-captured claim;
- create a fourth operation, eleventh Output Class, new PMS primitive, universal scale, compensatory score, or authority-bearing audit status;
- revise `PMS.yaml`, Δ–Ψ, their names, order, dependencies, or eleven-operator inventory;
- pre-empt the full Part-specific non-equivalence, confusion, invalid-pattern, analogy-stress, or LIMITS procedures;

### 3.6 Required counterpressure

Chapter 8 must withstand:

- a finer reconstruction can genuinely outperform a coarser one for a declared claim without becoming “higher truth”;
- a relative-level declaration can be analytically indispensable without positing ontological layers;
- a composition can form a real new analytical object while remaining selective and lossy;
- a decomposition can be highly informative without discovering final constituents;
- a sequence can support a path reconstruction without being identical to a path;
- a path can develop trajectory features without every path becoming a trajectory;
- a trajectory can be strongly or weakly path-dependent, so the property requires separate testing;
- a trajectory can perform a frame-function without becoming a `Frame` operator type;
- an operator-like contextual function can remain derived and non-primitive;
- operator weighting can materially affect visibility and development without revising PMS grammar;
- a structural analogy can remain useful and receive `analogy_only` even when `PROJECT_AS` is inadmissible;
- recursive opening can remain available while Stop and Non-Capture remain constitutive;
- formal precision and technical implementation can improve auditability while remaining semantically wrong, empirically unsupported, or non-authoritative.

### 3.7 Prohibited claims

Chapter 8 must not claim that:

- distinct terms can never be compared or related;
- all cross-level, cross-context, or cross-domain relations are invalid;
- every identity collapse yields the same Output Class;
- the catalogue itself proves an empirical counterclaim;
- pair checking replaces Source Trace, continuity, Admissibility Band testing, Loss disclosure, Claim Ceiling, Stop, or Non-Capture;

- the catalogue is exhaustive for all future domains;

- every analogy is merely decorative or every projection is analogy;
- every recursion must stop immediately or every non-captured structure is permanently inaccessible;
- the final Foundations chapter possesses higher authority than Chapters 0–7.

## 4. Catalogue Architecture

### 4.1 Cluster A — Resolution, Level, and Operation Limits

Sections 8.1–8.4 form the first cluster:

```text
finer granularity ≠ higher truth
relative level ≠ ontological layer
composition ≠ lossless addition
decomposition ≠ discovery of final constituents
```

The cluster protects three foundations at once:

- coordinates do not become truth rankings or ontology;
- operation products do not become lossless totals;
- operation direction does not become metaphysical depth.

The cluster must return to Chapters 0, 2, 4, and 6 rather than reproduce their full arguments.

### 4.2 Cluster B — Temporal Object and Historical-Property Limits

Sections 8.5–8.7 contain:

```text
path ≠ sequence
path ≠ trajectory
trajectory ≠ path dependence
```

This cluster protects the temporal object chain from collapse. It must preserve:

```text
sequence
→ ordered occurrence structure

path
→ actually traversed, selectively formed transition structure

trajectory
→ historically sedimented path-form with altered continuation possibilities

path dependence
→ separately tested property of historical determination
```

The arrows indicate conceptual progression, not automatic promotion or identity.

### 4.3 Cluster C — Type, Function, Operator, and Grammar Limits

Sections 8.8–8.10 contain:

```text
origin type ≠ target function
projection ≠ operator identity
operator weighting ≠ operator replacement
```

This cluster protects PMS Base and Chapter-5 continuity. It must make visible that:

- a contextual function does not rewrite source identity;
- operator-like performance does not add a primitive;
- relative dominance or load does not rename, reorder, bypass, decompose, or replace Δ–Ψ.

### 4.4 Cluster D — Analogy, Recursion, and Authority Limits

Sections 8.11–8.13 contain:

```text
structural analogy ≠ valid projection
recursion ≠ completeness
legibility ≠ authority
```

This cluster protects the system against three common forms of analytical inflation:

- resemblance treated as typed functional continuity;
- availability of further operations treated as total capturability;
- formal or technical success treated as truth or entitlement.

It supplies a direct handoff to RETYPE, LIMITS, the Decision Tree, and the Integrated Audit.

### 4.5 Non-equivalence and relation declaration

An admissible relation across a pair must state what kind of relation is claimed:

```text
comparison
analogy
source-material relation
operation occurrence
property test
contextual function
local superiority for a declared claim
```

The relation must not silently inherit the identity, type, scope, authority, or success conditions of the other term.

### 4.6 Failure and routing discipline

A non-equivalence breach can contribute to different local outcomes depending on the claim:

- `analogy_only` where a resemblance remains useful but projection is not established;
- `claim_reduction_required` where a bounded relation can survive after identity inflation is removed;
- `partially_admissible` where segmented claims diverge;
- `failed_transformation` where the tested operation claim depends on the collapse;
- `mandatory_stop` where analysis continues from a known prohibited identity or authority transfer;
- `non_capture` where rival relational interpretations cannot be responsibly adjudicated.

```text
non-equivalence breach
≠ one automatic Output Class
```

Output selection remains controlled by Chapter 6, Chapter 7, and the Boundary Decision Tree.
