## 1. Preparation Status and Scope

This record prepares Chapter 26 as the primary SUB site for deciding whether an analysis remains an internal reconstruction of a source object or has begun assigning that source object a bounded function in another declared context. Chapters 18–25 establish source entry, lower granularity, generic and family-specific `DECOMPOSE`, resolution assessment, bounded Stop, and re-entry. Chapter 26 does not repeat those procedures and does not pre-write RETYPE. It controls the operation boundary that must be crossed explicitly before the work enters `PROJECT_AS`.

The governing question is:

> Is the analysis opening the internal constitution of the source object, or is it preserving that object while asserting a bounded contextual target function?

The bounded Chapter-26 architecture is:

```text
source object with declared origin type and source function
+
analysis question, Frame, granularity relation, and proposed context
+
internal-constitution test
+
target-function test
+
recontextualization and dual-operation controls
→
operation-boundary result with separate claims, Records, Loss, and failure possibilities
```

Chapter 26 must resist six recurrent substitutions:

```text
new description
→ DECOMPOSE automatically

new Frame
→ PROJECT_AS automatically

new label
→ new target function automatically

internal component summary
→ RETYPE automatically

contextual interpretation
→ operation automatically

one useful analysis
→ one mixed DECOMPOSE / PROJECT_AS Record
```

All six are prohibited. The linguistic surface does not determine the operation. A text may sound classificatory while merely summarizing internal source structure. A text may sound decompositional while actually assigning an external target function. A Frame change may be only recontextualization. A case may genuinely require both operations, but the operation occurrences remain distinct and independently testable.

This Preparation Gate produces no canonical §26 prose, standalone Case, Transformation Record, Smoke Record, appendix expansion, new operation, new canonical Output Class, new Rule, new audit stage, schema extension, target-function catalogue, origin-type replacement mechanism, automatic operation classifier, person type, recommendation engine, or authority mechanism.

## 3. Contract Lock

### 3.1 Required core claim

Chapter 26 must establish:

> `DECOMPOSE` changes granularity in order to reconstruct the internal constitution of the same source object, while `PROJECT_AS` preserves the origin-typed source object and asserts a bounded contextual target function. A case may require both operations, but each operation occurrence requires a separate claim, Record, justification, Loss account, and failure possibility.

The operation-boundary assessment must declare:

- the source object and origin type;
- the source function or explanatory target;
- the analysis question;
- the Frame and proposed context;
- the granularity relation;
- whether internal source structure is opened;
- whether the source object remains the explanatory target;
- whether a contextual target function is asserted;
- whether origin type and target function remain distinct;
- whether the change is merely recontextualization;
- the candidate operation or operation chain;
- separate Record requirements;
- Loss, uncertainty, Stop, and Non-Capture.

### 3.2 Internal-constitution rule

A candidate remains within `DECOMPOSE` where the analysis asks what finer structures constitute, reproduce, maintain, destabilize, interrupt, or revise the source object. The primary change is a change of granularity or internal distinction set. The source object remains the explanatory target, even if its source category or source function is refined, reduced, or rejected.

Internal reconstruction may identify:

- components and component roles;
- internal relations;
- phases, sub-events, or transition clusters;
- subpaths and branch structures;
- inherited and new Loss;
- internal Frame changes;
- mechanisms that carry or disturb the coarser source function.

None of these automatically assigns a function in another target context. A component map can remain entirely within SUB even when it receives a new descriptive heading.

### 3.3 Target-function rule

A candidate crosses into `PROJECT_AS` where the source object remains origin-typed and is asserted to perform a bounded function in a declared target context. The target function is a new contextual claim and not a newly discovered origin type.

A target-function claim must declare:

- the origin-typed source object;
- the target context;
- the proposed contextual function;
- the constitutive source features on which that function depends;
- contextual boundedness;
- counterpressure and rival functions;
- Loss and excluded dimensions;
- failure and Stop conditions.

A new label, analogy, convenient metaphor, Reader display role, or later use is insufficient. The function must be source-traceable and contextually bounded.

### 3.4 Granularity versus target-context change

A lower granularity does not by itself create RETYPE. A new context does not by itself create `PROJECT_AS`. The test concerns what the claim now asserts.

```text
primarily finer internal structure
+
source object remains explanation target
→ DECOMPOSE pressure

source object retained as unit
+
bounded function asserted in another context
→ PROJECT_AS pressure
```

An analysis may change both granularity and context. This creates dual-operation pressure, not a licence to collapse the operations. The analyst must identify which claim belongs to which occurrence.

### 3.5 Source function versus target function

The source function is the function, role, or bounded operation of the source object that the decomposition is trying to reconstruct internally. It may be confirmed, refined, internally differentiated, partially preserved, rejected, or left underdetermined.

The target function is the new contextual function asserted by `PROJECT_AS`. It does not replace the source object’s origin type and does not inherit the source claim’s authority.

```text
source function as explanation target
≠
target function as new contextual claim
```

The same word may occur in both descriptions without establishing identity. The relevant question is whether the analysis explains the source object’s internal constitution or asserts what the retained source object does in another context.

## 4. Recontextualization Boundary

### 4.1 Recontextualization without operation change

A changed Frame may alter what becomes visible, relevant, comparable, or questionable without yet producing either `DECOMPOSE` or `PROJECT_AS`. Examples include:

- reading the same records from a later historical vantage;
- introducing a new source perspective;
- changing the analytical question;
- comparing two bounded contexts;
- presenting the object in a Reader or graph environment;
- translating terminology for another audience.

Recontextualization becomes operationally relevant only when it supports a new transformation claim. A new Frame alone is not `PROJECT_AS`; additional detail alone is not `DECOMPOSE`.

### 4.2 Mere summary versus functional projection

An analysis that seems like RETYPE may remain SUB where a new term merely summarizes internally reconstructed components. For example, calling a recurrent internal pattern a “closure cluster” does not establish a contextual target function if the term only names the reconstructed relation within the same source object.

Conversely, an analysis that seems like SUB may be RETYPE where it does not open internal structure but assigns the retained source object a role such as warning signal, coordination interface, attractor function, audit function, or frame function in another context.

The boundary therefore cannot be decided by nouns, labels, section headings, or visual layout.

### 4.3 Reader and graph boundary

A future Reader or embedded 3D graph application may expose origin types, source objects, component maps, contexts, candidate functions, Loss, operation chains, and rival interpretations. Displaying an object in a new spatial or interactive context does not itself execute `PROJECT_AS`.

```text
visual context
≠ declared target context automatically

node role in interface
≠ contextual target function automatically

interactive regrouping
≠ DECOMPOSE or PROJECT_AS automatically
```

The application may record analyst declarations and flag missing fields. It may not infer semantic target functions from geometry, proximity, colour, clustering, user interaction, or graph centrality.

## 5. Dual Operation and Invalid Collapse

### 5.1 Dual-operation rule

One inquiry may legitimately require both operations. The controlled pattern is:

```text
DECOMPOSE(X)
→ reconstruct constitutive source structure

PROJECT_AS(X or a declared derived source object)
→ assert a bounded contextual target function
```

The order may matter. A decomposition may supply the source features required for a later projection. A projection may also identify which source features need subsequent decomposition. In either direction, each link is a new testable claim.

### 5.2 Separate occurrence burdens

Each operation occurrence requires its own:

- operation identifier;
- source object and reference;
- tested claim;
- selection or target-function rule as applicable;
- source support;
- Loss;
- counterfactual sensitivity;
- result axes;
- failure, Stop, and Non-Capture possibility;
- canonical Output Class.

The records may be linked as a chain, but one record may not silently carry both operation identities. The success of one occurrence does not establish the success of the other.

### 5.3 Invalid collapse

Invalid collapse occurs where internal constitution and contextual target function are treated as one claim or where evidence for one operation is used as automatic evidence for the other.

Typical collapse patterns include:

- treating a component map as proof of a target function;
- treating a useful target function as proof that the internal decomposition is correct;
- replacing origin type with target function;
- describing recontextualization as projection without a target function;
- using one Loss account for two different operations;
- hiding a failed `DECOMPOSE` claim inside a new `PROJECT_AS` label;
- hiding an unsupported target function inside finer descriptive detail.

Invalid collapse creates at least `claim_reduction_required`, `mandatory_stop`, or `failed_transformation` pressure depending on the retained support and whether the claims can be separated.

### 5.4 Independent failure

Both operations may independently fail:

```text
DECOMPOSE admissible
+
PROJECT_AS unsupported
→ first result preserved; second fails or stops

PROJECT_AS admissible
+
DECOMPOSE unsupported
→ projection result does not repair decomposition failure

both unsupported
→ no mixed compromise claim
```

A dual-operation chain therefore requires link-specific results. There is no chain-level success that compensates for a failed link.

## 6. Anchor Object and Counterpressure

### 6.1 Minimal trajectory source

The anchor object `R-26` is a bounded review-governance trajectory already formed and decomposed in prior chapters. Its origin type remains Trajectory. The anchor supports three separate questions.

**SUB question:**

> Which subpaths, transition clusters, Non-Events, authority changes, and residues constitute or destabilize this trajectory?

This question opens internal source structure and retains the Trajectory as explanatory target.

**RETYPE question:**

> Within a declared organizational learning context, what bounded function does this retained trajectory perform as a warning, coordination, or comparison object?

This question preserves the origin type and proposes a contextual target function.

**Recontextualization question:**

> How does the same trajectory become differently legible when reviewed from a later audit Frame, without yet assigning it a target function?

This question may change context and interpretation while remaining pre-operational until a transformation claim is declared.

### 6.2 Attractor-occurrence comparison

A second bounded comparison uses an Attractor occurrence.

SUB may open the occurrence into repeated Frames, blocked alternatives, Non-Events, accumulated costs, and recurrence relations. RETYPE may project the retained occurrence or a declared trajectory form as an Attractor-function in a larger context. The repeated use of “Attractor” does not merge origin type and target function.

### 6.3 Counterpressure set

The chapter must test at least:

- a Frame change with no target function;

Local boundary results may include bounded findings such as:

These are local findings, not new canonical Output Classes and not necessarily new controlled enums. The prose may use them descriptively while the Shared Record carries the declared operation, routing, diagnostics, claim disposition, and canonical class.

### 7.2 Failure pressure

Failure pressure arises where the analysis:

- cannot identify the source object or origin type;
- claims internal structure without a granularity relation or source support;
- claims a target function without a declared target context;
- replaces origin type with target function;
- uses a new label as functional proof;
- treats mere recontextualization as an operation;
- silently mixes two operation occurrences;
- inherits success, authority, or Loss treatment across the boundary;
- uses graph structure or formal completeness as semantic proof.

### 7.3 Mandatory Stop

Mandatory Stop applies where continuation would require:

- inventing internal components or relations;
- inventing a target context or function;
- concealing an operation switch;
- keeping one record after dual-operation pressure is established;
- erasing a prior failed claim through projection;
- converting analogy or label substitution into `PROJECT_AS`;
- replacing origin type;
- inferring person properties, legitimacy, recommendation, or authority;
- crossing Source or Traceability Ceiling.

Stop preserves supported findings and prior dispositions. It does not prevent later re-entry under a new explicit operation claim and materially new basis.

### 7.4 Non-Capture

`non_capture` remains possible where:

- the prose is genuinely ambiguous between internal reconstruction and contextual function;
- the proposed context is identifiable but the target function is not;
- internal and external claims are entangled in sources that cannot be separated responsibly;
- rival operation classifications remain equally supported;
- origin-type continuity is underdetermined;
- separating the records would require invented structure.

```text
non_capture
≠ default DECOMPOSE
≠ default PROJECT_AS
≠ compromise mixed operation
≠ permission to defer origin-type integrity
```
