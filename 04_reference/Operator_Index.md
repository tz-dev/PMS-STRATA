## 1. Function and Authority

This index records how the eleven PMS Base operator types Δ–Ψ may be referenced within PMS-STRATA without being renamed, reordered, decomposed, extended, retyped, or converted into an ontology of strata. It is a control and navigation artifact. It does not replace `PMS.yaml`, the PMS paper, the current canonical Foundations prose, or the Formal Model Core.

The authority rule is:

```text
PMS.yaml
→ canonical repository-reference inventory, names, order, dependencies, and base guardrails

PMS paper
→ supporting explanatory elaboration, formal role, generative reasoning, and examples

PMS-STRATA
→ controls only what STRATA may infer, transform, or claim through COMPOSE, DECOMPOSE, and PROJECT_AS
```

`PMS.yaml` controls the current Base inventory, canonical signs and names, order, direct dependencies, organizational layers, and repository guardrails. The PMS paper supplies explanatory elaboration. The STRATA claim boundary controls only what STRATA may infer, transform, or claim from those sources; it does not revise PMS Base. Neither source makes the operator inventory complete, uniquely optimal, ontologically final, empirically self-validating, or immune to revision.

## 2. Canonical Distinctions

### 2.1 Sign, name, type, occurrence, and composite

```text
operator sign
≠
operator name
≠
operator type
≠
operator occurrence
≠
composite structure
```

- **Operator sign** is the canonical symbol used in the current PMS repository reference, such as `□`.
- **Operator name** is the canonical English label associated with that sign and type, such as `Frame`.
- **Operator type** is the abstract PMS Base function to which the sign and name refer.
- **Operator occurrence** is a concrete, reference-bound, context- or frame-bound, source-bound, and claim-bound structure reconstructed as expressing an operator function in a specific analysis.
- **Composite structure** is a selectively formed analytical object containing multiple identifiable constituents whose declared relations are constitutive of the object claimed.

[Chapter 1](../01_blocks/01_foundations.md#chapter-1-object-model-operator-type-operator-occurrence-and-composite-structure) is the primary STRATA definition site for these distinctions. The meanings, inventory, order, and dependencies of the operator types remain governed by PMS Base.

### 2.2 Meta-axiom language

The PMS paper calls Δ–Ψ **meta-axioms** and **meta-operators**. In this index, `PMS Base operator type` is the controlled term. Each type is treated as non-derivative at its own level of description within the current PMS reference. `Meta-axiom` does not mean an empirically proven law, an ontological constituent, or a proposition beyond revision.

### 2.3 Four distinct senses of composition

| Term | Meaning | Status |
|---|---|---|
| PMS dependency path | Default repository-reference relation among operator types | Base grammar |
| PMS operator composition | Formal or generative combination of operator types, often written with `∘` | Base-theory derivational representation |
| `Σ` Integration | One PMS operator type coordinating disparate or conflicting structures | Base operator |
| `COMPOSE` | STRATA operation forming a declared composite analytical object from multiple source structures | STRATA method |

These senses must not be substituted for one another.

```text
PMS operator composition
≠
Σ Integration
≠
STRATA COMPOSE
```

### 2.4 Operator-like target functions

A source object may, under `PROJECT_AS`, perform a bounded contextual function that resembles or corresponds to an operator function. The origin type remains unchanged.

```text
trajectory PROJECT_AS frame-function
≠
trajectory becomes □
```

The same rule applies to attractor-functions, asymmetry-functions, binding-functions, integration-functions, boundary functions, and other bounded higher-level functions.

### 4.2 Organizational operator layers

`PMS.yaml` additionally groups the operator types into four organizational layers:

| Layer | Canonical name | Contains | Controlled interpretation |
|---|---|---|---|
| `L1` | Early structural patterning | `Δ`, `∇`, `□`, `Λ`, `Α` | distinctions, impulses, frames, non-events, and recurrent patterns |
| `L2` | Relational asymmetry and temporality | `Ω`, `Θ` | asymmetrical relations and temporal extension |
| `L3` | Meta-structural reflexivity | `Φ`, `Χ`, `Σ` | transformation, distance, and integration |
| `L4` | Higher-order self-binding | `Ψ` | relatively stable self-binding across time and contexts |

These layers organize the current PMS reference. They are not STRATA Parts, relative levels, granularities, ontological strata, developmental ranks, or authority ranks.

```text
PMS operator layers L1–L4
≠
PATH–SUB–RETYPE–LIMITS
```

Three order representations must therefore remain distinct:

```text
direct dependency graph
≠
linear reading path
≠
organizational operator layers
```

STRATA must not infer from the dependency path or the organizational layers that:

- later operators possess greater truth or authority;
- earlier operators are lower ontological layers;
- every occurrence must instantiate the full chain;
- the path is the only possible future PMS formalization;
- a derived structure inherits the order position of the operator it resembles;
- an operator may be omitted from `PMS.yaml` dependencies because a local STRATA case appears to work without it.

## 5. Detailed Operator Entries

### 5.1 `Δ` — Difference

- **Canonical sign:** `Δ`
- **Canonical name:** `Difference`
- **German working rendering:** Differenz
- **Repository order:** 1 of 11
- **Status:** PMS Base operator type; treated as structurally basic and non-derivative at its own level of description within the current PMS repository reference
- **Canonical definition:** Minimal structural distinction enabling differentiation.
- **Canonical dependencies:** None in the current repository-reference dependency path.
- **Structures provided in `PMS.yaml`:** `boundary_formation`, `object_differentiation`, `structural_contrast`
- **Primary control sources:**
 - `PMS.yaml` → `pms_model_reference.meta_axioms[id="Δ"]`
 - supporting PMS explanatory source: `Praxeological Meta-Structure Theory.md` → §4.1 and §10.3

### Formal role

Marks or constructs a distinction through which an object, boundary, contrast, or role difference becomes structurally legible.

### Typical operator occurrences

The following are occurrence families, not additional operator types:

- a locally relevant inside/outside distinction
- a role difference made visible within a scene
- a contrast between available and unavailable action corridors

A valid occurrence remains reference-bound, context- or frame-bound, source-bound, and claim-bound. Competing typings must remain possible where the source structure supports them; they need not exist in every case. Reusing the operator name does not establish the occurrence.

### STRATA relation

- **PATH:** Differences help mark changed configurations and branch distinctions, but a difference alone is not a transition, path, or trajectory.
- **SUB:** A concrete difference-typed occurrence may be opened into the practices and relations that maintain the distinction; Δ itself is not decomposed.
- **RETYPE:** An origin-typed object may perform a bounded differentiating or boundary function only under an explicit target context; it does not become Δ.
- **LIMITS:** Additional differences must cross the Praxeological Relevance Floor and remain source-supported.

### Central non-equivalences

- Difference operator type ≠ any particular empirical difference
- difference ≠ asymmetry
- difference ≠ praxeological relevance
- additional distinction ≠ additional finding

### Must not be claimed

- that reality is ontologically composed of differences as discrete strata
- that every analyst-added distinction is praxeologically significant

### Paper-to-STRATA calibration note

The paper treats Δ as first in the proposed dependency sequence and structurally basic within PMS, while keeping the completeness and unique optimality of the full inventory open.

- that the expectation structure may be invented retrospectively without source support

### Paper-to-STRATA calibration note

The paper defines Λ through meaningful expected non-occurrence inside a frame. STRATA adds stricter source, expectation, and missing-information controls.

## 6. Operator Occurrence Control

### 6.1 Minimal occurrence declaration

The Operator Index does not create a second Transformation Record. Before a concrete PMS operator occurrence is used as a STRATA source, the later chapter or record must provide an inspectable occurrence declaration. This index does not redefine machine fields. The current `07_model/Transformation_Record.schema.json` owns formal field names, requiredness, and encoding; the declaration must identify:

- the reference object or source structure;
- the proposed operator typing;
- the relevant context or frame;
- the temporal scope where applicable;
- the source basis;
- the typing justification;
- relevant competing typings, where supported;
- and the current confidence or record status.

This declaration does not prove empirical truth. It makes the typing inspectable. Formal field names, requiredness, and encoding remain the responsibility of the current Transformation Record Schema, while operator meaning and typing constraints remain controlled by PMS Base, governing prose, and their designated Reference owners.

### 6.2 Multiple typings

One reference object or source structure may support competing typings or participate in several distinct operator occurrences. A repeated non-decision may, for example, be reconstructed as a `Λ` occurrence, participate in an `Α` occurrence, and contribute to an `Ω` structure. These are distinct analytical relations, not automatically one occurrence with three interchangeable types. Such plurality does not merge the operator types and does not license silent level mixing.

### 6.3 Occurrence identity

An occurrence remains distinct from:

- the operator sign;
- the operator name;
- the abstract operator type;
- another occurrence with the same typing;
- a composite containing the occurrence;
- a derived function that the occurrence or composite later performs.

Nominal sameness is insufficient for reference continuity.

## 9. Cross-Operator Controls

### 9.1 Weighting does not change dependency

An occurrence or composite may be described as `Ω`-dominant, `Λ/Θ`-heavy, `Χ/Σ`-stabilized, or otherwise weighted. Such descriptions concern local analytical load.

```text
operator weighting
≠
operator reordering
≠
dependency revision
```

### 9.2 Enabling is not establishing

A PMS operator may enable a later structure without being sufficient to establish it. Examples:

- `Θ` enables temporal ordering but does not establish a path or trajectory;
- `Α` enables recurrent stabilization but does not establish path dependence;
- `Ω` makes responsibility gradients structurally legible but does not establish a moral or legal responsibility verdict;
- `Χ` enables reflective distance but does not establish maturity;
- `Σ` enables integration but does not establish truth, completeness, or harmony;
- `Ψ` enables stable self-relation but does not establish consciousness or permanent identity.

### 9.3 Generativity is not exhaustive capture

Successful derivation or translation into Δ–Ψ may demonstrate formal tractability, explanatory usefulness, or internal coherence. It does not by itself demonstrate completeness, unique adequacy, empirical truth, semantic exhaustion, or superiority to rival grammars.

### 9.4 Structural analysis is not person analysis

Operator descriptions apply to scenes, enactments, roles, relations, configurations, paths, occurrences, and composites. They must not be converted into global person types, diagnoses, moral ranks, permanent identities, or irreversible labels.

### 9.5 Computational representation is bounded

Encoding operators, dependencies, or occurrences in YAML can validate declared structure and internal consistency. It does not implement praxis, prove subjective experience, establish causality, or validate a real-world application without calibration and external evaluation.
