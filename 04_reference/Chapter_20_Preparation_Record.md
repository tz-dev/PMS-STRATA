The chapter must answer this procedurally. It must not merely repeat that finer reconstruction is possible.

### 3.2 Required core claim

```text
DECOMPOSE is the controlled reconstruction of a provisionally compressed source object
as a relational organization of finer structures under declared granularity,
while retaining the source object as reference and test target.
```

This claim has seven conjunctive burdens:

1. the source object is independently identifiable;
2. the current compression and decomposition question are explicit;

4. components and component relations are both reconstructed;
5. source support and uncertainty are disclosed;
6. the coarser source function remains separately testable;

Failure of one burden cannot be compensated by strength in another.

The source function may be:

```text

partially preserved
```

These are open source-function effects, not canonical Output Classes and not a hierarchy. Preservation means that the function remains testable and its disposition remains recorded. It does not mean the function must survive.

- historical or case identity;

## 6. Preconditions

A `DECOMPOSE` occurrence requires all of the following:

1. **Identifiable source object** — the source exists independently of the proposed parts list.
2. **Bounded insufficiency question** — the current compression is under a specific claim-relevant pressure.
3. **Expected PraxisPurchase** — a stated difference could change a warranted reconstruction.
4. **Source route** — finer distinctions are not invented from the coarse label.
5. **Declared granularity change** — source and target granularities and added distinctions are stated.
6. **Reference preservation plan** — the same source object remains reconstructible.
7. **Source-function test** — the coarser function is retained as an explicit evaluation object.
8. **Loss and Stop readiness** — uncertainty, exclusion, irrecoverability, and stopping conditions can be recorded.

These are preconditions for executing the operation, not proof of success.

```text
preconditions satisfied
≠ components supported
≠ operation admissible automatically
```

A failed precondition may route to:

- no operation;
- claim reformulation;
- source acquisition;
- Optional Stop;
- `mandatory_stop` where continuation would be inadmissible;
- `failed_transformation` where a tested operation claim fails;
- `non_capture` where bounded reconstruction remains unavailable without protecting a stronger claim.

The exact canonical class depends on the delimited tested claim and must not be selected lexically.

## 8. The Decomposition Question

### 8.1 Required form

Every occurrence needs one precise leading question. It should identify:

- which source object is being opened;
- which finer distinction family is at issue;
- which current claim or function may change;
- which source route can support the inquiry;
- what would count as no gain;
- what would trigger Stop.

### 8.2 Valid question forms

Examples include:

- Which source-supported practices and relations reproduce this concrete Frame-typed occurrence?
- Which role, access, exposure, and cost relations constitute this declared Asymmetry-typed occurrence?
- Which expected-window failures and linked non-decisions form this compressed Non-Event structure?
- Which already-traversed transitions and internal temporal relations support this declared Trajectory?

These are procedural templates, not findings.

### 8.3 Invalid question forms

Invalid or incomplete prompts include:

- “What is inside it?”
- “Give more detail.”
- “What is the operator made of?”
- “Find the real micro-level cause.”
- “Which hidden components prove the coarse claim?”
- “What target function does this object perform elsewhere?”

The first two lack a bounded claim relation. The third attempts operator-type decomposition. The fourth presupposes truth hierarchy and causal depth. The fifth immunizes the source claim. The sixth belongs to `PROJECT_AS`.

```text
thematic curiosity
≠ decomposition question
```

The finer reconstruction must distinguish at least:

- direct support;
- indirect reconstruction;
- uncertain attribution;
- missing intermediate structure;
- rival internal model;
- inaccessible area;
- unsupported inference.

These are support descriptions, not Output Classes.

### 10.2 Precision ceiling

```text
semantic precision
≤ source precision
```

A finer vocabulary cannot create finer evidence. Where sources support only aggregate roles, the record may not invent exact local sequences. Where sources support event timing but not relation structure, the record must not infer mechanism. Where source categories are coarse, detailed operator typing remains provisional or unavailable.

### 10.3 Plausibility versus support

A plausible internal model may:

- guide source search;
- function as a rival model;

- expose what remains unknown.

It may not be entered as an established component model merely because it is coherent.

```text
plausible internal model
≠ source-supported decomposition
```

### 10.4 Competing models

When multiple internal models fit available sources, the operation may retain:

- segmented support;
- partially overlapping reconstructions;
- explicit rival models;
- bounded underdetermination;
- Non-Capture.

The chapter must not force a single internal model merely to complete the Record.

## 11. Component Identification

### 11.1 Component criteria

An actual operation-level component must have:

1. a declared relation to the same source object;
2. source support;
3. a role in carrying, disturbing, limiting, reproducing, or testing the coarser reconstruction;
4. placement within the finer relation model;
5. a bounded claim about what its inclusion changes.

### 11.2 Eligible component forms

Components may be:

- operator-typed occurrences;
- local configurations;
- subevents;
- structured Non-Events;
- transitions;
- roles;
- access, resource, cost, or exposure relations;
- subpaths;
- recurrent reproduction practices;
- thresholds or conditional arrangements;
- temporally distributed structures.

### 11.3 Carrying, disturbing, replaceable

The operation must permit at least three open functional roles:

```text
carrying component
→ supports or reproduces the coarser function

disturbing component
→ weakens, contradicts, limits, or differentiates it

replaceable component
→ participates without being necessary for persistence
```

These are local analytical roles, not universal component types or Output Classes.

### 11.4 Anti-causal and anti-essentialist boundary

Participation does not establish:

- necessity;
- sufficiency;
- causal priority;
- fundamentality;
- final constituency;
- person property;
- moral responsibility;
- intervention authority.

The generic Chapter-20 procedure records relations and support. It does not automatically prove causality.

## 14. Source-Function Testing

### 14.1 Separate test axis

The source or coarser function remains an explicit test target. The operation may yield the following open effects:

- refined;
- internally differentiated;
- partially preserved;
- rejected;

Preservation requires that the source function can be evaluated after decomposition. It does not require retention.



### 14.4 Confirmation without higher authority

A confirmed coarse function receives no automatic increase in truth, generality, causality, authority, or permanence. The operation confirms only what its sources, Frame, granularity, time, and claim ceiling support.

## 17. Non-Invertibility

The chapter must preserve:

```text
DECOMPOSE(COMPOSE(X))
≠ X
```

Reasons include:

- the prior composition selected and compressed material;
- some distinctions were excluded or became irrecoverable;
- later decomposition uses a new question and selection rule;
- later sources may reveal structures unavailable during composition;
- competing internal models may remain;
- source categories may not support reconstruction of former local distinctions;
- historical alternatives may no longer be recoverable.

The result must therefore record lineage and loss rather than claim restoration.

A reverse-direction chain requires a new operation occurrence and new testable claim. No operation erases prior Loss or failure.

## 19. Stop and Non-Capture

### 19.1 Optional Stop

Optional Stop is available when:

- the coarse reconstruction already suffices for the bounded claim;
- further differentiation is unnecessary;
- a valid resolution-neutral result has been reached and no new question warrants continuation;
- source acquisition is possible but not needed for the current claim.

Optional Stop is a methodological choice, not a canonical Output Class.

### 19.2 Mandatory Stop

`mandatory_stop` may be required when:

- further differentiation falls below the Relevance Floor;
- source precision no longer carries the finer terminology;
- reference continuity is lost;
- the source function can no longer be evaluated;
- continuation only displaces a counterexample;
- the claim or authority ceiling would be exceeded;
- the operation would become operator-type decomposition, new PATH, or unmarked `PROJECT_AS`.

### 19.3 Non-Capture

`non_capture` remains available where:

- competing internal models cannot be responsibly adjudicated;
- critical intermediate relations are inaccessible;
- the source object cannot be reconstructed at the proposed granularity without decisive distortion;
- available sources leave the operation materially underdetermined;
- every admissible decomposition would destroy a constitutive relation.

Non-Capture must not rescue:

- an unsupported source function;
- an invalid decomposition claim;
- a prior failed claim;
- a claim that requires reduction;
- an authority-bearing conclusion.

## 22. Operation Confusion Boundaries

### 22.1 DECOMPOSE versus description

```text
more wording or examples
≠ finer relational reconstruction
```

A valid operation needs changed distinctions, components, relations, source support, and a tested source function.

### 22.2 DECOMPOSE versus atomization

```text
smaller fragments
≠ functional components
≠ relational decomposition
```

The source object and relations must remain reconstructible.

### 22.3 DECOMPOSE versus new PATH

Opening an already declared Path into its traversed transitions and internal temporal relations may be `DECOMPOSE`. Selecting different source events, a different endpoint, or a different formation rule creates a new Path object and requires `COMPOSE`.

### 22.4 DECOMPOSE versus PROJECT_AS

A finer reconstruction of the same source object remains `DECOMPOSE`. Assigning a bounded function in another target context requires a separate `PROJECT_AS` occurrence, even when finer source traces support it.

### 22.5 DECOMPOSE versus operator-type decomposition

Concrete Frame-, Attractor-, Asymmetry-, Non-Event-, or Binding-typed occurrences may be opened. `□`, `Α`, `Ω`, `Λ`, `Ψ`, or any other Δ–Ψ type may not be treated as a material composite.

Chapter 20 must prepare, but not exhaust, the component counterfactual burden later expanded in Chapter 27.

- Would a relevant change in a relation alter the source-function effect?

- Is the internal model insensitive to too many source changes?

The generic procedure uses these questions to test constitutive load and overelasticity. It must not infer causal necessity from a thought experiment alone.
