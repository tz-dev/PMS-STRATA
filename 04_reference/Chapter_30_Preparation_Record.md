## 5. Complete Operation Architecture

### 5.1 Definition

The canonical definition to be operationalized is:

```text
PROJECT_AS is the controlled projection of an origin-typed source object
as a bounded function within a declared target context.
```

The operation adds a tested relation. It neither replaces the source object nor changes its origin type.

### 5.2 Minimal signature

```text
PROJECT_AS:
(X_g, T_o, C_t)
→
(F_t, g', J, L, V)
```

| Symbol | Role | Boundary |
|---|---|---|
| `X_g` | source object at relative source level `g` | must be identifiable before projection |
| `T_o` | origin type | remains visible and revisable only through source-side evidence |
| `C_t` | target context | cannot be inferred from function label alone |
| `F_t` | bounded target function | relational, not intrinsic type replacement |
| `g'` | relative target level | local relation, not ontological rank |
| `J` | projection justification | source- and target-specific, not rhetorical fit |
| `L` | canonical Loss plus separate visibility disclosure | exactly five Loss fields; no schema expansion |
| `V` | validity scope | context, time, roles, level, transfer, and Claim Ceiling |

The signature is not a formula of causal law and does not guarantee that an output tuple is warranted whenever inputs are present.

### 5.3 Preconditions

The operation cannot begin without:

- an identifiable source object and source record;
- a declared origin type and source reference;
- source and target coordinates;
- a specific target context and function;
- an expected praxis difference;
- a candidate constitutive source trace;
- a bounded Claim Scope and Claim Ceiling;
- sources sufficient to test the proposed relation;
- alternatives, Stop, and Non-Capture availability.

Failure of a precondition is not repaired by a persuasive label or by later family-specific vocabulary.

## 7. Justification and Expected Praxis Difference

Justification must answer four questions:

1. Why is a distinct target function analytically needed in this target context?
2. Which source features are proposed to carry it?
3. What target-side praxis difference follows if the function is warranted?
4. Which rival function or no-projection account remains plausible?

The expected praxis difference must name a change in at least one warranted dimension such as action corridor, role, access, cost, exposure, expectation, binding, alternative, temporal ordering, interpretation, integration, or Stop condition. “The source matters,” “the history is relevant,” “the label fits,” or “the diagram becomes clearer” is insufficient.

## 8. Constitutive Source Trace and Counterfactual Sensitivity

### 8.1 Constitutive Source Trace

The trace must distinguish:

```yaml
constitutive_source_trace:
  load_bearing_features:
  modulating_features:
  compressed_features:
  excluded_features:
  uncertain_relations:
  source_pointers:
```

The first four categories implement the Structure. `uncertain_relations` and `source_pointers` make existing uncertainty and evidence routes visible without becoming new canonical Loss fields or replacing substantive trace with citation.

```text
citation or link
≠ constitutive source trace
```

### 8.2 Load-bearing versus modulating

A load-bearing feature must be capable of changing, weakening, or defeating the function claim when materially altered. A modulating feature changes degree, reach, or form without alone constituting the function. Merely foregrounded features may be neither.

### 8.3 Counterfactual Sensitivity

The mandatory question is:

> Would a relevant change in the source structure alter the target-function claim?

The Structure’s local sensitivity descriptions may be used as open operation findings:

```text
strongly sensitive
partially sensitive
weakly sensitive
insensitive
underdetermined
not testable
```

They are not canonical Output Classes, confidence scores, causal strengths, or automatic routes. “Insensitive” creates failure or reduction pressure only after the complete claim and alternatives are assessed; “not testable” may require Stop, reduction, or Non-Capture depending on why testing is unavailable.

### 8.4 Same-source context contrast

## 9. Validity Scope, Visibility, Loss, and Alternatives

### 9.1 Validity scope

`V` must bound:

- target context and target object or scene;
- relevant time span and termination condition;
- relative target level and granularity;
- roles and relations;
- praxis dimensions affected;
- transferability, if any;
- Claim Scope and Claim Ceiling;
- re-entry trigger.

A local frame-function is not an all-context historical truth.

### 9.2 Projection visibility versus canonical Loss

The Structure §30.10 wording is controlled by the locked canonical Loss contract.

```yaml

  foregrounded:
  backgrounded:

loss:
  preserved:
  compressed:
  excluded:
  uncertain:
  irrecoverable:
```

`foregrounded` and `backgrounded` describe target-account visibility. They do not enlarge canonical Loss, replace `compressed` or `excluded`, or imply that backgrounded material is lost. Every actual Record must retain exactly the five canonical Loss fields.

### 9.3 Alternatives

At minimum, the operation must represent:

- one rival target function;
- the no-projection option;
- recontextualization-only where plausible;
- a rival `COMPOSE` or `DECOMPOSE` claim where the operation boundary is pressured;
- Non-Capture where responsible discrimination is unavailable.

Alternatives are not decorative. A more parsimonious no-projection account may defeat or reduce the candidate even when the target label is meaningful.
