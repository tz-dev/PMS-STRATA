## 1. Review question

The review asks where Chapters 33–35 should make their PMS basis more visible without turning RETYPE into a symbol catalogue, repeating PATH or SUB, or converting contextual target functions into PMS operator identities.

The governing test remains:

> Where a recurrent form, relational composite, weighting relation, or profile is used as a RETYPE source, does the prose show which concrete PMS operator occurrences and relations are already warranted, which of them carry the source object or target-function claim, and how material variation in those occurrences or relations would change the claim?

The desired repair is not:

```text
more Δ–Ψ symbols
```

It is:

```text
more reconstructible occurrence-level load
```

The review therefore distinguishes three burdens:

1. **source formation:** which already warranted PMS occurrences and relations form the source object;
2. **target-function correspondence:** which bounded aspect of PMS operator work the target function resembles or performs without becoming that operator;
3. **sensitivity and Loss:** which concrete occurrence relation is varied, preserved, compressed, excluded, uncertain, or irrecoverable.

## 2. Shared conservative patch principle

### Add only claim-bearing operator anchors

An operator reference is warranted only where it does at least one of the following:

- identifies an already warranted source occurrence or dependency;
- distinguishes constitutive from variable, background, uncertain, or incompatible source load;
- explains a source object’s formation through an existing `COMPOSE` or PATH Record;
- identifies the bounded PMS function dimension invoked by an operator-like target function;
- supplies a concrete occurrence-level counterfactual variation;
- discloses claim-relevant operator loss through the existing five canonical Loss fields;
- prevents an emergent, profile, or macrofunction label from replacing its source relation map.

### Do not add

- decorative Δ–Ψ inventories;
- one universal operator formula for recurrent forms, composites, or profiles;
- an implication that every case instantiates the same operator bundle;
- a numerical operator score or weighting vector;
- new operator dependencies, reordered dependencies, or a new primitive;
- a new `operator_trace` field, Rule, audit stage, Output Class, or routing path;
- repeated PATH or SUB derivations inside RETYPE;
- operator typing inferred from the desired target function;
- a requirement to foreground source operators that are immaterial to the tested claim.

### Use existing prose and record positions

The later patch should continue to use:

```text
source_reference
source_basis
origin_type
component or trajectory references
relation_map
constitutive_source_trace
counterfactual_sensitivity
loss.preserved / compressed / excluded / uncertain / irrecoverable
```

No schema expansion is required.

# 3. Chapter 33 — Recurrent Trajectory Form as Attractor-Function

## Overall assessment

Chapter 33 is conceptually strong and already protects the decisive negative boundaries:

```text
recurrent form
≠ one Trajectory
≠ PMS Attractor operator
≠ recurrence count
≠ causal law
≠ person or group type
```

It also contains substantial source-carrier language: Frames, Non-Events, costs, Bindings, role relations, temporal sequence, reproduction pathways, and countervailing interruption. The missing element is not more general Attractor theory. It is a more explicit bridge between those ordinary-language carriers and the **already warranted PMS occurrence relations** in the linked source Trajectories.

Relative patch need: **moderate and local**.

## Necessary additions

### 33.1 — Basic Claim / bounded Attractor work

Add one compact positive correspondence statement:

- the target function concerns a bounded subset of Attractor-like work: stabilization of transition accessibility, friction, expectation, role recurrence, repair/exit structure, or continuation cost;
- this does not establish an `Α` occurrence in the target and does not transfer the full semantics or dependencies of `Α` to the recurrent-form composite;
- the source-side carriers must remain independently warranted before this target correspondence is tested.

Suggested distinction:

```text
bounded dynamic attractor-function
→ contextual transition-stabilizing work

bounded dynamic attractor-function
≠ source object becomes Α
≠ full Α semantics inherited
```

### 33.2 — Recurrent-form source construction

Add a conditional occurrence-level comparability requirement:

> Where the source Trajectories are PMS-derived, the comparison coordinates should identify which claim-relevant operator occurrences or relations recur, vary, oppose, or remain unavailable across the linked PATH Records.

The chapter should not re-prove each Trajectory. It should reference the locked source Records and make reconstructible, where material:

- recurring `□`-conditioned entry or relevance boundaries;
- recurring `Λ` Non-Event relations;
- recurring `Α` stabilization or low-friction relations;
- recurring `Ω` exposure, cost, access, or exit gradients;
- recurring `Θ` order, delay, persistence, or phase relation;
- recurring `Ψ` continuity or breach-cost relations;
- countervailing `Φ`, `Χ`, or `Σ` occurrences where they interrupt or redirect the form.

This list is illustrative. Only source-supported relations enter.

Suggested distinction:

```text
same operator label across Trajectories
≠ comparable occurrence relation
```

### 33.5 — Constitutive Repetition and Source Load

The current five-way distinction—constitutive, variable, background, uncertain, incompatible—is already excellent. Add one sentence making it explicitly applicable to operator occurrence relations:

- an operator occurrence may be constitutive in one recurrent-form claim, variable or background in another, and incompatible in a third;
- classification concerns the concrete occurrence relation, not the abstract operator type;
- canonical dependencies remain preserved even when practical load differs across phases or Trajectories.

The existing carrier list should be tightened by requiring that terms such as Non-Event, Asymmetry, Binding, Frame, or Attractor refer back to source-supported occurrence typing where such typing has already been established.

No universal recurrent-form formula should be inserted.

### 33.6 — Attractor Load

Add one source-to-target trace pattern that begins with concrete occurrence relations rather than the recurrent-form label alone:

```text
claim-relevant occurrence relations across T1 ... Tn
→ discriminating recurrent-form composite R
→ documented persistence, transmission, institutionalization, or reactivation pathway
→ bounded later-path difference in D
```

The patch should explicitly preserve the distinction between:

- **source carrier:** the PMS occurrence relation reconstructed in the source Trajectories;
- **derived source form:** `R`;
- **target function:** bounded dynamic attractor-function in `D`.

These three levels must not collapse into one `Α` claim.

### 33.9 — Counterfactual Attractor Test

Add operator-occurrence examples to the already complete variation matrix:

- replace a recurrent supported `Λ` non-repair relation with timely repair;
- remove or redistribute a recurring `Ω` exposure or exit-cost gradient;
- alter a constitutive `Θ` order, delay, persistence, or phase relation;
- interrupt a recurring `Ψ` continuity relation;
- introduce a source-supported `Χ` interruption or `Σ` repair relation where it would break the recurrent form;
- change a `□` entry condition or `Φ` recontextualization where the recurrent relation depends on it.

The abstract operator definition is never varied. Only the concrete occurrence or relation is changed.

## Useful but non-essential addition

### 33.3 or 33.6 — one compact operation-chain illustration

```text
independently warranted PMS-structured Trajectories
→ COMPOSE under declared comparison coordinates
→ derived recurrent-form composite R

R
→ PROJECT_AS
→ bounded dynamic attractor-function in D
```

This should remain a visibility aid, not a second derivation of PATH or `COMPOSE`.

## Do not change

- three independent warrant layers;
- target-independent source selection;
- dynamic/static claim separation;
- Pattern Threshold and anti-count rule;
- anti-determinism, anti-probability, and anti-person/group typing;
- present-condition, common-Frame, independent-regeneration, static-only, motif, and no-projection alternatives;
- localized failure and canonical routing distinctions.

# 4. Chapter 34 — Composite Structures as Higher-Level Functions

## Overall assessment

Chapter 34 is already strongly PMS-specific in §§34.2–34.6. It separately treats bounded boundary-, attractor-, asymmetry/access-, binding-, and integration-functions and repeatedly protects:

```text
operator-like function
≠ operator identity
≠ new primitive
```

Its source packet also requires components, boundaries, relation map, countervailing relations, uncertainty, and inherited Loss. The principal opportunity is therefore not to add more symbols to the five family sections. It is to make the **generic source-composite and emergence grammar** explicitly preserve occurrence typing and dependencies across those families.

Relative patch need: **light and local**.

## Necessary additions

### 34.1 — Source Composite and generic family claim

Add one conditional requirement under the existing component-and-relation Source Trace:

- where components are PMS operator-typed occurrences, each component remains linked to its occurrence Record, source Frame, role, temporal position, uncertainty, and relevant canonical dependency context;
- the relation map states which occurrence relations coordinate, reinforce, oppose, substitute, delay, repair, or transfer load;
- the target-function candidate cannot supply missing source typing.

Suggested distinction:

```text
operator-typed component inventory
≠ operator-relation topology

operator-relation topology
≠ higher-level function automatically
```

No new fields are required; the obligation fits the existing component references and relation map.

### 34.2–34.6 — family-specific bounded function correspondence

The five family sections already contain the correct PMS vocabulary. Add only a short common clarification, preferably once in §34.1 or §34.7 and cross-applied:

- a boundary-function names bounded `□`-like separation work;
- an attractor-function names bounded `Α`-like stabilization work;
- an asymmetry/access function names bounded `Ω`-like gradient and corridor work;
- a binding-function names bounded `Ψ`-like continuity and breach/exit work;
- an integration-function names bounded `Σ`-like coordination or repair work.

In every case:

```text
bounded function correspondence
≠ operator occurrence identity
≠ complete operator semantics
≠ dependency inheritance by the composite
```

This prevents purely generic macrofunction language while avoiding repeated operator definitions.

### 34.7 — Emergent Function

Add one occurrence-level emergence sentence:

> Composite-level visibility is admissible only where the emergent target difference remains reconstructible through the concrete component occurrences, their relation topology, countervailing relations, and the exact Loss introduced by source formation and projection.

Where PMS-typed components are material, the emergence claim must show which relation among their occurrences is absent at the isolated-component level and becomes visible only at the composite level.

Suggested distinction:

```text
newly visible relation at composite level
≠ source-free novelty
≠ new operator
```

### 34.8 — Aggregation versus Functional Formation

Add a compact operator-sensitive test:

- if the same component occurrence types are present but coordination, dependency, sequence, repair, or load-transfer relations are disrupted, does the claimed function remain?
- if yes, the relation map may not be constitutive;
- if no, the change may support relational load without proving causal monopoly.

This deepens the existing count-versus-formation boundary without adding another audit route.

### 34.10 — Counterfactual Higher-Level Function Test

The current ten-part test is already comprehensive. Add only one interpretive rule:

> When a component is PMS operator-typed, variation should alter or remove the concrete occurrence or its relation while preserving the abstract operator definition and the canonical grammar.

Relevant examples can remain limited to the family under test; no full Δ–Ψ matrix is needed.

## Useful but non-essential addition

### 34.1 or 34.11 — one explicit two-record chain

```text
warranted local operator occurrences
→ COMPOSE
→ relational composite Q

Q
→ PROJECT_AS
→ bounded higher-level function in H
```

The chain is especially useful for the distributed-asymmetry pressure object because it makes clear that successful `COMPOSE` does not establish successful `PROJECT_AS`.

## Do not change

- the independent source-composite requirement;
- component removal, substitution, relation disruption, subset sufficiency, rival Frame, internal conflict, and missingness pressure;
- descriptive aggregation as a legitimate weaker endpoint;
- separate family functions and separate claims;
- the non-ontological meaning of “higher-level” and “emergent”;
- localized failure, Claim Reduction, Mandatory Stop, Non-Capture, and authority prohibition.

A broad re-anchoring patch would be redundant and intrusive. Only two small clarifications are warranted.

Relative patch need: **minimal and clarifying**.

## Necessary additions

### 35.1–35.2 — invoked-occurrence scope

Clarify once that the source packet lists **only operator occurrences invoked by the weighting claim**, plus material countervailing or uncertain occurrences. It does not require a complete Δ–Ψ census and does not treat absent operators as zero-valued weights.

Suggested distinction:

```text
occurrence not invoked or not source-supported
≠ zero weight
≠ absent operator function in every sense
```

This prevents the illustrative occurrence map from being read as a universal profile template.

### 35.5 and 35.9 — profile label versus load-bearing occurrence relation

Add one compact completion question:

> Can the profile and projected function be reconstructed from the declared occurrence and relation packet if the profile label is removed?

If not, the label is carrying work that belongs to the Source Trace.

Suggested distinction:

```text
profile label removed
+ source relation still reconstructible
→ label may be acceptable compression

profile label removed
+ claim relation disappears
→ possible profile or projection label substitution
```

This fits the existing anti-inflation and counterfactual architecture.

## Useful but non-essential addition
