## 2. Reference Function and Non-Goals

The Admissibility Band is a relational operating range for a declared transformation occurrence and claim. It is not an interval measured by one variable.

```text
Praxeological Relevance Floor
─────────────────────────────
admissible transformation range
─────────────────────────────
Praxeological Traceability Ceiling
```

Below the lower boundary lies:

```text
distinction without praxeological purchase
```

Above the upper boundary lies:

```text
abstraction without traceable load
```

The diagram is topological and procedural, not metric. The Floor and Ceiling test different failure modes. Passing them does not by itself establish full admissibility.
Canonical separations:

```text
relational operating range
≠
metric interval

passing Floor and Ceiling
≠
full admissibility

band position
≠
canonical output class

formal completeness
≠
substantive admissibility
```

## 3. Admissibility Assessment Object

Admissibility is assessed for a declared analytical occurrence, not for an object in the abstract.

The full assessment object includes:

```text
operation occurrence T
+
source or reference object X
+
transformation context C
+
tested claim Q
+
source basis S
```

The compact notation retained from the architecture is:

```text
Admissible(T, X, C)
```

The compact notation does not erase the claim or source basis. It is a shorthand for a richer record-bound assessment.

```text
compact notation
≠
complete proof calculus
```

| Assessment element | Required declaration | Failure if absent | Primary handoff |
| --- | --- | --- | --- |
| Operation occurrence | Exactly one of `COMPOSE`, `DECOMPOSE`, `PROJECT_AS` for the tested occurrence | operation identity cannot be audited | `04_reference/Transformation_Operation_Index.md` |
| Source object | object, occurrence, composite, or origin-typed source | source trace and type duties become indeterminate | Chapters 1, 4, and 7 |
| Reference object | the object whose continuity is at stake | DECOMPOSE may drift to a different object; COMPOSE may hide source replacement | Chapters 5, 20, and 47 |
| Transformation context | frame, granularity, relative level, temporal scope, target context where applicable | context and level changes become unmarked | Chapters 2, 5, and 7 |
| Tested claim | claim type, reach, and current wording | the result cannot be classified or reduced | `04_reference/Claim_Type_Table.md` |
| Source basis | direct support, inference, gaps, and limits | Source Ceiling and TraceableLoad cannot be tested | Chapters 45 and 49 |

The same source object may support different results under different operation occurrences or claims. No object receives a global admissibility status.

```text
admissible operation occurrence
≠
globally admissible object
```

## 5. Praxeological Relevance Floor

The **Praxeological Relevance Floor** is the lower boundary below which an added distinction, refinement, composition, or functional assertion creates no additional warranted praxis finding.

Canonical formulation:

> **Below the Praxeological Relevance Floor, additional resolution is not an additional praxis finding. It is distinction without praxeological purchase.**

The Floor does not ask whether an analyst can state more detail. It asks whether the added structure changes a warranted reconstruction.

| Praxis dimension | Changed-reconstruction question | Possible evidence | What does not suffice |
| --- | --- | --- | --- |
| Action corridors | Does the distinction change what continuations were open, closed, delayed, or costly? | branch records, constraints, commitments | more labels for the same corridor |
| Costs and exposure | Does it change who bears cost, risk, delay, or vulnerability? | distributional records, timing, asymmetry | unlocated generic risk |
| Roles and asymmetries | Does it alter role structure, capacity, obligation, or exposure? | relational evidence and frame | moral ranking |
| Expectations and Non-Events | Does it change the evidenced expectation structure or meaningful non-realization? | expectation and non-occurrence record | missing data alone |
| Temporality | Does order, duration, delay, or irreversibility change the claim? | time-bounded sequence and transition evidence | chronology without structural load |
| Bindings and commitments | Does it alter obligations, persistence, or reachable alternatives? | commitment and continuation evidence | psychological diagnosis |
| Path or trajectory | Does it change path formation, branch closure, sedimentation, or dependence? | ordered transitions and historical load | post hoc narrative |
| Function | Does it alter the source or target function warranted in context? | source-feature dependency | analogy or label substitution |
| Claim ceiling | Does it permit or require a different assertion? | changed source, context, or counterfactual result | stylistic rephrasing |
| Stop or countercase | Does it reveal a new failure, rival, loss, or stop condition? | countercase and loss record | complexity alone |

Praxeological relevance is not equivalent to actionability. Irreversible, uncontrollable, or non-intervention-ready structure can still change a warranted praxis reconstruction.

```text
PraxisPurchase
≠
action recommendation
```

## 6. Changed-Reconstruction Test

The Changed-Reconstruction Test operationalizes the Relevance Floor.

Core question:

```text
Which warranted reconstruction changes,
and what becomes different because of the added distinction?
```

A valid answer identifies both the changed reconstruction and the source support for the change.

| Test result | Meaning | Claim consequence | Possible output interaction |
| --- | --- | --- | --- |
| changed reconstruction | the added distinction alters a warranted praxis relation | retain or refine the tested claim | `admissible`, bounded, provisional, partial, or another class depending on remaining gates |
| no changed reconstruction after a valid test | the refinement is permitted but adds no praxis finding | retain prior warranted reconstruction; reject the gain claim | `resolution_neutral` |
| difference asserted but not source-supported | the alleged gain exceeds the source basis | reduce or fail the claim | `claim_reduction_required`, `failed_transformation`, or `mandatory_stop` |
| difference cannot be discriminated | calibration or source limits prevent decision | mark provisional, partial, or capture limit | `admissible_but_provisional`, `partially_admissible`, or `non_capture` |
| continued detail without purchase | further refinement is unnecessary or becomes inadmissible | stop continuation | optional stop or `mandatory_stop` depending on the condition |

A neutral result is not a failed test. An unsupported refinement is not a neutral result.

```text
valid resolution test with no changed reconstruction
→ resolution-neutral result
→ resolution_neutral

unsupported refinement
≠
resolution neutrality
```

## 7. Resolution Gain, Neutrality, and Lower Stop

Resolution is one context in which the Relevance Floor is especially visible.

The tested claim is ordinarily a **resolution-gain claim**. Possible local results include:

- resolution gain;
- resolution-neutral result;
- resolution drift;
- resolution escape;
- unsupported refinement;
- Non-Capture.

```text
resolution-neutral result
≠
claim reduction
```

Resolution neutrality records the outcome of a valid comparison. It is not a weaker claim type on a universal claim ladder.

| Resolution condition | Local result | Continuation rule | Canonical handoff |
| --- | --- | --- | --- |
| finer reconstruction changes warranted praxis structure | resolution gain | continue only as required by the claim | classify under all remaining gates |
| finer reconstruction is valid but changes no warranted reconstruction | resolution-neutral result | further identical refinement is unnecessary | `resolution_neutral` |
| detail grows faster than discrimination or source support | resolution drift | stop or fail the attempted refinement | `mandatory_stop` or `failed_transformation` |
| challenged claim is moved to finer resolution without being answered | resolution escape | record anti-immunization failure | `mandatory_stop` or `failed_transformation` |
| source does not support finer components or relations | unsupported refinement | do not classify as neutral | `failed_transformation` or `mandatory_stop` |
| no adequate resolution remains without distortion | granularity Non-Capture | state limiting condition and re-entry requirement | `non_capture` |

Optional stop is appropriate when more refinement could be admissible but is unnecessary for the current claim. Mandatory stop applies when continuation would cross a binding boundary.

## 8. Praxeological Traceability Ceiling

The **Praxeological Traceability Ceiling** is the upper boundary beyond which a transformation no longer carries reconstructible structural load from its source objects.

Canonical formulation:

> **Above the Praxeological Traceability Ceiling, abstraction no longer carries reconstructible praxis load. It becomes a label without traceable source structure.**

The Ceiling is not limited to large-scale composition. In DECOMPOSE, it may appear as fragmentation whose details no longer reconstruct the same source object or bear on its coarser function.
Central counterfactual question:

```text
Would a relevant change in a declared load-bearing source structure
alter the composite, reconstruction, or target function?
```

If the result remains fixed regardless of relevant source change, its source dependency is doubtful.

| Ceiling signal | COMPOSE form | DECOMPOSE form | PROJECT_AS form |
| --- | --- | --- | --- |
| source-indifference | same composite label despite changed source configuration | same micro-story despite changed source object | same target function for materially different origins |
| hidden heterogeneity | differences compressed without disclosure | components treated as homogeneous or final | source features flattened into one target label |
| reference loss | source path or occurrence no longer reconstructible | finer account shifts to a different object | origin object disappears behind target function |
| temporal loss | order and sedimentation erased | internal process detached from source temporality | target function ignores constitutive temporal load |
| counterfactual insensitivity | turning point removal changes nothing | component removal changes nothing despite constitutive claim | load-bearing source change leaves function unchanged |
| loss concealment | compression presented as total preservation | uncertainty converted to component certainty | excluded source features not declared |

## 9. Traceable Load and Constitutive Source Trace

`TraceableLoad` is the preserved, reconstructible source burden carried by the result. It is more than citation and less than lossless reproduction.

A sufficient trace normally identifies:
- the relevant source object or objects;
- load-bearing features and relations;
- modulating features where applicable;
- constitutive order and temporality where applicable;
- cost, asymmetry, expectation, non-event, and binding structure where relevant;
- source-to-result dependency;
- compressed, excluded, uncertain, and irrecoverable elements;
- the claim limitation produced by those losses.

```text
citation
≠
TraceableLoad

Constitutive Source Trace
≠
bibliography

TraceableLoad
≠
complete reproduction
```

| Trace category | Question | Required declaration | Failure risk |
| --- | --- | --- | --- |
| load-bearing | Which source features must remain for the claim to hold? | identified features and dependency | overelastic result |
| modulating | Which features change degree, direction, or expression without solely constituting the result? | role and sensitivity | false constitutiveness |
| compressed | Which acknowledged distinctions are represented at lower resolution? | compression and retained load | false completeness |
| excluded | Which available structures are intentionally outside the result? | selection rationale and claim limit | selection concealment |
| uncertain | Which relations remain unresolved? | uncertainty and claim effect | precision inflation |
| irrecoverable | Which information can no longer be reliably reconstructed? | irrecoverability and consequence | false reversibility |

## 10. Operation-Specific Ceiling Forms

| Operation | Traceability duty | Primary counterfactual | Upper-bound failure | Required loss focus |
| --- | --- | --- | --- | --- |
| `COMPOSE` | reconstruct the composite from sources, selection, ordering, formation rule, and constitutive relations | Would removal, reordering, or replacement of a load-bearing source alter the composite? | macro label persists independently of source formation | compression, exclusion, heterogeneity, irrecoverable ordering loss |
| `DECOMPOSE` | retain the same reference object while showing how finer relations bear on the coarser object or function | Would removal or change of a claimed component alter the reconstruction or tested source function? | fragmentation loses reference, function, or source-supported relation | uncertainty, selected distinctions, residual structure, source limits |
| `PROJECT_AS` | map a bounded target function to indispensable origin features without changing origin type | Would relevant source modification weaken, change, or remove the target function? | target label remains fixed across materially different origins | foregrounding, compression, excluded features, contextual limits |

The operation-specific forms do not create different Ceilings. They are different manifestations of the same traceability duty.

## 11. Type Integrity

Type Integrity prevents operations from changing the identity of their source classes or the PMS Base grammar by implication.

Required separations:

```text
operator type
≠
operator occurrence
≠
composite

origin type
≠
target function

derived object or function
≠
new PMS primitive
```

| Operation | Type-integrity duty | Typical violation | Possible result |
| --- | --- | --- | --- |
| COMPOSE | retain the declared types of sources while creating a new analytical composite | composite treated as a new operator or as lossless identity of its parts | claim reduction, failure, or mandatory stop |
| DECOMPOSE | open only concrete occurrences or composites; keep the reference object visible | PMS operator type decomposed as an empirical aggregate | failed transformation or mandatory stop |
| PROJECT_AS | preserve origin type and mark the target as a bounded contextual function | source becomes the target operator type or new primitive | failed transformation |

Type Integrity does not make every occurrence typing immutable. A source-function claim or occurrence typing may be revised by a valid DECOMPOSE.

```text
TypeIntegrity
≠
type immutability of occurrence claims
```

## 12. Reference, Functional, and Temporal Continuity

Continuity is not one undifferentiated pass/fail property. The applicable continuity duties depend on the operation and claim.

| Continuity | Core question | Pass condition | Qualified result | Failure mode |
| --- | --- | --- | --- | --- |
| Reference Continuity | Is the transformation still about the same declared object? | reference and constitutive identity remain traceable | bounded or partial reconstruction | object substitution or drift |
| Functional Continuity | Does the function remain warranted by source structure and context? | source-function or target-function dependency remains explicit | function refined, differentiated, partial, provisional, or rejected as a separate claim effect | semantic resemblance substituted for function |
| Temporal Continuity | Are order, duration, delay, sedimentation, and irreversible effects preserved where constitutive? | relevant temporal load remains reconstructible | declared compression with bounded claim | chronology or temporality silently erased |
| Type Integrity | Do source type and target function remain distinct? | origin type preserved; occurrence revisions explicit | prior typing reduced or rejected in a separate claim | type jump or primitive invention |

A valid DECOMPOSE may reject a prior source-function claim while remaining admissible as an operation.

```text
operation result: admissible decomposition
source-function effect: rejected
prior source claim: failed, withdrawn, reduced, or underdetermined
```

```text
rejected source-function claim
≠
failed DECOMPOSE transformation
```

## 13. Contextual Boundedness

Every retained claim must state where, for what, and how far it applies.

Ordinary boundedness may include:
- source frame and target context;
- granularity and relative level;
- temporal scope and validity period;
- affected roles, objects, and relations;
- claim reach and generality;
- target function and excluded functions;
- conditions for re-entry or extension.

Ordinary STRATA boundedness does not automatically produce the output class `admissible_with_bounded_claim`.

```text
ordinary contextual boundedness
≠
bounded-claim output
```

The bounded-claim class is appropriate when a material narrowing relative to the initially declared claim or an explicitly stated comparison claim is itself the decisive governance result. The comparison baseline must be record-bound rather than supplied by an unstated norm.

| Condition | Claim treatment | Typical class interaction |
| --- | --- | --- |
| ordinary declared context is sufficient | retain claim as stated | `admissible` if all other gates pass |
| materially narrower context or function is required and already tested | retain only narrowed claim | `admissible_with_bounded_claim` |
| context boundary is known but support remains materially open | retain scope and provisional qualifier separately | `admissible_but_provisional` where provisionality is primary |
| no non-arbitrary boundary can be stated | do not retain the projection or broad claim | `claim_reduction_required`, `mandatory_stop`, `failed_transformation`, or `non_capture` |

## 14. Counterfactual Sensitivity

Counterfactual Sensitivity tests whether a result bears structural load from declared source features.

```text
Counterfactual Sensitivity
≠
causal proof
≠
empirical experiment
```

The test must identify a source-grounded feature, a relevant modification, and the expected effect on the result.

| Local sensitivity result | Meaning | Permissible claim effect | Not automatic |
| --- | --- | --- | --- |
| `strongly_sensitive` | relevant change materially alters or removes the result | supports load-bearing relation within scope | causal proof |
| `partially_sensitive` | some but not all claimed aspects respond | bound, separate, or partially retain claims | `partially_admissible` without claim analysis |
| `weakly_sensitive` | result changes only marginally or under narrow conditions | reduce strength or function; mark calibration limit | failure in every case |
| `insensitive` | result remains unchanged under relevant source modification | reclassify, reduce, fail, stop, or treat as analogy | one fixed output class |
| `underdetermined` | sources do not settle the expected change | provisional, bounded, partial, or capture-limited claim | `non_capture` automatically |
| `untestable` | available sources cannot support the counterfactual | state unavailable test and limit claim | proof of failure or validity |

A support downgrade is not a claim reduction:

```text
supported
→ provisional
→ underdetermined
```

records changing support status. It does not by itself change the claim type, relation, or reach.

## 15. Source Ceiling and Inferential Distance

The **Source Ceiling** is reached when available sources no longer support additional distinctions, internal processes, precision, or rival discrimination.

```text
Source Ceiling
≠
Praxeological Relevance Floor
≠
Praxeological Traceability Ceiling
```

A result can be highly traceable but too precise for the available sources. A result can use many sources but remain source-indifferent in its transformation logic.

| Source condition | Permitted assertion | Prohibited inflation | Possible response |
| --- | --- | --- | --- |
| directly supported relation | relation within recorded scope | unrecorded universality or causality | retain under remaining gates |
| supported pattern with inferred links | explicitly inferred structural claim | presenting inference as direct observation | bounded or provisional claim |
| missing internal order | coarser object or underdetermination claim | invented sequence or mechanism | reduce, stop, or Non-Capture |
| rivals not discriminable | provisional preference, shared partial structure, or no selection | single necessary reconstruction | provisional, partial, or Non-Capture |
| source exhausted | record source limit | further formal precision | mandatory stop for unsupported continuation |

As inferential distance grows, the burden generally increases for source trace, alternatives, loss disclosure, calibration, uncertainty marking, and claim limitation. This is a burden relation, not a numeric distance score.

## 16. Calibration Limits

Calibration asks whether distinctions and thresholds discriminate relevant cases and permit countercases.

```text
formal precision
≠
calibration

calibration
≠
universal threshold
```

| Calibration state | Meaning | Claim effect | Possible output interaction |
| --- | --- | --- | --- |
| discriminating | criterion separates relevant cases and failures | retain criterion within scope | any class subject to other gates |
| calibration-open | structural form is identifiable but threshold remains unsettled | retain provisional or bounded statement | `admissible_but_provisional` or `admissible_with_bounded_claim` |
| case-dependent | threshold depends on declared context or frame | state context and comparison set | bounded or provisional result |
| non-discriminating | criterion fits positives, negatives, and rivals alike | reduce, fail, or stop | `claim_reduction_required`, `failed_transformation`, or `mandatory_stop` |
| not calibratable with present sources | no warranted threshold is available | state source/capture limit | `admissible_but_provisional` or `non_capture` depending on retained claim |

A calibration-open result does not license an unbounded claim and does not automatically determine one output class.

## 17. Selection and Canonical Loss

No STRATA transformation is selection-free.

```text
selection
≠
loss
```

Selection states what enters the transformation and according to which rule. Loss records what happens to visibility and recoverability through that selection and transformation.

| Operation | Selection duty | Typical hidden-selection risk |
| --- | --- | --- |
| COMPOSE | sources, sequence, periodization, branch points, non-events, formation rule | retrospective narrative presented as inevitable |
| DECOMPOSE | distinctions, components, relations, thresholds, reconstruction depth | chosen microstructure presented as natural or final |
| PROJECT_AS | source features, target context, target function, foregrounded relations | target label predetermines selected source features |

Canonical loss declaration:

```yaml
loss:
  preserved:
  compressed:
  excluded:
  uncertain:
  irrecoverable:
```

| Loss class | Meaning | Claim duty | Does not mean |
| --- | --- | --- | --- |
| preserved | structure remains available at the result level required by the claim | identify what and how | nothing changed |
| compressed | acknowledged structure is represented at lower resolution | state retained load and hidden detail | excluded |
| excluded | available structure is deliberately outside the result | state rationale and scope effect | irrelevant in every context |
| uncertain | status or relation is unresolved | mark uncertainty and consequence | irrecoverable |
| irrecoverable | reliable reconstruction is no longer available | limit reversibility and completeness claims | mere inconvenience |

Declared loss is not automatic failure. Hidden or claim-incompatible loss may require claim reduction, failure, mandatory stop, or Non-Capture.

## 18. Alternatives and No-Transformation

A strong transformation claim must remain criticizable through relevant alternatives.

Possible alternatives include:
- a rival COMPOSE, DECOMPOSE, or PROJECT_AS;
- a different selection or formation rule;
- a different granularity or relative level;
- a narrower claim or target function;
- a structural analogy instead of projection;
- No Transformation;
- Non-Capture;
- an external method for an external-warrant claim.

```text
preferred transformation
≠
only conceivable transformation
```

The alternative burden is proportional to the claim’s reach and inferential distance. STRATA does not require exhaustive enumeration of every logically possible alternative for a minimal local claim.

| Alternative condition | Governance meaning | Typical handoff |
| --- | --- | --- |
| one candidate provisionally preferred; material rival remains | usable result with unresolved rivalry | `admissible_but_provisional` |
| shared separable structure across rivals | retain only common or differentiated parts | `partially_admissible` |
| no warranted candidate can be selected | capture boundary remains | `non_capture` |
| no transformation is needed for the tested claim | retain the source description; no transformation claim is required | optional stop |
| only analogy is supportable | do not assert target function | `analogy_only` |

A `resolution-neutral result` requires a valid resolution comparison in which the tested resolution-gain claim produces no changed reconstruction. No-transformation necessity alone does not establish resolution neutrality.

```text
no transformation needed
≠
resolution neutrality automatically
```

## 19. Claim Ceiling

The **Claim Ceiling** is the maximum structurally and source-supported assertion—including relation, reach, precision, generality, functional scope, and dependence strength—permitted by the applicable record constraints.

It is an integrated constraint result, not an independent universal scale.
```text
source support
+
operation identity
+
type and reference integrity
+
continuity
+
context and scope
+
counterfactual load
+
calibration
+
loss
+
alternatives
+
authority boundary
→ maximum warranted assertion
```

```text
claim ceiling
≠
Source Ceiling
≠
Praxeological Traceability Ceiling
```

| Ceiling component | Constrains | Typical overclaim |
| --- | --- | --- |
| Source Ceiling | detail, precision, internal process, rival discrimination | model detail presented as source fact |
| Traceability Ceiling | source-to-result dependence and reconstructibility | generic macro or target label |
| Type Integrity | object identity and function/type distinctions | target function presented as origin type |
| Contextual Boundedness | scope, period, role, target context, transfer | local property generalized globally |
| Counterfactual Sensitivity | constitutive and functional load | source-insensitive function claim |
| Calibration | threshold and comparative discrimination | universal threshold from one case |
| Loss | completeness, reversibility, preservation | lossless or total-capture claim |
| Alternatives | necessity and uniqueness | preferred reconstruction presented as only one |
| Independent Authority Ceiling | hard prohibition rather than a claim-ceiling dimension | successful transformation presented as empirical proof, diagnosis, legitimacy judgment, or action mandate |

The Claim Ceiling is assessed subject to the independent Authority Ceiling. Authority is not a graded claim-ceiling axis and cannot be increased by structural success. A canonical output class does not raise the Claim Ceiling. A successful operation does not authorize a stronger claim than its sources and boundaries permit.

## 20. Authority Ceiling

The **Authority Ceiling** is the limit beyond which a structural transformation would illegitimately inherit or generate empirical, causal, normative, person-evaluative, legal, political, diagnostic, intervention, or application authority.

```text
claim ceiling
≠
authority ceiling
```

The Claim Ceiling limits the structurally and source-supported assertion retained in a record. The Authority Ceiling is an independent hard boundary that blocks forms of authority STRATA cannot license, regardless of structural success.

| Blocked authority inflation | Why blocked | Nearest admissible formulation |
| --- | --- | --- |
| empirical truth from structural admissibility | admissibility is a transformation-governance result | state the structural claim and external empirical burden separately |
| actual causality from Counterfactual Sensitivity | sensitivity is a source-load test, not causal identification | state structural dependency or hypothesis |
| semantic validity from formal correspondence | translation and schema fit do not establish meaning preservation | retain bounded analogy or external semantic test |
| person typing or diagnosis | output classes and operator profiles classify records, not persons | describe the bounded record or relation |
| moral, legal, or political legitimacy | STRATA has no legitimacy mandate | state the structural distinction without judgment |
| sanction or intervention entitlement | analysis does not confer action authority | handoff to an authorized external process |
| new PMS primitive from derived object or function | PMS.yaml controls the operator inventory | retain the result as derived and bounded |
| model superiority from translation success | cross-model mapping does not establish superiority | retain correspondence or analogy with rival test |

```text
successful transformation
≠
application authority

formal validity
≠
semantic or empirical validity
```

Canonical governance remains:

```yaml
governance:
  authority_inheritance: prohibited
```

## 21. Non-Compensatory Gate Architecture

Admissibility checks are not interchangeable scores. Formal elegance, detail, source quantity, or technical consistency cannot compensate for the failure of a load-bearing condition.

| Strong feature | Cannot compensate for | Reason |
| --- | --- | --- |
| high detail | no PraxisPurchase | detail without changed reconstruction lies below the Floor |
| many citations | no TraceableLoad | source mention does not establish source-to-result dependency |
| strong sources | invalid type jump | evidence does not authorize a different operation identity |
| traceable result | authority inflation | source dependence does not create normative or application authority |
| formal completeness | unbounded context or claim | all fields can be complete while the claim remains overbroad |
| counterfactual sensitivity | causal proof | load response is not causal identification |
| successful later operation | earlier failed claim | new transformation is a new testable claim |
| large composite | higher authority | analytical scale does not confer rank |

Not all failed checks imply the same final class. A failed or limited gate may yield a legitimate bounded, provisional, neutral, analogical, partial, reduction, stop, failure, or Non-Capture result.

```text
not all gates passed
≠
no legitimate methodological result
```

## 22. Ordered Admissibility Audit

The audit order prevents later formal or interpretive success from hiding an earlier identity or boundary failure.

| Order | Audit stage | Required question | Record consequence if unresolved |
| --- | --- | --- | --- |
| 1 | Source and Claim Entry | What source, reference object, claim, scope, coordinates, and source basis are being tested? | no unqualified result |
| 2 | Operation Classification | Is this exactly one occurrence of COMPOSE, DECOMPOSE, or PROJECT_AS, or is a separate operation chain required? | reclassify, separate records, or fail the attempted operation |
| 3 | Praxeological Relevance Floor | What warranted reconstruction changes? | resolution-neutral result, claim reduction, Stop, failure, or capture limit |
| 4 | Praxeological Traceability Ceiling | What load-bearing source structure does the result carry? | reduce, fail, Stop, retain analogy only, or record Non-Capture |
| 5 | Continuity and Type Integrity | Are source type, reference object, function, time, and relevant context preserved as required? | bound, separate, reduce, fail, or Stop |
| 6 | Counterfactual Sensitivity | Would relevant source-grounded change alter the result? | qualify, reduce, reclassify, Stop, or record a capture limit |
| 7 | Loss and Selection | What was selected, and what became preserved, compressed, excluded, uncertain, or irrecoverable? | limit the claim; hidden loss blocks an unqualified result |
| 8 | Alternatives | What rival transformation, narrower claim, non-translation, or no-transformation option remains? | provisional, partial, reduced, or capture-limited result |
| 9 | Source and Calibration Limits | Do sources and discriminating thresholds support the claimed precision? | provisional result, claim reduction, Stop, failure, or Non-Capture |
| 10 | Anti-Immunization | Was an earlier failure corrected or merely moved to another frame, level, granularity, composition, or target function? | preserve the earlier failure and stop the rescue claim |
| 11 | Stop and Non-Capture | Must continuation end, is Claim Reduction required, or does adequate capture remain unavailable? | record the applicable positive boundary result and re-entry conditions where relevant |
| 12 | Claim and Authority Ceiling | What maximum assertion remains, and what authority is independently prohibited? | reduce the claim or prohibit authority inflation |

Output mapping is not a thirteenth or fourteenth audit stage. It occurs only after the twelve-stage audit as a separate routing handoff:

```text
local findings and controlled local results
+
full cross-rule pattern
→
Boundary_Decision_Tree route selection
→
one canonical Output Class for the tested claim
```

The class identity and semantic boundary remain owned by `07_model/Output_Classes.yaml`. Route selection and collision handling remain owned by `07_model/Boundary_Decision_Tree.yaml`. The later record schema records the selected class without erasing local findings, Stop triggers, loss, capture boundaries, or prior failures.

A later-stage success does not erase an earlier-stage failure. Each operation occurrence in a chain receives its own audit record and output class.

## 23. COMPOSE Quick Gate

`COMPOSE` forms a new composite analytical object from many or sequential source structures. The quick gate does not replace the full audit. This quick gate presupposes every applicable common check in Section 22. Omission from the compact table does not make a check inapplicable.

| Gate | COMPOSE question | Pass signal | Stop or failure signal |

| Identity | Are multiple or sequential sources forming a declared new composite? | formation rule and composite identity explicit | chronology, list, or aggregation mislabeled as COMPOSE |
| Selection | Why these sources, period, ordering, branch points, and non-events? | selection rule and alternatives declared | retrospective convenience hidden |
| PraxisPurchase | What does the composite reveal that the sources separately do not? | changed reconstruction | mere aggregation |
| TraceableLoad | Can the composite be reconstructed from sources and constitutive relations? | source-to-composite map | macro label independent of sources |
| Temporality | Is order or historical load constitutive? | ordering rule and counterfactual reordering test | sequence treated as trajectory without warrant |
| Type Integrity | Are source types retained and the composite kept derived? | no new primitive | composite promoted to operator |

| Loss | What is compressed, excluded, uncertain, or irrecoverable? | canonical loss declaration | lossless-addition claim |

| Claim Ceiling | Is the result sequence, path, trajectory, path dependence, or another declared composite? | object class and reach explicit | higher historical claim smuggled in |

Typical local results include admissible sequence, path, trajectory, declared composite, provisional composition, competing composition, reduced claim, failed composition, mandatory stop, and Non-Capture. They must map to the fixed output vocabulary without becoming new classes.

## 26. Output-Class Handoff

The Admissibility Band Reference does not redefine the ten canonical classes. It records common gate patterns and their possible governance handoffs.

The mapping is not an automatic algorithm. The tested claim, local result, and failed or limited checks must remain visible.

| Gate pattern | Local result or claim effect | Canonical output class |
| --- | --- | --- |
| all applicable requirements pass for the claim as declared | claim retained as tested | `admissible` |
| a materially narrower claim is formulated, tested, and passes | bounded claim retained | `admissible_with_bounded_claim` |
| coherent claim remains usable but source, calibration, counterfactual, or rival limits remain material | provisional qualifier retained | `admissible_but_provisional` |
| valid resolution comparison produces no changed warranted reconstruction | resolution-neutral result | `resolution_neutral` |

band position

## 27. Stop, Failure, and Re-Entry

Stop is a positive methodological result.

Two methodological forms remain distinct:

```text
mandatory stop
→ continuation would be inadmissible
→ canonical output: mandatory_stop

optional stop
→ continuation may be admissible but is unnecessary for the present claim
→ no additional canonical output class
```

```text
mandatory stop
≠
optional stop
```

| Trigger | Stop form | Preserved result | Re-entry condition |
| --- | --- | --- | --- |
| no additional purchase after a valid neutral test | optional stop unless repetition becomes inadmissible | resolution-neutral or prior warranted reconstruction | new distinction or question |
| continued refinement falls below the Floor | mandatory stop | prior warranted result | new source or materially new distinction |
| traceable load is lost | mandatory stop | source object and any earlier bounded result | restored Source Trace |
| Source Ceiling is reached | mandatory stop for further unsupported detail | source-limited claim | new sources |
| type integrity cannot be maintained | mandatory stop or failed transformation | source identity and failure record | new operation and claim |
| calibration becomes non-discriminating | mandatory stop | calibration-open or bounded result where available | new calibration basis |
| anti-immunization violation | mandatory stop | original failed claim and countercase | independent new claim and record |

Failure concerns the attempted transformation. Stop concerns continuation. Non-Capture concerns adequate capture. These may interact but are not interchangeable.

Re-entry requires a changed condition and a new or revised record. It is not unrecorded continuation.

## 28. Non-Capture and Capture Boundaries

Non-Capture preserves the methodologically positive result that the present grammar, source basis, granularity, composition, calibration, or projection cannot adequately capture the object or claim.

Required separations:

```text
Non-Capture
≠
non-capture claim
≠
non_capture
```

- **Non-Capture** is the methodological concept.
- A **non-capture claim** is a record-bound assertion about what remains inadequately captured and why.
- `non_capture` is the canonical output class for the tested record.

| Capture form | What must be stated | Possible class interaction |
| --- | --- | --- |
| captured | what claim and structure are adequately retained | `admissible`, `admissible_with_bounded_claim`, or `admissible_but_provisional` subject to other gates |
| partially captured | what remains captured, uncaptured, and separable | `admissible_with_bounded_claim`, `admissible_but_provisional`, `partially_admissible`, `mandatory_stop`, or `non_capture` depending on the tested claim |
| not captured | what failed, which limiting condition applies, and why weaker capture is unavailable | `non_capture` |
| source Non-Capture | source gap that prevents adequate claim without treating absence as Non-Event | `admissible_with_bounded_claim`, `admissible_but_provisional`, or `non_capture` depending on what remains warranted |
| calibration Non-Capture | no discriminating threshold remains | `non_capture` or `mandatory_stop` |
| projection Non-Capture | no source-traceable target function is available | `non_capture` or `analogy_only` where resemblance remains |

Non-Capture does not prove a rival superior, protect a weak claim, or prohibit criticism. It must state limiting condition, alternatives, and re-entry conditions.

## 29. Anti-Immunization and Operation Chains

The governing anti-immunization rule is:

```text
new transformation
=
new testable claim
```

A change of frame, granularity, relative level, composition, or target function does not erase an earlier failed claim.

| Chain event | Required preservation | Prohibited move |
| --- | --- | --- |
| COMPOSE followed by PROJECT_AS | composite result and projection claim receive separate records | projection retroactively validates the composition |
| COMPOSE followed by DECOMPOSE | composite loss and decomposition reference remain visible | finer reconstruction treated as exact inverse |
| DECOMPOSE followed by COMPOSE | source-function effect and new formation rule remain separate | recomposition presented as recovery of original |
| DECOMPOSE followed by PROJECT_AS | operation result, source-function effect, and target-function claim remain separate | rejected source function treated as failed DECOMPOSE |
| PROJECT_AS followed by DECOMPOSE | origin type and projected function remain visible | target function decomposed as a PMS operator type |
| multi-operation chain | each occurrence retains local result, class, loss, and failure history | integrated result overwrites components |

No operation chain forms a fourth operation. Integrated assessment adds a new audit claim; it does not merge the identities of the operations.

| Machine-checkable | Requires human or context judgment | Prohibited automatic inference |
