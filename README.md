# PMS-STRATA

**Granularity, Trajectory, Composition, and Cross-Level Functional Projection in PMS**

PMS-STRATA specifies how praxis structures may be composed, decomposed, and functionally projected across declared granularities and relative levels while preserving source traceability, origin-type integrity, transformation loss, claim boundaries, stop conditions, and non-capture.

It does not turn analytical recursion into ontological totality, greater authority, or immunity from failure.

## Purpose

PMS normally reconstructs praxis within a declared frame and analytical resolution. More complex reconstructions also require controlled movement between:

- temporal configurations and trajectories;
- provisionally compressed objects and finer reconstructions;
- local structures and composite analytical objects;
- origin-typed objects and bounded functions in another context.

PMS-STRATA makes those movements explicit, typed, inspectable, and criticizable.

It is a **bounded transformation discipline within PMS**. It is not:

- a new PMS Base;
- a superior meta-layer;
- an ontology of levels;
- a source of additional application authority;
- a mechanism for rescuing failed claims by changing frame, granularity, level, composition, or target function.

## Theoretical Dependency

PMS-STRATA depends exclusively on the current repository-reference specification of **PMS Base** in [`PMS.yaml`](https://raw.githubusercontent.com/tz-dev/Praxeological-Meta-Structure-Theory/refs/heads/main/model/PMS.yaml).

It uses the existing Δ–Ψ grammar and must not silently:

- add, rename, reorder, decompose, or extend the base operators;
- alter their dependency path;
- treat derived structures or functions as independent PMS primitives;
- override PMS application guardrails;
- convert structural findings into person-level, diagnostic, forensic, clinical, legal, or irreversible labels;
- inherit application authority from formalization, visualization, corpus size, or implementation detail.

The governing PMS principle remains:

```text
more structure
≠
more authority
```

Any application remains scene-bound, claim-typed, reversible where applicable, open to critique, and subject to the PMS requirements of distance, self-binding discipline, dignity-in-practice, calibration, and external accountability.

## The Three Operations

PMS-STRATA recognizes exactly three core transformation operations.

### `COMPOSE`

`COMPOSE` forms a new composite analytical object from multiple or sequential source structures.

```text
many or sequential source structures
→
new composite analytical object
```

Typical outputs include:

- sequences;
- warranted paths;
- trajectories;
- temporally bounded composites;
- structurally declared composite objects.

A valid composition must disclose:

- source selection;
- ordering;
- formation rule;
- constitutive relations;
- preserved structure;
- compression;
- exclusion;
- uncertainty;
- irrecoverable loss.

`COMPOSE` does not automatically create a target function.

```text
composite object
≠
contextual target function
```

### `DECOMPOSE`

`DECOMPOSE` reconstructs a provisionally compressed occurrence or composite under finer granularity while preserving the same reference object.

```text
compressed occurrence or composite
→
finer reconstruction of the same reference object
```

`DECOMPOSE` applies to occurrences and composites, not to the Δ–Ψ operator types themselves.

```text
operator type
≠
decomposable occurrence or composite
```

Finer resolution does not receive automatic epistemic privilege.

```text
finer reconstruction
≠
truer reconstruction
```

A decomposition may produce:

- resolution gain;
- resolution neutrality;
- resolution drift;
- resolution escape;
- mandatory stop;
- failure;
- non-capture.

### `PROJECT_AS`

`PROJECT_AS` projects an origin-typed source object as a bounded contextual target function.

```text
origin-typed source object
→
bounded contextual target function
```

The source object retains its origin type.

```text
X : Tₒ
PROJECT_AS
Fₜ @ Cₜ
```

means:

```text
X functions as Fₜ in context Cₜ
```

not:

```text
X becomes Fₜ as its origin type
```

A trajectory may function as a frame, macro-event, attractor, access structure, or other bounded analytical function without becoming a new PMS operator or primitive.

## Operation Vocabulary Closure

Within the present STRATA grammar, every admitted transformation must be typed as:

```text
COMPOSE
DECOMPOSE
PROJECT_AS
```

or as a finite declared chain of their separate occurrences.

```text
closed operation vocabulary
≠
proved representational completeness
```

PMS-STRATA does not claim to have mathematically proven that every conceivable PMS-relevant transformation is representable through these three operations.

A candidate that cannot be typed as one of the three operations, or as a declared chain of their occurrences, would require an explicit corpus-level revision. It may not be introduced locally as an informal fourth operation.

## The STRATA Admissibility Band

Every STRATA transformation must operate between a lower and an upper bound.

```text
Praxeological Traceability Ceiling
─────────────────────────────
admissible transformation
─────────────────────────────
Praxeological Relevance Floor
```

### Praxeological Relevance Floor

Below the lower bound, additional distinctions produce no further warranted praxis-relevant difference.

```text
additional detail
+
no changed reconstruction
=
distinction without praxeological purchase
```

A distinction is not justified merely because it can be made.

### Praxeological Traceability Ceiling

Above the upper bound, a composition or projection no longer carries a reconstructible structural load from its source objects.

```text
material source change
+
arbitrarily unchanged target label
=
abstraction without traceable load
```

A source citation alone does not establish constitutive traceability.

```text
citation
≠
constitutive source trace
```

### Admissibility

A transformation is admissible only where it remains both discriminating and reconstructively anchored.

```text
Admissible(T, X, C)
iff
PraxisPurchase
and TraceableLoad
and TypeIntegrity
and ContextualBoundedness
```

Relevant tests additionally include:

- reference continuity;
- functional continuity;
- temporal continuity;
- counterfactual sensitivity;
- selection and declared loss;
- alternatives;
- source ceiling;
- calibration;
- claim ceiling;
- authority ceiling;
- anti-immunization;
- stop;
- non-capture.

Formal elegance, detail quantity, corpus size, or schema validity cannot compensate for missing relevance, traceable load, or Type Integrity.

## Transformation Loss

Every routed transformation preserves an explicit five-part Loss record:

```yaml
loss:
  preserved:
  compressed:
  excluded:
  uncertain:
  irrecoverable:
```

Loss is not a scalar and is not automatically additive.

```text
Loss
≠
single score
≠
average
≠
ranking
```

For operation chains, local Loss profiles remain separately preserved.

```text
chain loss
=
ordered sequence of local Loss records
```

not:

```text
chain loss
=
merged or averaged result
```

## Stop, Failure, and Non-Capture

A further STRATA operation is not justified merely because it is available.

A claim must be reduced, stopped, rejected, or marked as non-capture where:

- no additional praxis-relevant difference is produced;
- the source basis no longer supports the requested resolution;
- a composite loses its traceable source load;
- reference continuity fails;
- origin type and target function collapse;
- the target context becomes arbitrary;
- calibration deteriorates;
- a new level, frame, granularity, composition, or function is used mainly to rescue a failed claim;
- bounded attempts leave no adequate retained capture claim.

### Stop

Stop is a positive methodological result.

```text
mandatory stop
→
further continuation under the present claim is inadmissible
```

```text
optional stop
→
further continuation is unnecessary
```

Optional Stop is not an additional Output Class.

### Failure

A failed transformation records failure of the declared transformation claim.

```text
failed transformation
≠
mandatory stop
≠
non-capture
```

A later successful transformation does not repair the earlier failure.

```text
new transformation
=
new testable claim
```

### Non-Capture

`non_capture` is a legitimate bounded result.

It requires:

```text
delimited capture claim
+
adequate bounded attempts
+
preserved partial capture
+
persistent material remainder
+
no adequate retained whole-claim form
+
distortion if forced
+
explicit alternatives or external-method openness
=
non_capture
```

It must not be used to immunize an otherwise weak claim.

```text
missing information
≠
non-capture
```

```text
one failed attempt
≠
non-capture
```

## Cases, Countercases, and Chains

The Case corpus contains:

```text
59 YAML Operation Records
↔
59 same-basename Markdown companions
+
10 multi-record Package Narratives
```

Each YAML Record represents one operation occurrence.

Each Markdown companion provides a human-readable account of the same occurrence.

A Package Narrative may connect several Records through a shared source, comparison, or chain context.

```text
Package Narrative
≠
Operation Record
≠
merged result
≠
automatic precedent
```

The corpus directly instantiates all ten Output Classes and includes the six minimum chain families:

```text
COMPOSE → PROJECT_AS
COMPOSE → DECOMPOSE
DECOMPOSE → COMPOSE
DECOMPOSE → PROJECT_AS
PROJECT_AS → DECOMPOSE
COMPOSE → PROJECT_AS → DECOMPOSE
```

Every operation occurrence retains its own:

- claim;
- source;
- target;
- audit;
- Loss;
- local result;
- Output Class;
- stop status;
- failure status;
- capture boundary.

## Repository Authority Order

The repository separates architectural authority, canonical prose, formalization, tests, references, publications, and presentation.

This `README.md` is a repository-navigation and orientation document. It is not an independent theoretical authority.

The authority order is:

```text
PMS.yaml
→ PMS-STRATA Structure
→ canonical Blocks
→ Minified Controls
→ Formal Model
→ Appendices
→ Cases
→ Reference Kernel
→ Derivative Publications
→ Reader
```

### `PMS.yaml`

- Governing PMS Base operator inventory and dependency path.
- Source of PMS guardrails and application constraints.
- Not modified by PMS-STRATA.

### `00_source/PMS-STRATA_Structure.md`

- Authoritative architectural blueprint.
- Defines chapter and Appendix ownership.
- Controls corpus structure without replacing the owned canonical prose of the Blocks.

### `01_blocks/*`

- Canonical STRATA prose.
- Primary theory layer for Front Matter, Foundations, PATH, SUB, RETYPE, LIMITS, and Conclusion.

### `02_appendices/*`

- Controlled consolidation and operationalization layer.
- Contains definitions, notation, Record templates, admissibility tests, transformation patterns, stress tests, the Case index, and the integrated audit template.
- Does not compete with the primary theory owners in the canonical Blocks and Minified Controls.

### `03_cases/*`

- Contains Cases, Countercases, Confusion Cases, YAML Records, Markdown companions, Package Narratives, and reusable templates.
- Pressure-tests discrimination, transformation success, failure, stop, claim reduction, and non-capture.
- Does not function as automatic precedent or application authority.

### `04_reference/*`

- Active Reference Kernel.
- Contains the Glossary, indexes, claim tables, evidence map, cross-references, Reader pathways, audit checklist, coverage matrix, and current control references.
- Routes to theory owners without becoming a competing theory source.

### `05_minified/*`

- Compact control artifacts.
- Contains the Canonical Kernel, Claim Boundary, Operation Signatures, Admissibility Band, Block Contracts, and Chapter Contracts.
- Used for consistency control rather than as an independent theory source.

### `06_derivative_publications/*`

- Contains the compact overview, derived publishable paper, and technical whitepaper.
- Derivative publications possess no authority to revise the source corpus.

### `07_model/*`

- Machine-readable operationalization of transformation and boundary logic.
- Includes the Operation Registry, Output Classes, Admissibility Rules, Boundary Decision Tree, Transformation Record Schema, Root manifest, and companion schema.
- Formalizes and checks the corpus but does not replace or substantively validate it.

### `08_PMS-STRATA Reader/*`

- Navigation and presentation layer.
- Reads repository artifacts without duplicating or redefining their content.
- Possesses no independent analytical authority.
