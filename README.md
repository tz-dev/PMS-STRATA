PMS-STRATA specifies how praxis structures may be composed, decomposed, and functionally projected across declared granularities and relative levels—while preserving source traceability, origin-type integrity, transformation loss, claim boundaries, stop, and non-capture. It does not turn analytical recursion into ontological totality, greater authority, or immunity from failure.

## Purpose

PMS normally reconstructs praxis within a declared frame and analytical resolution. More complex reconstructions also require controlled movement between:

- temporal configurations and trajectories,
- provisionally compressed objects and finer reconstructions,
- local structures and composite objects,
- origin-typed objects and bounded functions in another context.

PMS-STRATA makes those movements explicit, typed, inspectable, and criticizable.

It is a **bounded transformation discipline within PMS**. It is not a new PMS base, a superior meta-layer, an ontology of levels, or a source of additional application authority.

## Theoretical Dependency

PMS-STRATA depends exclusively on the current repository-reference specification of **PMS Base** in `PMS.yaml`.

It uses the existing Δ–Ψ grammar and must not silently:

- add or rename base operators,
- alter the default operator order or dependency path,
- treat derived structures as independent primitives,
- override PMS application guardrails,
- convert structural findings into person-level, diagnostic, forensic, or irreversible labels.

The governing PMS principle remains:

```text
more structure
≠
more authority
```

Any application remains scene-bound, claim-typed, reversible where applicable, open to critique, and subject to the PMS requirements of distance, self-binding discipline, dignity-in-practice, calibration, and external accountability.

## Core Architecture

PMS-STRATA is organized into four operational parts built on shared foundations.

### Foundations

Defines the common object model and the distinctions required by every later operation:

- operator type,
- operator occurrence,
- composite structure,
- configuration,
- event and non-event,
- transition,
- path and trajectory,
- frame,
- granularity,
- relative level,
- origin type,
- target function,
- transformation context.

### Part I — PATH

Specifies temporal order, transition, path formation, trajectory formation, path dependence, branches, delays, unavailable alternatives, non-events, and the operation `COMPOSE`.

### Part II — SUB

Specifies decomposition under finer granularity, resolution gain and neutrality, resolution drift and escape, preservation of the source object, and the operation `DECOMPOSE`.

### Part III — RETYPE

Specifies bounded cross-level functional projection while preserving origin type, source reference, historical load, and context. Its operation is `PROJECT_AS`.

### Part IV — LIMITS

Consolidates the admissibility boundaries that already apply locally throughout PATH, SUB, and RETYPE. It governs relevance, traceability, continuity, loss, calibration, anti-immunization, stop, and non-capture.

## The Three Operations

### `COMPOSE`

Forms a composite analytical object from multiple temporally or structurally ordered source objects.

```text
many / sequential source structures
→
composite object
```

Typical outputs include sequences, paths, trajectories, and other declared composites. Selection, ordering, compression, exclusion, and irrecoverable loss must remain explicit.

### `DECOMPOSE`

Reconstructs a provisionally compressed occurrence or composite under finer granularity.

```text
compressed object
→
finer relational reconstruction
```

`DECOMPOSE` applies to concrete occurrences and composites, not to the Δ–Ψ operator types themselves. Finer resolution does not receive automatic epistemic privilege.

### `PROJECT_AS`

Projects an origin-typed object as a bounded function within a declared target context.

```text
origin-typed source object
→
contextual target function
```

The origin type remains visible. A trajectory that functions as a frame does not become a frame operator as its origin type.

## The STRATA Admissibility Band

Every STRATA transformation must operate between a lower and an upper bound.

### Praxeological Relevance Floor

Below the lower bound, additional distinctions produce no further warranted praxis-relevant difference.

```text
additional detail
+
no changed reconstruction
=
distinction without praxeological purchase
```

### Praxeological Traceability Ceiling

Above the upper bound, a composition or projection no longer carries a reconstructible structural load from its source objects.

```text
material source change
+
arbitrarily unchanged target label
=
abstraction without traceable load
```

### Admissibility

A transformation is admissible only where it remains both discriminating and reconstructively anchored.

```text
Admissible(T, X, C)
iff
PraxisPurchase
and TraceableLoad
and TypeIntegrity
and ContextualBoundedness
```

Relevant tests additionally include reference continuity, functional continuity, counterfactual sensitivity, declared loss, source support, claim scope, and an explicit stop condition.

## Stop, Failure, and Non-Capture

A further STRATA operation is not justified merely because it is available.

A claim must be reduced, stopped, rejected, or marked as non-capture where:

- no additional praxis-relevant difference is produced,
- the source basis no longer supports the requested resolution,
- a composite loses its traceable source load,
- origin type and target function collapse,
- the target context becomes arbitrary,
- calibration deteriorates,
- or a new level is used mainly to rescue a failed claim.

`non_capture` is a legitimate bounded result. It records that the present grammar, sources, granularity, composition, or projection cannot adequately reconstruct the object. It must not be used to immunize an otherwise weak claim.
