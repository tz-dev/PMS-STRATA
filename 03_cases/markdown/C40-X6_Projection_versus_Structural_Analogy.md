## 1. Case Statement

The independently reconstructed `C17-LAMBDA-01` Trajectory is compared with a synthetic technical workflow trace. Four formal relations correspond:

```text
ordered historical phases
↔ ordered workflow states

missed expected review
↔ declared but skipped check node

persistent workaround
↔ repeated fallback branch

partial repair with residual burden
↔ rollback with residual state
```

These correspondences are useful. They expose where two transition structures resemble and where the resemblance breaks. They do **not** establish that the historical Trajectory performs a transition-debugging function for the technical workflow.

```text
formal correspondence
≠ Semantic Preservation

Semantic Preservation
≠ Target Function automatically

useful analogy
≠ failed source object
≠ weak PROJECT_AS
```

The case is synthetic and tests method boundaries only. It provides no empirical workflow validation, causal proof, semantic equivalence, design recommendation, person judgment, or application authority.

## 4. The Structural Correspondence

The analogy is not a label substitution. It retains four explicit relation pairs and can fail when those pairs are removed.

### Order

The Q0–Q5 trajectory and s0–s5 trace each contain an ordered progression. This supports comparison of order, not a shared clock or identical temporal meaning.

### Skipped transition

The warrantable missed Q1 review occupies a formally comparable position to a declared technical check that is skipped while other transitions continue. The resemblance concerns non-realization within a larger sequence. It does not equate `Λ` with a machine node.

### Persistent fallback

The Q2–Q4 workaround/default pattern corresponds to repeated use and stabilization of a fallback branch. Historical burden and responsibility remain source-only.

### Residual repair

Partial Q5 repair corresponds to rollback that reduces but does not eliminate residual state. Historical revision cost and technical residual state are not semantically identical.

## 5. Breaking Points and Residual Ledger

### Source-only residuals

- expectation;
- responsibility;
- asymmetric burden;
- binding and exit costs;
- contested historical boundaries;
- practical uncertainty.

### Target-only residuals

- executable guards;
- runtime constraints;
- deterministic transition rules;
- implementation state;
- machine rollback semantics.

Deleting these residuals would make the mapping look cleaner only by falsifying both objects.

```text
better formal fit through residual deletion
≠ better reconstruction
```

## 6. PraxisPurchase and TraceableLoad

### PraxisPurchase — `gain`

The bounded analogy distinguishes:

1. useful relation-preserving comparison;
2. mere terminology reuse;
3. semantic-identity overreach;
4. independently warranted functional projection.

That is a real comparative gain.

### TraceableLoad — `within_ceiling`

Every retained correspondence points to declared source and target relations. The analogy remains traceable because it does not claim the absent semantic or functional bridge.

The stronger projection would exceed the ceiling.

```text
traceable analogy
≠ traceable target function
```

## 7. Counterfactual Sensitivity

The analogy is `partially_sensitive`:

- removing order weakens the comparison;
- completing the review removes the skipped-transition relation;
- eliminating fallback persistence removes the recurring-fallback relation;
- replacing partial repair with complete repair removes the residual-state relation.

But sensitivity of the analogy does not establish a target function.

A function would additionally need to show that changes in the source Trajectory alter a target-side analytical or practical discrimination in the declared technical context.
