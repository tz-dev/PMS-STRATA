# C40-N7 — Person-Level Type Jump

## 1. Case purpose

This countercase executes the Chapter-40 `N7` pressure: a bounded function of a relational configuration is incorrectly converted into a stable property of one participating person.

The case tests one `PROJECT_AS` occurrence only. It does not classify the person, diagnose a state, infer motive, assign maturity, rank dignity, decide legitimacy, recommend action, or authorize sanction.

## 2. Source configuration

The source is the bounded coordination configuration `configuration.c40-n7.c3-role-field` during `C3-R0–R4`.

It retains the source-side result from `C40-P3`: recurrent form `R3` performs a bounded dynamic attractor-function in configuration `C3` by changing transition access, role recurrence, resource commitment, reopening friction, and release cost.

Within that configuration, role-holder `p7` occupies the coordinating role `r_coord` during `C3-R1–R3`. The warranted source relation is limited to participation:

```text
p7 occupies r_coord in C3
+ p7 contributes to selected maintenance acts
+ p7 is constrained by the same configuration
≠ p7 owns the configuration function
```

## 3. Tested PROJECT_AS claim

The attempted target claim states:

```text
because p7 participates in C3 while C3 carries an attractor-function,
p7 is an intrinsic "attractor type" or "binding type"
across later contexts
```

This is not a bounded contextual function. It converts a configuration-level relation into a stable person property and then extends it beyond the source context.

## 4. Material variation tests

### 4.1 Person replacement

Replace `p7` with `p8` while retaining the role script, resource commitments, access rules, and reopening costs of `C3`.

The configuration-level attractor-function remains materially present.

```text
person changed
+ configuration retained
→ function substantially retained
```

### 4.2 Configuration dissolution

Retain `p7` but dissolve the recurrent role/resource configuration and reopen ordinary transition routes.

The alleged person-level function disappears.

```text
person retained
+ configuration changed
→ alleged function disappears
```

### 4.3 Cross-context comparison

Place `p7` in comparison context `D7`, where the role script, resource lock-in, and reopening friction are absent.

No comparable attractor- or binding-function is supported.

The claim therefore follows the configuration, not the person.

## 5. Type-integrity finding

```text
configuration performs bounded function
≠ person owns function

person participates in configuration
≠ person embodies macrofunction

role contribution
≠ essence
≠ diagnosis
≠ stable trait
≠ motive
≠ moral rank
```

The source configuration, its bounded function, and the participation relation remain separately visible. The target person-property claim is withdrawn.

That alternative requires its own source support, temporal scope, counterfactual test, Loss, and result. It does not repair this failed operation.

No-person projection remains the default retained alternative.
