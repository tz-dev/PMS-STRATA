# PMS-STRATA — Admissibility Band Minified

**Status:** canonical control artifact for corpus maintenance and audit  
**Dependency:** `PMS_STRATA_Claim_Boundary_Minified.md`, `PMS_STRATA_Operation_Signatures_Minified.md`, PMS Base as represented by `PMS.yaml`, and the current `PMS-STRATA_Structure.md`  
**Function:** compact specification of the operating range within which `COMPOSE`, `DECOMPOSE`, and `PROJECT_AS` count as bounded, source-traceable, type-integral, and criticizable STRATA transformations

---

## 1. Governing Principle

A STRATA operation is not admissible merely because it can be formulated.

```text
available transformation
≠
admissible transformation
```

Admissibility requires that an operation produce a warranted praxeological difference while remaining reconstructibly dependent on its source structures, preserving type and reference discipline, declaring loss, limiting its claim, and remaining open to stop, failure, and non-capture.

The STRATA Admissibility Band therefore prevents two opposed forms of analytical drift:

```text
below the band
→ distinction without praxeological purchase

above the band
→ abstraction without traceable load
```

Within the band, a transformation is sufficiently discriminating to matter and sufficiently anchored to remain inspectable.

---

## 2. The Band

### 2.1 Lower bound

The **Praxeological Relevance Floor** is the lower limit below which an added distinction, refinement, composition, or functional claim creates no warranted change in the reconstruction of praxis-relevant structure.

Canonical formulation:

> **Below the Praxeological Relevance Floor, additional resolution is not an additional praxis finding. It is distinction without praxeological purchase.**

### 2.2 Operating range

A transformation lies within the band when it:

- changes a warranted praxis-relevant reconstruction;
- remains supported by an adequate source basis;
- preserves a traceable relation between source and result;
- preserves reference and type discipline;
- declares its selection and loss;
- remains bounded to a frame, context, granularity, relative level, and claim scope;
- is sensitive to relevant changes in its stated source load;
- permits rival transformations, claim reduction, stop, and non-capture.

### 2.3 Upper bound

The **Praxeological Traceability Ceiling** is the upper limit above which a composition, decomposition, or projection no longer carries reconstructible structural load from its source objects.

Canonical formulation:

> **Above the Praxeological Traceability Ceiling, abstraction no longer carries reconstructible praxis load. It becomes a label without traceable source structure.**

### 2.4 Compact band representation

```text
BELOW
resolution or transformation without praxeological purchase

WITHIN
warranted difference with preserved source load and bounded claim

ABOVE
abstraction, fragmentation, or projection without reconstructible source load
```

---

## 3. No Universal STRATA Scale

The band is relational, not metrically fixed.

There is no universal:

- smallest praxis-relevant distinction;
- finest admissible granularity;
- largest legitimate composite;
- maximum number of compositional levels;
- fixed threshold at which repetition becomes an attractor-function;
- fixed threshold at which a path becomes a trajectory;
- fixed threshold at which analogy becomes projection.

Admissibility depends on:

```text
frame
+ source object
+ source basis
+ granularity
+ relative level
+ temporal scope
+ transformation context
+ claim scope
```

The Planck-scale analogy, where used, is heuristic only. It does not establish a constant praxeological unit.

```text
relational boundary
≠
universal scale value
```

## 4. Admissibility Object

Admissibility is assessed for a specific transformation claim, not for a concept or object in the abstract.

Minimal assessment object:

```text
operation T
applied to source object X
within transformation context C
for claim Q
under source basis S
```

Compact notation:

```text
Admissibility(T, X, C, Q, S)
```

The same object may support:

- one admissible transformation;
- another transformation only with a reduced claim;
- a resolution-neutral result;
- a failed transformation;
- or non-capture.

No object is globally admissible or inadmissible independent of operation and claim.

## 5. Praxeological Relevance Floor

### 5.1 Praxeological purchase

A distinction or transformation possesses **praxeological purchase** when it changes at least one warranted reconstruction concerning:

- available, constrained, or closed action corridors;
- distribution of costs;
- exposure or risk;
- roles and asymmetries;
- expectations and non-events;
- bindings and commitment structures;
- temporal order, duration, delay, or irreversibility;
- path construction or path dependence;
- recontextualization;
- integration possibilities;
- projection validity;
- claim scope;
- failure or stop conditions.

Praxeological relevance does not require immediate actionability. An irreversible, inaccessible, or non-steerable structure may still be relevant when it changes a warranted reconstruction.

### 5.2 Changed-reconstruction test

The central lower-bound question is:

> **Which warranted statement must be formulated differently because of this additional distinction or transformation?**

Possible effects include:

```text
typing changes
cost distribution changes
role or asymmetry changes
path construction changes
path-dependence claim changes
target function changes
claim becomes narrower
countercase becomes visible
stop becomes necessary
no relevant reconstruction changes
```

The final result in this list does not establish resolution gain.

### 5.3 Detail is not difference

```text
additional information
+
no changed warranted reconstruction
=
resolution without praxeological purchase
```

More detail may be accurate while remaining irrelevant to the present claim.

### 5.4 Lower-bound failure forms

Typical forms include:

- event inflation;
- temporal over-resolution;
- atomistic component lists;
- distinctions without relational consequence;
- role proliferation without changed asymmetry;
- profile or modulator inflation;
- technical precision without praxis gain;
- repeated reformulation of the same claim;
- new labels without added discrimination;
- decomposition pursued only because further decomposition is possible.

### 5.5 Resolution gain

`resolution_gain` is warranted when the added distinction:

- identifies a previously hidden constitutive relation;
- changes a typing or functional claim;
- redistributes reconstructed costs, risks, or roles;
- reveals a relevant event, non-event, branch, or residue;
- revises a path or trajectory;
- identifies a countercase;
- changes a stop or claim ceiling;
- or improves discriminative comparison between rival reconstructions.

### 5.6 Resolution-neutral result

A correct refinement may produce no additional praxis finding.

```text
resolution_neutral
≠
failed analysis
```

A resolution-neutral result may establish that:

- a coarser reconstruction remains sufficient;
- a suspected distinction is not load-bearing;
- an internal variation does not alter the source function;
- or further refinement is unnecessary for the current claim.

It does not authorize the stronger claim that finer analysis produced additional support.

### 5.7 Lower-stop rule

A transformation must stop at the lower bound when:

- no warranted reconstruction changes;
- only terminological refinement remains;
- the source basis cannot support the added distinction;
- further resolution repeats the same result;
- complexity grows without discrimination;
- or the operation is being used to postpone an objection.

### 5.8 Minimal relevance-floor record

```yaml
relevance_floor:
  proposed_difference:
  affected_praxis_dimensions: []
  changed_reconstruction:
  changed_claim:
  source_support:
  result: gain | neutral | below_floor | underdetermined
  stop_required:
```

## 6. Praxeological Traceability Ceiling

### 6.1 Traceable load

A transformation result possesses **traceable load** when:

- its constitutive source objects remain identifiable;
- its load-bearing source features are stated;
- relevant relations remain reconstructible;
- relevant temporality remains reconstructible;
- costs, asymmetries, non-events, and bindings do not disappear where constitutive;
- selection and compression are disclosed;
- the result changes when its stated source load changes;
- and the claim remains limited to what this source trace can support.

### 6.2 Traceability is more than citation

A source reference alone does not establish traceability.

Traceability requires:

```text
source identification
+
structural mapping
+
functional dependency
+
loss disclosure
+
claim limitation
```

A cited source that does not alter or constrain the target result carries no demonstrated load.

### 6.3 Constitutive source trace

Every strong transformation claim must distinguish:

```yaml
constitutive_source_trace:
  load_bearing_features: []
  strongly_modulating_features: []
  weakly_modulating_features: []
  compressed_features: []
  excluded_features: []
  uncertain_features: []
```

A long list is not required. The trace must be sufficient to show what the result depends on and where the dependency ends.

### 6.4 Source-target dependency

The central upper-bound question is:

> **Would a relevant change in a stated load-bearing source structure alter the resulting composite, decomposition status, or projected function?**

```text
material source change
+
arbitrarily unchanged target result
=
possible abstraction without traceable load
```

### 6.5 Traceability is not exhaustiveness

Traceability does not require:

- complete reproduction of the source;
- lossless transformation;
- preservation of every detail;
- a fully reversible operation;
- or total reconstruction of all possible alternatives.

It requires preservation of the load-bearing source relation for the claim being made.

```text
traceable load
≠
exhaustive retention
```

### 6.6 Upper-bound failure forms

Typical forms include:

- macro-label without reconstructible path;
- trajectory without transitions or sedimentation;
- macro-event without preserved internal duration;
- attractor-function without a repetition or stabilization mechanism;
- higher-level asymmetry without local or distributed cost trace;
- frame-function without historical carriers;
- decomposition in which the source object disappears;
- components without reconstructible coarser function;
- profile without stable weighting;
- projection without source dependency;
- result invariant across contradictory source structures;
- metaphorical continuity substituted for structural continuity.

### 6.7 Macro-label elasticity

A target label is overelastic when it:

- absorbs opposed source structures;
- remains unchanged under removal of declared constitutive features;
- has no identifiable countercase;
- survives every loss of source detail;
- or changes meaning to preserve itself.

Overelastic labels exceed the ceiling unless narrowed, reclassified, or abandoned.

### 6.8 Operation-specific ceiling forms

For `COMPOSE`, the ceiling is exceeded when the composite can no longer be reconstructed through its source sequence, relations, transitions, or loss profile.

For `DECOMPOSE`, the ceiling is exceeded when finer components and details no longer reconstruct the same source object or its coarser function.

For `PROJECT_AS`, the ceiling is exceeded when the target function no longer depends on the origin-typed source object within the declared target context.

### 6.9 Upper-stop rule

The operation must stop or the claim must be reduced when:

- source structures are no longer identifiable;
- relevant relations have disappeared;
- the target result becomes source-indifferent;
- the source object is replaced rather than transformed;
- only analogy or metaphor remains;
- formal precision exceeds source precision;
- or the claim cannot state what would count against it.

### 6.10 Minimal traceability-ceiling record

```yaml
traceability_ceiling:
  target_claim:
  load_bearing_source_features: []
  preserved_relations: []
  preserved_temporality: []
  preserved_cost_and_asymmetry_structure: []
  source_target_dependency:
  abstraction_risk:
  result: within_ceiling | claim_reduction | above_ceiling | underdetermined
  stop_required:
```

## 7. Type Integrity

A transformation remains admissible only when its type commitments remain explicit and non-collapsing.

Mandatory distinctions:

```text
operator type
≠
operator occurrence

operator occurrence
≠
composite structure

origin type
≠
target function

derived analytical object
≠
new PMS primitive
```

### 7.1 Type-integrity requirements

- `COMPOSE` may form a new analytical object without rewriting the origin types of its components.
- `DECOMPOSE` may explain, refine, differentiate, or reject a source typing without decomposing the PMS operator type itself.
- `PROJECT_AS` must preserve the source object's origin type while adding a bounded target function.
- Operator weighting must not become operator replacement.
- A profile or modulator must not become a hidden primitive.
- A higher-level function must not be attributed directly as an essence or person type.

### 7.2 Type-integrity failure

A transformation fails type integrity when:

- target function replaces origin type;
- local components automatically inherit the type of a composite;
- a derived object is inserted into the Δ–Ψ base grammar;
- a functional analogy is treated as operator identity;
- or levels and granularities are mixed without declaration.

### 7.3 Type-integrity record

```yaml
type_integrity:
  source_origin_type:
  source_occurrence_or_composite:
  target_object_class:
  target_function:
  origin_type_preserved:
  primitive_inflation_detected:
  level_mixing_detected:
  result:
```

## 8. Reference, Functional, and Temporal Continuity

### 8.1 Reference continuity

The transformation must continue to refer to the declared historical or structural source object, except where `COMPOSE` explicitly creates a new composite from declared sources.

Reference continuity fails when only the name remains while the constitutive source object has been exchanged.

### 8.2 Functional continuity

A coarser or target function must remain supported by concrete source features and relations.

Functional continuity does not require that a function survive every decomposition or countercase. A valid operation may show that the function must be revised or rejected.

### 8.3 Temporal continuity

Where temporality is constitutive, the transformation must preserve enough of:

- order;
- duration;
- transition structure;
- sedimentation;
- branch points;
- non-events;
- irreversibility;
- historical load.

Temporal continuity is not total chronological retention.

### 8.4 Continuity matrix

```yaml
continuity:
  reference:
    preserved:
    limits:
  type:
    preserved:
    limits:
  function:
    preserved:
    revised:
    limits:
  temporal:
    preserved:
    limits:
```

Partial continuity may require claim reduction rather than total rejection.

## 9. Contextual Boundedness and Claim Ceiling

An admissible result must state where, for what, and how far it applies.

Required bounds may include:

- source frame;
- target frame;
- transformation context;
- source and target granularity;
- relative source and target level;
- temporal scope;
- affected roles or objects;
- validity scope;
- claim type;
- claim ceiling.

### 9.1 Contextual-boundedness rule

```text
local transformation result
≠
global property of the source object
```

A function established in one target context is not automatically inherited by:

- other contexts;
- later scenes;
- related objects;
- all members of a category;
- or all analytical levels.

### 9.2 Authority ceiling

No successful transformation creates:

- greater truth by finer resolution;
- greater truth by higher composition;
- normative authority;
- person-evaluative authority;
- decision authority;
- or proof of PMS superiority.

```text
more structure
≠
more authority
```

### 9.3 Context and claim record

```yaml
context_and_claim:
  source_frame:
  target_frame:
  transformation_context:
  source_granularity:
  target_granularity:
  source_relative_level:
  target_relative_level:
  temporal_scope:
  validity_scope:
  claim_type:
  claim_ceiling:
  authority_inheritance: prohibited
```

## 10. Counterfactual Sensitivity

### 10.1 Function

Counterfactual Sensitivity tests whether a transformation result actually depends on the structures identified as load-bearing.

It is a load test, not a causal proof.

```text
counterfactual sensitivity
≠
causal demonstration
≠
empirical experiment
```

### 10.2 Core question

> **Would a relevant modification of the source structure alter the transformation result?**

A relevant modification must affect a feature declared as:

- constitutive;
- strongly modulating;
- temporally load-bearing;
- or functionally necessary.

Arbitrary or source-free scenarios do not provide a valid test.

### 10.3 Sensitivity classes

```text
strongly_sensitive
partially_sensitive
weakly_sensitive
insensitive
underdetermined
untestable
```

### 10.4 Operation-specific tests

For `COMPOSE`:

- Would a different order change the composite?
- Would removal of a turning point reduce a trajectory to a path or sequence?
- Would removal of a relevant non-event change the path?
- Would a different selection rule produce a rival composite?

For `DECOMPOSE`:

- Would removal or change of a component alter the coarser function?
- What functional-load, substitutability, compensation, and remainder-status results apply?
- Does the finer reconstruction still refer to the same source object?

For `PROJECT_AS`:

- Would a materially different source object perform the same target function?
- Which source features are indispensable to that function?
- Would the target function weaken, change, or disappear under relevant source modification?

### 10.5 Insensitive result

An insensitive result suggests:

- overelastic labeling;
- an unstated source dependency;
- metaphorical projection;
- predetermined output;
- or abstraction above the ceiling.

An insensitive result does not automatically invalidate every weak claim. It requires reduction, reclassification, or stop.

### 10.6 Untestable result

Untestability does not automatically prove failure.

Permissible effects must be recorded on separate axes:

```text
support status:
supported → provisional or underdetermined

claim relation or reach:
strong or broad → bounded or narrow

projection claim:
functional projection → structural analogy

canonical output:
selected only after the full gate pattern is assessed;
possible results include admissible_but_provisional,
claim_reduction_required, analogy_only, mandatory_stop,
failed_transformation, or non_capture
```

### 10.7 Minimal counterfactual record

```yaml
counterfactual_test:
  load_bearing_feature:
  proposed_change:
  source_grounding:
  expected_result_change:
  observed_or_inferred_result:
  sensitivity_class:
  confidence:
  claim_effect:
```

## 11. Source and Calibration Limits

### 11.1 Source ceiling

The source ceiling is reached when:

- no further supported distinction can be made;
- internal order or relations remain inaccessible;
- additional precision would be model-generated rather than source-supported;
- or the evidence cannot distinguish rival reconstructions.

```text
formal precision
must not exceed
source precision
```

### 11.2 Missing source is not non-event

```text
no record
≠
recorded non-occurrence

unknown event
≠
non-event
```

A non-event requires an evidenced expectation structure and a relevant non-realization within that frame.

### 11.3 Inferential distance

As inferential distance increases, the transformation requires stronger:

- justification;
- source trace;
- alternative testing;
- loss disclosure;
- uncertainty marking;
- and claim reduction.

### 11.4 Calibration

Calibration is the ability to set distinctions and thresholds such that:

- relevant cases remain comparable;
- relevant differences remain visible;
- output classes remain discriminating;
- and countercases remain possible.

STRATA does not assume universal thresholds for trajectory, attractor-function, macro-asymmetry, sedimentation, or projection.

### 11.5 Calibration-open result

A valid output may state:

```text
structural form identified;
threshold remains calibration-sensitive
```

### 11.6 Source and calibration record

```yaml
source_and_calibration:
  source_basis:
  direct_support: []
  inferred_structure: []
  missing_structure: []
  inferential_distance:
  source_ceiling:
  calibration_threshold:
  calibration_status:
  confidence:
  claim_effect:
```

## 12. Loss and Selection

No STRATA transformation is selection-free.

`COMPOSE` selects source objects, ordering, periodization, and formation rules.  
`DECOMPOSE` selects distinctions, components, relations, and internal thresholds.  
`PROJECT_AS` selects source features, target context, and target function.

Every admissibility assessment must disclose:

```yaml
loss:
  preserved: []
  compressed: []
  excluded: []
  uncertain: []
  irrecoverable: []
```

Loss is not automatic failure when:

- it is explicit;
- the load-bearing trace remains;
- the claim is bounded accordingly;
- and false completeness is not asserted.

Hidden loss occurs when:

- compression is presented as total preservation;
- alternatives disappear without record;
- heterogeneity is denied;
- uncertainty is converted into precision;
- or the target result conceals the conditions of its own formation.

---

## 13. Alternatives and Non-Translation

An admissible strong transformation must preserve the possibility of alternatives.

Relevant alternatives may include:

- a rival `COMPOSE`;
- a rival `DECOMPOSE`;
- a rival `PROJECT_AS`;
- a narrower claim;
- a different granularity;
- a different target context;
- no transformation;
- analogy only;
- non-translation;
- non-capture.

```text
preferred transformation
≠
only conceivable transformation
```

A transformation becomes suspect when it cannot state:

- a plausible rival;
- a countercase;
- a relevant source modification;
- or a condition under which it should stop.

## 14. Unified Admissibility Test

### 14.1 Core band test

```text
Admissible_core(T, X, C)
iff
PraxisPurchase(T, X, C)
and TraceableLoad(T, X, C)
and TypeIntegrity(T, X, C)
and ContextualBoundedness(T, X, C)
```

### 14.2 Full operational gate

```text
Admissible_full(T, X, C, Q, S)
iff
CoreBandSatisfied
and SourceSupportAdequate
and ReferenceContinuityPreserved
and FunctionalContinuityWarranted
and CounterfactualSensitivityAssessed
and LossDeclared
and AlternativesConsidered
and ClaimCeilingDeclared
and StopConditionDefined
and AuthorityInheritanceProhibited
```

This is a specification of required checks, not a proof calculus or an empirical law.

### 14.3 Non-compensatory rule

The core conditions are not interchangeable scores.

```text
high detail
cannot compensate for
no praxis purchase
```

```text
strong rhetoric
cannot compensate for
no traceable load
```

```text
source trace
cannot compensate for
invalid type jump
```

```text
formal completeness
cannot compensate for
unbounded context or claim
```

A failed load-bearing condition requires claim reduction, stop, failure classification, or non-capture.

## 15. Decision Order

Admissibility should be checked in the following order:

```text
1. Source and claim entry
2. Operation classification
3. Praxeological Relevance Floor
4. Praxeological Traceability Ceiling
5. Reference Continuity, TypeIntegrity, and continuity views
6. Counterfactual Sensitivity
7. Loss and selection
8. Alternatives and non-translation
9. Source and calibration limits
10. Anti-immunization
11. Stop and non-capture
12. Claim and authority ceiling
```

A later-stage success does not erase an earlier-stage failure.

## 16. Output Classes

Canonical admissibility outcomes are:

```text
admissible
admissible_with_bounded_claim
admissible_but_provisional
resolution_neutral
analogy_only
partially_admissible
claim_reduction_required
mandatory_stop
failed_transformation
non_capture
```

### 16.1 `admissible`

All load-bearing requirements are met for the declared claim and scope.

### 16.2 `admissible_with_bounded_claim`

The transformation is supported, but its context, time, function, or generality must remain narrow.

### 16.3 `admissible_but_provisional`

The structure is supported enough for controlled use, but source, calibration, or counterfactual limits remain material.

### 16.4 `resolution_neutral`

The refinement is permitted but produces no additional praxis finding.

### 16.5 `analogy_only`

A useful structural similarity exists, but source-traceable functional projection has not been established.

### 16.6 `partially_admissible`

Some stages or subclaims satisfy the band while others require reduction, separation, or non-capture.

### 16.7 `claim_reduction_required`

The current claim may survive only under a narrower object class, asserted relation, function, dependence strength, generality, or scope. A support downgrade is recorded separately.

### 16.8 `mandatory_stop`

Continuation would cross the relevance floor, traceability ceiling, source ceiling, type boundary, or anti-immunization rule.

### 16.9 `failed_transformation`

The proposed operation does not establish its required result.

### 16.10 `non_capture`

The object remains wholly or partly insufficiently reconstructible within the present STRATA operation, source basis, or grammar.

## 17. Claim Reduction

Before total rejection, a claim may be reduced where a weaker formulation remains warranted.

Canonical reductions include:

```text
trajectory
→
path
→
sequence
```

```text
strong path dependence
→
weak order dependence
```

```text
functional projection
→
analogy only
```

```text
higher-level function
→
local or partial function
```

Component claims are not reduced on one universal role ladder. Functional load, substitutability, compensation, and remainder status are tested on separate local axes.

```text
functional load:
constitutive / strongly modulating / weakly modulating / incidental / underdetermined

substitutability:
replaceable / non-replaceable / conditionally replaceable

compensation:
compensatory / non-compensatory / unresolved

remainder status:
integrated / residual / uncaptured
```

Support downgrade is recorded separately from Claim Reduction:

```text
supported
→
provisional
→
underdetermined
```

A valid resolution-gain test may produce a resolution-neutral result. That is a local result and canonical output handoff, not a reduction of claim type or reach.

```text
tested claim: resolution-gain claim
local result: resolution-neutral result
canonical output: resolution_neutral
```

Claim reduction must preserve the original failed or unsupported stronger claim in the record.

## 18. Stop

Stop is a positive methodological result.

### 18.1 General mandatory-stop conditions

A transformation must stop when:

- no new praxeological difference emerges;
- source trace is lost;
- source precision is exceeded;
- type integrity cannot be maintained;
- reference identity collapses;
- contextual boundedness cannot be stated;
- calibration becomes non-discriminating;
- a countercase is only moved to another level;
- or further transformation merely protects the previous claim.

### 18.2 Mandatory and optional stop

```text
mandatory stop
→ continuation would be inadmissible
→ canonical output: mandatory_stop

optional stop
→ continuation may be possible but is unnecessary for the present claim
→ methodological concept; no additional canonical output class
```

### 18.3 Re-entry

Re-entry after stop requires a new record and a new reason, such as:

- new sources;
- a different claim;
- a newly visible counterstructure;
- or a newly warranted calibration.

Re-entry is not unrecorded continuation.

### 18.4 Stop record

```yaml
stop:
  trigger:
  operation:
  mandatory:
  claim_before:
  claim_after:
  preserved_result:
  unresolved:
  reentry_condition:
```

## 19. Non-Capture

Non-Capture records that an object cannot presently be reconstructed, decomposed, composed, or projected with sufficient adequacy under the available source basis and admissibility constraints.

Possible forms include:

```text
source_non_capture
granularity_non_capture
compositional_non_capture
projection_non_capture
calibration_non_capture
semantic_non_capture
partial_capture
```

Non-Capture must state:

- what was attempted;
- what was captured;
- what remains uncaptured;
- which condition limits capture;
- what rival or external account may remain superior;
- and what could permit later re-entry.

```yaml
non_capture:
  object:
  attempted_operations: []
  captured_structure: []
  uncaptured_structure: []
  limiting_condition:
  rival_or_alternative:
  claim_effect:
  reentry_condition:
```

Non-Capture is not a device for making a weak claim immune from criticism.

Canonical statement:

> **PMS-STRATA preserves the possibility that a structure remains only partially reconstructible, non-projectable, or better captured outside the present grammar.**

## 20. Anti-Immunization Rule

A change of granularity, level, composition, frame, or target function creates a new testable reconstruction. It does not erase a failure in the claim from which the transformation began.

```text
original claim failed
+
new transformation proposed
=
original failure preserved
and new claim separately tested
```

Prohibited rescue forms include:

- escaping to finer granularity without answering the coarse-level objection;
- escaping to a higher level without preserving the local countercase;
- replacing a failed typing with a new projection and treating the original claim as repaired;
- treating translation success as confirmation of PMS;
- treating non-capture as immunity from rivals.

Canonical rule:

> **A change of granularity, level, composition, or target function constitutes a new testable reconstruction. It does not erase the failure of the claim from which the transformation began.**

## 21. Operation-Specific Quick Gates

### 21.1 `COMPOSE`

A composition is within the band only if:

- the source objects and their relation are identified;
- the result is more than chronology or aggregation;
- selection and formation rules are explicit;
- relevant events, non-events, asymmetries, bindings, and alternatives remain traceable;
- the composite reacts to changes in load-bearing sources;
- compression and irrecoverable loss are disclosed;
- no target function is smuggled in without `PROJECT_AS`;
- and the path or composite remains reconstructible.

### 21.2 `DECOMPOSE`

A decomposition is within the band only if:

- a concrete occurrence or composite, not a base operator type, is opened;
- the granularity change is declared;
- the added distinctions produce or test a warranted praxis difference;
- components and relations are reconstructed together;
- source support carries the finer structure;
- the source object and coarser function remain testable;
- resolution drift and escape are excluded;
- and stop occurs where finer detail adds no purchase.

### 21.3 `PROJECT_AS`

A projection is within the band only if:

- the origin-typed source object is identified;
- the target context and target function are explicit;
- origin type remains preserved;
- the function is carried by a constitutive source trace;
- the result is counterfactually sensitive;
- validity scope and loss are declared;
- analogy, recontextualization, and label substitution are excluded or separately classified;
- and no new primitive or authority is generated.

## 23. Completion Test

A STRATA transformation passes the minified admissibility gate only when all applicable questions can be answered:

1. What exact transformation claim is being tested?
2. Which frame, granularity, relative level, temporal scope, and source basis govern it?
3. Does the operation create a warranted praxis-relevant difference?
4. Which statement changes because of the transformation?
5. Does the result remain reconstructibly dependent on load-bearing source features?
6. Are relations, temporality, costs, asymmetries, non-events, and bindings preserved where constitutive?
7. Are source reference and origin type preserved as required by the operation?
8. Is the target function separated from origin type?
9. Is the result bounded to a declared context and claim ceiling?
10. Has a relevant counterfactual source modification been tested or marked unavailable?
11. Are preservation, compression, exclusion, uncertainty, and irrecoverable loss declared?
12. Have rival transformations and the no-transformation option been considered?
13. Does formal precision remain within the source ceiling?
14. Are calibration limits explicit?
15. Does the operation answer rather than relocate prior objections?
16. Is a stop condition defined?
17. Is claim reduction available where the stronger claim fails?
18. Does non-capture remain a real possible result?
19. Is authority inheritance explicitly prohibited?
20. Could the transformation still fail under a relevant countercase?

A missing answer does not automatically invalidate every weak or provisional use. It prevents an unqualified strong admissibility result.
