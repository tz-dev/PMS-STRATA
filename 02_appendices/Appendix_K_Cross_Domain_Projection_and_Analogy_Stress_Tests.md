# Appendix K — Cross-Domain Projection and Analogy Stress Tests

**Status:** substantive bounded provisional completion  
**Authority:** appendix-level stress-test and navigation layer only  
**Primary owners:** Chapters 29, 37–40; Minified Kernel; Operation Registry; Boundary Decision Tree  
**Case anchors:** `C40-X6`, `C38-X3`, `C38-N1`, `C40-N3`, `C40-N7`, `C40-P1`, `C40-P7F`, `C40-P7G`

## K.1 Purpose and boundary

This appendix tests cross-domain and cross-context mappings without turning resemblance, translation, execution, label transfer, or visual similarity into functional projection. It does not define a new operation. Every admissible functional transfer remains a `PROJECT_AS` occurrence governed by the canonical operation signature.

```text
cross-domain comparison
≠ PROJECT_AS automatically

structural analogy
≠ functional continuity

translation success
≠ semantic preservation

formal correspondence
≠ praxeological equivalence
```

The appendix is intentionally adversarial. A mapping may be useful and still terminate as `analogy_only`. It may be rhetorically familiar and still fail as label substitution. It may preserve some structural relations while leaving target function, source dependence, or contextual boundedness unestablished.

## K.2 The three-way classification

### K.2.1 Valid functional projection

A cross-domain `PROJECT_AS` claim requires all of the following:

1. an independently typed source object;
2. a declared target context;
3. a bounded target function rather than a renamed source label;
4. constitutive source trace linking source features to the target function;
5. source-reference and origin-type preservation;
6. counterfactual sensitivity to relevant source variation;
7. disclosed residuals, exclusions, uncertainty, and irrecoverable loss;
8. a no-projection or rival-projection alternative;
9. claim and authority ceilings.

Compactly:

```text
X : T_o
PROJECT_AS
F_t @ C_t
```

means only:

```text
X functions as F_t in C_t under bounded warrant
```

It never means:

```text
X becomes F_t as origin type
```

### K.2.2 Structural analogy

An analogy records a structured resemblance without asserting source-dependent target function. It may compare ordering, branching, recurrence, transition form, residual load, or failure shape. It is legitimate when it improves comparison while semantic preservation or functional dependence remains unestablished.

```text
useful resemblance
+ explicit residuals
+ no unsupported function claim
→ analogy_only may be correct
```

Analogy is not a defective projection by default. It is a different claim family with a lower reach.

### K.2.3 Label substitution

Label substitution occurs when a familiar PMS or STRATA term is applied in the target domain without a typed function, constitutive source trace, source-variation effect, or new discrimination.

Typical markers:

- the target description changes but target praxis does not;
- the label survives relevant source removal;
- no actor, access, cost, timing, corridor, repair, or selection relation changes;
- the mapping is defended by lexical familiarity;
- the source type is silently replaced by the target label.

Where the declared claim is `PROJECT_AS`, label substitution ordinarily supports `failed_transformation`, not `analogy_only`, because even a bounded similarity claim may be absent.

## K.3 Cross-domain stress protocol

A stress test should declare a source domain `D_s`, a target domain `D_t`, a comparison purpose, and the exact mapping claim. Domain names alone are insufficient.

### Test K1 — Source independence

Can the source object be identified and typed before the cross-domain mapping?

```text
source object created only by target vocabulary
→ projection claim circular
```

### Test K2 — Mapping unit

What exactly is mapped?

- object;
- relation;
- sequence;
- transition;
- Path;
- Trajectory;
- Composite;
- bounded function.

A whole-domain mapping such as “domain A is Ω” is presumptively overbroad unless decomposed into explicit claim components.

### Test K3 — Target function

What changes in the target context if the mapping is retained?

Valid answers identify bounded changes in reconstruction, discrimination, access, timing, cost, action corridor, repair, selection, or coordination. “It offers a useful perspective” is not yet a target function.

### Test K4 — Constitutive source trace

For each source feature, record:

```text
source feature
→ mapped target relation
→ target function contribution
→ source-variation expectation
→ residual / limitation
```

A table of correspondences without functional dependence remains analogy evidence.

### Test K5 — Semantic preservation

Ask which source meanings survive, which change, and which have no target equivalent. Semantic preservation need not be total, but the retained function must not depend on silently discarded differences.

### Test K6 — Counterfactual source variation

Remove, weaken, reorder, or substitute a load-bearing source feature. If the alleged target function remains unchanged, the mapping is weakly source-sensitive or source-insensitive.

```text
same label after load-bearing source removal
→ presumptive label substitution
```

### Test K7 — No-projection comparison

Compare the target analysis with and without `PROJECT_AS`. If the same claim, discrimination, and practical consequences remain, the projection lacks PraxisPurchase.

### Test K8 — Rival mapping

Test at least one alternative:

- a narrower projection;
- another target function;
- analogy only;
- recontextualization only;
- no transformation;
- an external domain-specific method.

### Test K9 — Residual ledger

Record features without counterparts in both directions:

```text
source-only residuals
 target-only residuals
mapping-induced compression
uncertain equivalences
irrecoverable distinctions
```

Residuals are not noise to be erased. They frequently decide whether the route remains projection, collapses to analogy, or fails.

### Test K10 — Authority firewall

No cross-domain mapping grants authority to rank domains, diagnose persons, validate institutions, prove model superiority, prescribe sanctions, or inherit authority from PMS Base.

## K.4 Stress matrices

### K.4.1 Projection / analogy / substitution matrix

| Test dimension | Valid projection | Structural analogy | Label substitution |
|---|---|---|---|
| source object independently typed | required | usually required | often missing |
| target context | explicit | comparison context may suffice | vague or absent |
| bounded target function | required | not asserted | absent |
| constitutive source trace | required | correspondence may suffice | absent |
| counterfactual source sensitivity | required | optional for similarity claim | typically absent |
| origin type preserved | required | identity not claimed | often violated |
| residuals disclosed | required | required for disciplined analogy | usually ignored |
| legitimate terminal class | bounded admissible class | `analogy_only` | often `failed_transformation` |

### K.4.2 Translation success matrix

A translation can succeed at one dimension and fail at another:

| Dimension | Possible result |
|---|---|
| syntax | expressions correspond |
| execution | procedures run |
| structure | phases or relations resemble each other |
| semantics | meanings are partly preserved |
| function | source-dependent target function is established |
| authority | never inherited automatically |

```text
syntax success
≠ execution success
≠ semantic preservation
≠ functional projection
≠ model superiority
```

## K.5 Canonical case routes

### K.5.1 `C40-X6` — Projection versus structural analogy

The source Trajectory and a technical workflow trace preserve a bounded phase/transition resemblance. The stronger debugging-function claim lacks semantic preservation and constitutive source-function dependence. The correct terminal result is `analogy_only`.

### K.5.2 `C38-X3` — PROJECT_AS versus recontextualization

The same source packet is renamed inside a new interpretive frame while access, costs, action corridors, timing, and counterfactual outcomes remain unchanged. The declared projection fails.

### K.5.3 `C38-N1` — Origin-type replacement

An operator-occurrence profile and bounded function are misread as a new operator type. The error is not repaired by the usefulness of the profile.

### K.5.4 `C40-N3` — Label substitution

A Trajectory receives a registry-style label, but source variation does not alter the alleged target function. The rhetorical mapping is inert.

### K.5.5 `C40-N7` — Person-level type jump

A configuration-level function is transferred to a person as intrinsic type, diagnosis, motive, rank, or sanction basis. This violates Type Integrity and the person boundary.

### K.5.6 Positive contrasts

`C40-P1`, `C40-P7F`, and `C40-P7G` show that valid projections require source-sensitive, context-bounded functions. Competing projections may both be viable when each has a separate claim and record.

## K.6 Cross-domain claim splitting

A broad claim may contain separable components:

```text
whole claim:
  structural correspondence
  semantic preservation
  target function
  model superiority
  recommendation
```

Possible adjudication:

```text
structural correspondence → retained as analogy
semantic preservation     → underdetermined
bounded target function   → failed or separately tested
model superiority         → excluded
recommendation            → outside authority
```

Claim splitting must not be used to retroactively convert a failed whole claim into success. Each successor claim is new and separately testable.

## K.7 Cross-domain Non-Capture

Cross-domain mapping may end in `non_capture` only where:

- the capture claim is delimited;
- multiple adequate bounded mapping attempts have been made;
- each retains different load-bearing relations;
- no adequate whole-claim mapping remains;
- forced integration would distort either domain;
- partial capture, residuals, rivals, and re-entry are preserved.

```text
hard translation
≠ non_capture automatically

missing vocabulary
≠ non_capture automatically
```

An external method may be superior. STRATA must preserve that possibility rather than converting every remainder into a new projection or operator.

## K.8 Reader and graph boundary

A later Reader may display source and target nodes, correspondence edges, residuals, source-variation tests, analogy-only routes, and failed label transfers. It may not infer semantic preservation or target function from geometric alignment.

```text
parallel graph geometry
≠ functional equivalence

edge visibility
≠ evidential warrant

cross-domain layer
≠ higher authority
```

## K.9 Completion boundary

Appendix K is complete when it supports disciplined routing among projection, analogy, recontextualization, substitution, type jump, claim reduction, Stop, Failure, and Non-Capture without adding a fourth operation or an automatic domain-comparison engine.
