## H.1 Purpose and Boundary

Appendix H catalogues recurring valid, bounded, reduced, stopped, failed, analogy-only, provisional, partial, neutral, and non-capture patterns.

Patterns are diagnostic aids. They do not replace source-specific audit.

```text
pattern match
≠ automatic Output Class
≠ universal inference
≠ class ranking
≠ new theory
```

A pattern is usable only where the current claim shares the relevant type, source, operation, continuity, Loss, and context structure. Surface similarity is insufficient.

The catalogue is organized by structural pattern rather than chapter number. Cases illustrate patterns; cases do not originate the rule.

---

## H.2 Reading Convention

Each pattern contains:

```text
Form
Why it may carry or fail
Required evidence
Common confusion
Likely candidate routes
Case anchor
```

“Likely candidate routes” are candidate-generation aids. Final routing remains with the full ten-class collision audit in the Boundary Decision Tree.

The catalogue does not treat classes as better or worse. A mandatory stop or genuine non-capture may be the most responsible result for a given claim.

## H.3 Cross-Cutting Validity Pattern

### H.V0 — Declared, Traceable, Typed, Bounded Transformation

**Form**

```text
one delimited claim
+ one registered operation occurrence
+ source-supported transformation
+ declared Loss
+ bounded validity
+ preserved type/reference duties
+ alternatives
+ authority ceiling
```

**Why it may carry**

The operation makes a warranted difference while remaining reconstructibly dependent on its sources.

**Required evidence**

- exact operation identity;
- source and target declarations;
- constitutive Source Trace;
- operation-specific result;
- twelve-stage audit;
- all five Loss fields;
- ten-class candidate set and final selection.

**Common confusion**

Schema validity alone does not instantiate this pattern.

**Candidate routes**

`admissible`, `admissible_with_bounded_claim`, `admissible_but_provisional`, or another class depending on the decisive limitation.

## H.4 Valid COMPOSE Patterns

### H.CV1 — Warranted Sequential Composition

**Form**

```text
source occurrences
+ source-supported ordering
+ warranted transitions
+ declared selection and Loss
→ bounded Path composite
```

**Required evidence**

- sequence is more than chronology;
- transition relations are warranted;
- omitted alternatives and non-events are disclosed;
- removing a load-bearing transition changes the composite.

**Case anchor**

[`C17-LINEAR-01`](../03_cases/markdown/C17-LINEAR-01_Simple_Linear_Path.md).

### H.CV2 — Branch-Preserving Composition

**Form**

```text
one realized continuation
+ source-supported alternative statuses
→ branching Path without retrospective free story
```

Rejected, blocked, aborted, deferred, and unavailable branches remain distinct.

**Case anchor**

[`C17-BRANCH-01`](../03_cases/markdown/C17-BRANCH-01_Branching_Path.md).

### H.CV3 — Trajectory with Bounded Historical Load

**Form**

```text
warranted Path
+ sustained historical load
+ later structural effect
→ bounded Trajectory claim
```

The pattern does not automatically establish Path Dependence or attractor-function.

**Case anchors**

[`C17-HISTORY-01`](../03_cases/markdown/C17-HISTORY-01_Similar_End_States_Different_Histories.md) and [`C17-WEAKPD-01`](../03_cases/markdown/C17-WEAKPD-01_Repeated_Pattern_with_Weak_Path_Dependence.md).

### H.CV4 — Composite with Explicit Constitutive Relations

**Form**

```text
multiple source structures
+ selection rule
+ formation rule
+ constitutive relation topology
→ new composite analytical object
```

The result is not a mere list and not an automatic target function.

**Case anchor**

[`C47-CP1A`](../03_cases/markdown/C47-CP1A_COMPOSE_Distributed_Access_Composite.md).

## H.5 Invalid COMPOSE Patterns

### H.CI1 — Chronology Presented as Path

**Form**

```text
timestamp order
without warranted transition set
→ Path claim
```

**Why invalid**

Chronology alone does not establish constitutive transitions or selective continuation.

**Likely route**

`claim_reduction_required` where chronology remains supportable but the Path claim does not.

**Case anchor**

[`C17-CHRON-01`](../03_cases/markdown/C17-CHRON-01_Chronology_Presented_as_Path.md).

### H.CI2 — Teleological Composition

**Form**

```text
later outcome
used to retroactively define all prior steps as directed toward it
```

**Why invalid**

The composition imports purpose and inevitability not warranted at the historical cuts.

**Case anchor**

[`C17-TEL-01`](../03_cases/markdown/C17-TEL-01_Teleological_Composition.md).

### H.CI3 — Macro-Label without Traceable Path

**Form**

```text
broad label
+ weak or absent constitutive source trace
→ macro composite claim
```

**Why invalid**

The target label remains unchanged under relevant source variation and exceeds the Traceability Ceiling.

**Case anchor**

[`C17-MACRO-01`](../03_cases/markdown/C17-MACRO-01_Macro_Label_without_Traceable_Path.md).

### H.CI4 — Omitted Asymmetry Composition

**Form**

```text
selected events
- constitutive cost/asymmetry relation
→ sanitized composite
```

**Why invalid**

The omitted relation is load-bearing; selection and Loss are not adequately disclosed.

**Case anchor**

[`C17-OMEGA-01`](../03_cases/markdown/C17-OMEGA-01_Composition_through_Omitted_Asymmetry.md).

### H.CI5 — Automatic Higher-Level Function

**Form**

```text
COMPOSE(X_1, …, X_n)
→ composite
→ function inferred without separate PROJECT_AS occurrence
```

**Why invalid**

Composite formation and contextual functional projection are distinct claims and operations.

## H.6 Valid DECOMPOSE Patterns

### H.DV1 — Same-Reference Finer Reconstruction

**Form**

```text
compressed occurrence or composite
+ bounded decomposition question
+ source-supported components and relations
→ finer reconstruction of same reference object
```

**Required evidence**

- source reference preserved;
- target granularity declared;
- component relations and internal temporality supported;
- source-function effect stated;
- unresolved structure retained.

**Case anchor**

[`C28-TRAJECTORY-01`](../03_cases/markdown/C28-TRAJECTORY-01_Admissible_Trajectory_Decomposition.md).

### H.DV2 — Resolution Gain

**Form**

```text
finer reconstruction
→ changed warranted relation, role, cost, path, or claim
```

**Case anchor**

[`C28-GAIN-01`](../03_cases/markdown/C28-GAIN-01_Resolution_Gain.md).

### H.DV3 — Resolution Neutrality

**Form**

```text
source-supported finer comparison
+ no changed warranted reconstruction
→ resolution_neutral
```

Neutrality is a valid finding, not a failed analysis.

**Case anchor**

[`C17-RES-01`](../03_cases/markdown/C17-RES-01_Path_or_Resolution_Drift.md).

### H.DV4 — Bounded Reopening after COMPOSE or PROJECT_AS

**Form**

```text
prior result object
→ new DECOMPOSE occurrence
→ finer source-side reconstruction
```

The new occurrence is not an inverse. Earlier Loss remains.

**Case anchors**

[`C54-CD1B`](../03_cases/markdown/C54-CD1B_DECOMPOSE_Reopen_P54.md) and [`C54-PD1B`](../03_cases/markdown/C54-PD1B_DECOMPOSE_Q0_Q5_Origin_Trajectory.md).

## H.7 Invalid DECOMPOSE Patterns

### H.DI1 — Operator-Type Decomposition

**Form**

```text
PMS operator type
→ internal components by DECOMPOSE
```

**Why invalid**

DECOMPOSE opens occurrences and composites, never Δ–Ψ operator types.

**Case anchor**

[`C28-OPTYPE-01`](../03_cases/markdown/C28-OPTYPE-01_Operator_Decomposition_Error.md).

### H.DI2 — Fragmentation without Source Function

**Form**

```text
compressed object
→ component list
without relational reconstruction or source-function return
```

**Why invalid**

More pieces do not constitute a finer reconstruction.

**Case anchor**

[`C28-FRAGMENT-01`](../03_cases/markdown/C28-FRAGMENT-01_Fragmentation_without_Source_Function.md).

### H.DI3 — Unsupported Internal Structure

**Form**

```text
plausible microstructure
without sufficient source support
→ asserted as actual reconstruction
```

**Likely route**

Claim reduction where a more limited statement remains available.

**Case anchor**

[`C28-UNSUPPORTED-01`](../03_cases/markdown/C28-UNSUPPORTED-01_Unsupported_Internal_Structure.md).

### H.DI4 — Overfine Analysis

**Form**

```text
further detail
+ no changed reconstruction
+ continued recursion
```

**Likely route**

`mandatory_stop` where continuation would fall below the Relevance Floor.

**Case anchor**

[`C28-OVERFINE-01`](../03_cases/markdown/C28-OVERFINE-01_Overfine_Analysis_below_the_Relevance_Floor.md).

### H.DI5 — Resolution Escape

**Form**

```text
objection at current granularity
→ move to another granularity
→ answer different claim
```

**Why invalid**

Changing granularity does not erase the earlier claim or failure.

**Case anchor**

[`C28-ESCAPE-01`](../03_cases/markdown/C28-ESCAPE-01_Resolution_Escape.md).

### H.DI6 — Hidden PROJECT_AS

**Form**

```text
DECOMPOSE source
→ finer structure
→ new contextual function asserted in same occurrence
```

**Why invalid**

The functional claim requires a separate PROJECT_AS record.

## H.10 Valid Claim-Bounding Patterns

### H.BV1 — Admissible with Bounded Claim

**Form**

```text
material reach restriction identified
+ narrower claim already formulated and tested
+ retained scope and excluded reach explicit
```

The bounded claim is not merely the original claim with a disclaimer appended.

### H.BV2 — Admissible but Provisional

**Form**

```text
one coherent usable claim remains
+ material calibration, support, temporal, or rival limit unresolved
```

**Case anchors**

[`C40-P7F`](../03_cases/markdown/C40-P7F_Frame_Function_Candidate.md), [`C40-P7G`](../03_cases/markdown/C40-P7G_Attractor_Function_Candidate.md), and [`C49-CAL1`](../03_cases/markdown/C49-CAL1_PROJECT_AS_Calibration_Open_Threshold_Function.md).

### H.BV3 — Partially Admissible after Claim Split

**Form**

```text
whole claim split into subclaims
+ at least one retained subclaim passes
+ another subclaim fails, stops, or remains unresolved
```

**Case anchors**

[`C28-SUBRETYPE-01`](../03_cases/markdown/C28-SUBRETYPE-01_SUB_or_RETYPE.md) and [`C28-SUBPATH-01`](../03_cases/markdown/C28-SUBPATH-01_SUB_or_New_PATH.md).

### H.BV4 — Claim Reduction Required

**Form**

```text
original claim does not pass
+ plausible narrower claim remains
+ narrower claim not yet independently tested
```

The route does not pre-authorize the reduced claim.

**Case anchors**

[`C17-CHRON-01`](../03_cases/markdown/C17-CHRON-01_Chronology_Presented_as_Path.md) and [`C53-CPD1C`](../03_cases/markdown/C53-CPD1C_DECOMPOSE_Q47_Complete_Return_Claim.md).

```text
further distinction available
```

### H.SV2 — Resolution-Escape Stop

```text
new granularity would answer a different claim

```

Case: [`C50-FP1X`](../03_cases/markdown/C50-FP1X_DECOMPOSE_Granularity_Escape_Stop.md).

### H.SV3 — Optional Stop after Sufficiency


## H.12 Invalid Stop Patterns

### H.SI1 — Stop as Avoidance

```text
unanswered objection
→ stop declared merely to avoid testing
```

This is not a valid Stop. The record must identify a canonical stop condition and preserve the unresolved claim.

### H.SI2 — Stop as Failure Erasure

```text
operation fails
→ analyst declares stop
→ failure removed from history
```

A stop may follow a failure, but it does not replace or repair the failure result.

### H.SI3 — Optional Stop as Mandatory Prohibition

Optional Stop records sufficiency, not an inadmissibility of continuation. Conflating the two distorts the route.

## H.13 Genuine Non-Capture Pattern

### H.NV1 — Adequate Bounded Attempts with Persistent Capture Limit

**Form**

```text
clearly delimited capture claim
+ multiple adequate bounded attempts
+ each preserves partial capture and remainder
+ no adequate retained whole-claim form
+ forced integration would distort
→ non_capture
```

**Case anchor**

[`C52-NC1`](../03_cases/markdown/C52-NC1_Competing_Decompositions_of_a_Compressed_Handoff_Occurrence.md).

### H.NI1 — Missing Information Presented as Non-Capture

```text
sources incomplete
+ no adequate attempts
→ non_capture asserted
```

Invalid. The correct state may be provisional, underdetermined, claim reduction, formal incompleteness, or stop.

### H.NI2 — One Failed Transformation Presented as Non-Capture

```text
one projection or decomposition fails
→ object declared uncapturable
```

Invalid. Operation failure and capture limitation are distinct.

### H.NI3 — Non-Capture as Weak-Claim Shield

```text
claim poorly specified or unsupported
→ non_capture invoked to avoid withdrawal
```

Invalid. Non-Capture must not immunize a weak claim.

## H.15 Continuity Patterns

### H.CNV1 — Same Reference, Changed Resolution

Valid for DECOMPOSE where the same object is reconstructed under finer granularity and source-function effects are explicit.

### H.CNV2 — New Composite, Preserved Provenance

Valid for COMPOSE where the target is a new object but source references, selection, formation, and Loss remain explicit.

### H.CNV3 — Same Origin Type, Added Contextual Function

Valid for PROJECT_AS where the target function is bounded and source-dependent.

### H.CNI1 — Same Label, Changed Reference

Invalid where nominal continuity substitutes for constitutive continuity.

### H.CNI2 — Same Present State, Erased History

Invalid where two equal present cuts are treated as equivalent despite different path loads relevant to the claim.

### H.CNI3 — Chain Loss Reset

Invalid where a later operation starts with an empty Loss profile and silently discards inherited uncertainty or exclusion.

## H.16 Anti-Ontology Patterns

### H.OV1 — Relational Analytical Level

Valid:

```text
X is higher relative to Y under declared relation R and context C
```

### H.OI1 — Analytical Level as Reality Layer

Invalid:

```text
higher analytical level
→ ontologically higher entity
```

### H.OI2 — Finest Resolution as Final Constituent

Invalid. DECOMPOSE does not discover ultimate ontological atoms.

### H.OI3 — Largest Composite as Ultimate Whole

Invalid. COMPOSE does not produce an ontologically final totality.

### H.OI4 — Target Function as Ontological Promotion

Invalid. PROJECT_AS does not promote an object into a new origin type or reality layer.

## H.17 Failure-Preservation Patterns

### H.FV1 — Successor Claim after Failure

```text
Q_0 fails
→ Q_1 declared with new source/context/scope
→ new record
→ Q_1 may pass
```

The history retains both outcomes.

### H.FI1 — Moving the Answer

```text
Q_0 challenged
→ frame/granularity/function changed
→ Q_1 answer presented as if it answered Q_0
```

Invalid. New transformation means new claim.

### H.FI2 — Projection Rescue

```text
source claim fails
→ source projected into another function
→ original claim declared rescued
```

Invalid unless the original claim itself is separately retested. The new projection is an independent claim.

### H.FI3 — Granularity Rescue

```text
coarse claim fails
→ finer claim passes
→ coarse failure erased
```

Invalid. The finer claim may be useful, but it does not rewrite the predecessor.

## H.18 Chain Patterns

### H.CHV1 — Separated Occurrence Chain

```text
T_1
→ explicit Handoff H_1,2
→ T_2
```

Each occurrence keeps:

- its own operation identity;
- tested claim;
- Loss;
- result;
- Output Class;
- Stop/Failure/Non-Capture state.

### H.CHI1 — Compound Operation

```text
COMPOSE_PROJECT_AS
```

Invalid. No fourth or compound operation is recognized.

### H.CHI2 — Inverse Assumption

```text
DECOMPOSE(COMPOSE(X)) = X
COMPOSE(DECOMPOSE(X)) = X
```

Invalid. Return operations are new occurrences and inherit prior Loss.

### H.CHI3 — Chain Result Averaging

Invalid:

```text
one failure + two passes
→ average admissible chain
```

Local results remain separate. An integrated chain result may summarize only after preserving all local findings.

## H.19 Output-Class Confusion Patterns

Appendix H identifies recurring confusions but leaves full boundary adjudication to Appendix I.

| Confused forms | Correct distinction |
|---|---|
| ordinary boundedness vs `admissible_with_bounded_claim` | bounded-claim class requires a material decisive reach restriction and an already tested narrower claim |
| provisional vs non-capture | provisional retains one coherent usable claim; non-capture leaves no adequate retained form of the same capture claim |
| partial vs provisional | partial concerns split subclaims; provisional concerns one coherent claim under unresolved conditions |
| claim reduction vs bounded claim | reduction means the narrower claim is not yet independently passed |
| mandatory stop vs failure | stop prohibits continuation; failure rejects the declared operation claim |
| failure vs non-capture | failure is operation-specific; non-capture follows adequate bounded attempts and persistent capture limits |
| analogy-only vs failed projection | analogy-only requires an independently delimited affirmative analogy claim |
| resolution neutral vs claim reduction | neutrality preserves the reconstruction after a real resolution test; reduction changes claim reach |

No row creates a default precedence.

## H.20 Pattern-to-Record Requirements

A pattern catalogue entry may be used only if the record still supplies:

- current source evidence;
- operation-specific payload;
- current claim scope;
- five-field Loss;
- alternatives;
- current audit findings;
- current collision adjudication;
- current authority ceiling.

Do not cite a prior case as substitute for current evidence.

```text
same pattern family
≠ same adjudication
```

## H.21 Reusable Countercase Template

The file [`countercase_template.md`](../03_cases/templates/countercase_template.md) is now a reusable companion template for one invalid or blocked transformation occurrence.

It requires:

- the apparently plausible claim;
- the exact structural defect;
- the preserved source material;
- operation classification;
- decisive audit findings;
- Loss;
- alternatives and salvageable narrower claims;
- correct class-boundary contrasts;
- authority boundary;
- YAML-record link.

A countercase is not merely a negative example. It must show why the route fails or stops and what remains preserved.

## H.22 Completion Checklist

A pattern analysis is ready only where:

- the pattern is matched by structural features, not labels;
- operation identity is correct;
- source and claim are delimited;
- valid and invalid alternatives are both considered where relevant;
- TypeIntegrity and traceability are not inferred from surface similarity;
- a likely candidate route is not treated as final selection;
- prior failure, stop, reduction, or non-capture is preserved;
- no case ranking or universal inference is introduced;
- no pattern creates a new operation, Output Class, Loss field, PMS primitive, or authority;
- the current record remains the adjudication owner for the current occurrence.

The bounded Appendix-H result is:

```text
admissible_with_bounded_claim
```
